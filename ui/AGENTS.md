# ui

React 19 + TypeScript app for the web and the desktop front end. It talks to the core only through the protocol (`docs/spec/protocol.md`), with types generated into `src/generated/`.

Spec: `docs/spec/ui.md`. Guidelines: `docs/guidelines/` (TypeScript, Tailwind CSS, frontend design, and the Partsmith design direction).

Lost references and fixes (ui.md 3.7, 3.9, 3.22, 4.1, 4.2): `src/app/actions/fixes.ts` runs every message and cause action (`runFixAction` with the place that offers it, `FixPlace`, and `runOfferedFix` for a button or marker, which first checks `selectFixBlock`: `apply` through `apply_fix`, joining the command's transaction only from its banner, `pick`, `show`, `undo`), `copyDetails`, `showLost`, and `focusRepair` and `blurRepair` for the repair mode a focused Problems row shows; `src/app/actions/edits.ts` runs user changes (`runChange`, `commitReportedEdits`) and `src/app/actions/loss-notifications.ts` reports what they broke (`reportChange` over `changeNotifications`); `src/app/actions/element-lists.ts` lists a body's elements once per model mesh (`listedElements`, and `listedElementsOrNone` where a missing or failed list means none); `src/problems/problems.ts` groups problems by root (`problemRows`, `groupedRows`), gives the severity a row shows (`rowSeverity`, `problemSeverity`) and computes the change notices (`changeNotifications`, `lossKeys`); `src/repair/` holds repair mode (`repairView`, `candidateAction`, `ghostBuffer`, `ghostSegments`, `selectRepairMode`, `repairTitle`, `regionCandidatePlaces` and `selectRegionCandidates` for the candidate regions the scene fills and numbers, the overlay and its frame painter, and in `frame.ts` what it frames, `frameRepair`, and where its candidate markers go, `elementCentroids` and `candidatePoints`) and the fix buttons, cause lines, message actions and `ShowLostButton` every panel shows; the fix and notification buttons wrap `src/layout/WaitingButton.tsx`, the button of an action that waits during a feature command (3.7). `ViewportHandle.itemBounds` gives the world box of selection items as drawn, for what a `show` action frames. Re-attaching a sketch whose face is lost (3.16.1) lives in `src/app/actions/sketch.ts`, where `reattachSketch` opens plane picking for the sketch (`SketchSession.reattaching`) and `enterAttachedSketch` edits it once a fix attached it, and in `src/app/actions/sketch-plane.ts`, where `pickPlane` places a new sketch or attaches the re-attached one on a picked plane (refusing with `attach_after` what a feature after the sketch made) and `sketchPlaneOf` gives the plane a picked item stores; `showLost` and a `pick` action at a sketch's plane run it, the sketch header lists the candidates, and `selectReattachingSketch`, `selectPointsIntoSketchPlane` and `selectSketchFaceLost` in `src/state/selectors.ts` tell what is re-attached and lost, reading the recipe through `selectSketchRecord`, over `sketchRecord` in `src/core/recipe.ts` (which also has `comesAfter`, for `attach_after`). Frames on the model (3.7, 3.16.1, 2.12): a face sketch stores its descriptor's `fallback` with `fallback_frame: body` (`sketchPlaneOf`), and a re-attached sketch without motion the face's world `placement` without the frame (`sketchPlaneOf` with frame `world`), which keeps it without motion; sketch commits send the plane as stored, a hole's helper sketch keeps the face's world `placement` for drawing its points, and an axis picked on an edge or round face stores the descriptor's `axis_direction` as `direction`.

What features use (ui.md 3.9, 3.16.10): `refreshUses` in `src/app/actions/timeline.ts` keeps `DocumentState.uses` at the document's revision through `CoreApi.listUses` (a background request outside the mutation queue, one `LatestOnly` per app), and `src/timeline/uses.ts` derives from it `dropWarning`, `usersOf`, `usesAreCurrent`, `usedEntities` and `entityUse`, and names users with `usedByText`. The timeline drag (`src/timeline/use-strip-drag.ts`, with the drop rule `dropIndex` in `strip.ts`) checks each pointer move with `dropWarning` (`ps:drop-check`), turns the insertion bar `warningMark` and shows the `drop-hint` chip (`src/timeline/DropHint.tsx`); an item's menu (`src/timeline/FeatureMenu.tsx`) lists "Used by" once the uses are current and selects the users. In sketch mode, `enterSketch` and `recordSketchEdit` refresh the uses; `SketchOverlay` draws the `entity-used` marks after the constraint glyphs on each entity's anchor (`entityAnchor` in `src/sketch/annotations.ts`, `annotationCenters` in `src/sketch/screen.ts`); and `deleteSketchItems` sets `SketchSession.notice` to `entity_used`, which the sketch controller shows in place of the step prompt until that prompt changes, for 8 s at most. Ghosts in sketch coordinates lie on their sketch's latest solved placement: `ghostBuffer` gives a region repair's old outline there (3.7). A cause line's `show` (4.2) keeps its ghost's points (`keepCauseGhost` in `src/repair/repair.ts`), which `causeGhost` gives in world coordinates on the shown sketch's placement, `src/repair/CauseGhost.tsx` and `paintCauseGhost` draw as the `cause-ghost` path, and the show frames with what it selected.

Newcomer errors (ui.md 2.10, 2.14, 3.7, 3.16.7, 3.16.8, 3.21): the units control and the palette's `document.units.*` commands run `setUnits` in `src/app/actions/document.ts`, which sends `set_document_units` (`CoreApi.setDocumentUnits`) with `keep_sizes` while the session's `AppState.keepSizes` (`setKeepSizes`) is on and `DocumentState.bareNumbers` (from `document_changed`) is above 0, and the units menu offers that option as its `keep-sizes` checkbox, a `MenuEntry` with `keepsOpen` and a `testId`; what reads the app state's document units, millimeters without a document, reads them through `selectDocumentUnits` in `src/state/selectors.ts` (the units button, which shows no unit without a document, reads them itself). Under a fillet, chamfer or shell field, `fieldLimit` in `src/inspector/status.ts` gives the largest value that works from the field's "too large" message, which `ExpressionInput` shows as `field-limit` with the `warningMark` border (its `limit` prop). Extrude and Revolve name the sketch whose outline is open (`FEATURE_REQUIREMENTS` in `src/commands/features.ts` returns each type's `DisabledAvailability`, here with an `action`, which `explainDisabled` puts on the notification), and its "Show '{sketch}'" runs `showOpenEnds` in `src/app/actions/sketch.ts`, which frames the open ends as the sketch problems popover's Show does (`showSketchFinding`, over `framedPoints` in `src/sketch/issues.ts`). Sketch messages are the core's: the popover shows each finding's `findingMessage` with its fixes, a failed commit carries the probe's first error, an over-constrained one its `message`, and an edited dimension the sketch cannot take shows `refusedDimensionMessage` (the dimension editor's `cannot_take` problem), with Add reference and Cancel in `src/sketch/ReferenceOffer.tsx`, which the selection inspector's size field also shows for a new dimension that would over-constrain.

Files and document assets (ui.md 2.15, 3.19, 4.4, ADR 0037): `src/files/assets.ts` holds `AssetFile`, `ASSET_NAME` and `referencedAssetNames` (the one place the UI reads `.ptsm` text: string values that are asset names, nothing else), and `src/files/digest.ts` `fileDigest` (SHA-256 through Web Crypto). `FileService` reaches the `assets/` folder next to a document (`reachesFolder`, `readAssets`, `writeAssets`, `chooseFolder`): the web through the folder the user chose (`folderHolds`, its permission asked before the file's in `readHandle`), the desktop through the host's `read_asset` and `write_asset`. `src/app/actions/document.ts` opens a file with the assets its text names (`openText` opens it again without them after `asset_mismatch`) and writes in the order of file-format.md 3.11 (`writeDocument`: `saveDocument`, Save's change check `unchangedElsewhere` with `save_conflict`, `wroteAssets` with `save_folder_needed`, the document, the written digest in the file reference, then `markSaved`), one write at a time (`writeInTurn` over `createOneAtATime` of `src/core/queue.ts`, which feature command starts also use), each built when its turn comes, so Save takes the file and digest the write before it left; `src/app/actions/document-assets.ts` says why imports are missing (`explainMissingAssets`), runs "Choose folder" (`chooseFolderOf`, then `reopenWithAssets`, one mutation-queue task that takes the settled recipe when its turn comes, as a core restart reopens it; `runChange` follows the document session, so an edit made meanwhile goes to the reopened document) and keeps the actions offered for one document to it (`offerOf`, `isOffered`). `DocumentState.assets` holds what the core accepted, which `restartCore` gives the new core again.

Print suggestions (ui.md 3.17, print.md 3.12, ADR 0040): `src/print/suggestion.ts` words a finding's suggestion in millimeters (`suggestionText`, the words the CLI and Python print, kept in step by the shared cases of U-233) and outlines each split plane in the finding's box (`splitPlaneOutline`, and `focusedSplitOutlines` for the focused finding), which the scene draws in the overlay pass and the viewport counts in `data-split-planes`; `HealthRow.suggestion` carries the words to the row's `health-suggestion` line, `findingPoint` in `src/print/health.ts` marks a drain hole at its point, `focusFinding` frames a split finding's box, and `installPrintAnalysis` drops the focused finding when the panel closes, the document, the print orientation or the report changes, or its check is hidden. `findingAt` lives in `src/print/checks.ts`, so both modules read it without importing each other.

Drawing tools (ui.md 3.16.4, 3.16.5): `src/sketch/recipes.ts` and the commits of `src/sketch/drawing.ts` (`drawClick`) decide what each tool adds: ids in order, point order, the inferred snap, direction and tangent constraints, and typed dimensions. features/sketch.md tests 44 to 50 hold that output as `examples/sketch/tool-*.ptsm`, which no UI test reads, so a change to a tool's output updates those tests and examples in the same change.

Engine web budgets (engine.md section 5, ADR 0043): `e2e/engine-budgets.spec.ts` measures the engine's web column by hand (`@perf`, `PARTSMITH_PERF=1`) on `e2e/pages/engine.html`, whose module worker `e2e/pages/engine-worker.ts` compiles `public/core/partsmith_core.wasm` once and times `callCore` on new instances of it. `e2e/support/engine-budgets.ts` holds the driver (`openEngine`, `ok`), the warm-up before the rows (`warmUp`) and the rows of `crates/partsmith-engine/benches/budgets.rs` ported under the same names (`MEMORY_ROW`, `TIMED_ROWS`), so a change to a row of `budgets.rs` (its documents, edits, samples or checks) changes its row here in the same change; engine test 156 checks the names on every e2e run. `e2e/support/perf.ts` holds `expectWithinBudgets`, which `perf.spec.ts` shares.

## Commands

```sh
pnpm install
pnpm dev                 # Vite dev server
pnpm lint                # oxlint, then oxfmt --check
pnpm format              # oxfmt
pnpm typecheck
pnpm test                # Vitest
pnpm test:scripts        # node:test tests of scripts/ and of the workflow files
pnpm check:licenses      # the npm packages that ship against the allow list of deny.toml (docs/spec/delivery.md 2.10)
pnpm notices             # rewrite both third-party notices files after changing a lock file, a Cargo.toml, rust-toolchain.toml or ../scripts/*-version.sh (delivery.md 2.9)
pnpm check:notices       # both notices files against what the lock files give, as CI's schema job runs it
pnpm build && pnpm check:dist   # the build in dist/ against the Pages file limit, the headers, the notices and the initial JavaScript limit (delivery.md 2.6)
pnpm e2e                 # Playwright against the production build and the core in public/core (e2e/README.md); locally set PLAYWRIGHT_CHROMIUM_EXECUTABLE=/opt/pw-browsers/chromium
PARTSMITH_PERF=1 pnpm e2e engine-budgets.spec.ts   # the engine's web-column budgets (engine.md section 5), by hand, one performance file at a time
pnpm e2e --project firefox   # the tests tagged @engines in Firefox (or --project webkit), as the platforms workflow runs them; the two run only when --project names them (ui.md 6.8); Firefox runs headed, so without a display run it under xvfb-run --auto-servernum
```

## Rules

- `type`, never `interface`. Strict TypeScript, no `any`.
- Styling is Tailwind utility classes only. Conditional classes use `clsx/lite`. No inline `style` attributes, no `px` values, arbitrary values only when unavoidable.
- `src/index.css` holds only the Tailwind import, the two `@font-face` rules of the self-hosted fonts, the font theme variables and the `dark` custom variant (`docs/spec/ui.md` 2.16.1, ADR 0031). Do not add CSS or CSS variables there without human approval. Interface text and numbers inherit Geist from the root; use `tabular-nums` where digits line up and `font-mono` for code only (ui.md 2.16.7), never a font family or `font-feature-settings`.
- Light and dark themes come from the role-to-color mapping documented in `docs/spec/ui.md`; the `dark` class on the root element switches themes.
- Icons from `lucide-react`.
- Sketch mode's overlay is a chunk of its own (ui.md 3.1, delivery.md 2.6): only `src/sketch/overlay-chunk.ts` (`loadSketchOverlay`, `loadedSketchOverlay`) reaches `src/sketch/SketchOverlay.tsx`, through `import()`, and `App` renders it suspended until it has loaded. A static import of it, or of a module only it uses, from the main chunk puts that code back into the initial JavaScript, which `pnpm build && pnpm check:dist` limits. `src/layout/test-app.testing.tsx` loads the chunk before any test, so every shell a test renders shows sketch mode at once.
- Tests build on the shared fakes in `src/test/fakes` (core, app, state, selection items, viewport, deferred promises, a `ResizeObserver` stand-in, and the repair data of corpus R16 with its store changes and element lists, of a lost profile region and of a deleted sketch line in `repairs.ts`, and the small timelines with their `list_uses` answers of the drop warning, "Used by" and used mark tests, with `stateWithUses` for a store state whose uses are known, in `uses.ts`); the fake core applies the fixes its `fixes` option lists for `apply_fix`, puts its `ghosts` option first in every recompute frame, reports repair candidates in their bodies' current meshes, answers `list_uses` with its `uses` option (none by default), and answers `set_document_units` and reports `bare_numbers` counting every parameter expression and record string that is a number without a unit (it knows no counts or angles, so units tests use lengths, as `NC09_DOCUMENT` does); the fake `CoreApi` and the sketch harness of `src/sketch/view.testing.ts` answer `listUses` with no uses unless a test stubs it; for documents with imports (ui.md 3.19), the fake core keeps the assets `open_document` supplies (`mismatchedAssets` refuses some), fails an import without its asset with `asset_missing` and saves the assets the text names, the fake file service (`src/test/fakes/files.ts`) keeps each handle's text and the asset files of fake folders (`createFakeFolderHandle`) and desktop handles, answers `chooseFolder` from `folderChoices` and records every call (`callsOf`), and `src/test/fakes/web-folders.ts` holds File System Access handles for the web file service's folder tests; `src/test/type-roles.ts` tells tabular figures and code apart in jsdom, which applies no stylesheet (ui.md 2.16.7). `src/test/setup.ts` widens jsdom's window to 1280 CSS pixels (wide enough for docked panels, ui.md 3.2), gives elements the no-op `scrollIntoView` that jsdom lacks (tests spy on it) and unmounts Testing Library renders after each test, after the file's own `afterEach` hooks, so a file calls `cleanup()` itself only when its teardown must follow the unmount; `beforeEach(installPopoverPolyfill)` installs and removes the popover stand-in.
