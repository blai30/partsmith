# partsmith-desktop

Tauri 2 desktop host: one engine `Session` behind the `call` command, native open and save dialogs, read and write access to exactly the files the user chose, and the close guard. No modeling logic.

Spec: `docs/spec/desktop.md`. Decisions: ADR 0014 (Tauri, its dependencies, no fs plugin, no Tauri npm package). The UI half lives in `ui/src/files/desktop-file-service.ts`, `ui/src/files/choose-file-service.ts` and `ui/src/app/close-guard.ts`.

## Interface

- `Host` (`src/host.rs`): one engine `Session` behind a mutex; `call(frame)` answers every request frame with a response frame and never panics. `Host::default()` displays meshes, as the web worker does.
- `Files` (`src/files.rs`): access to exactly the files the user picked. `pick_open` and `pick_save` go through a `Dialogs` implementation and grant the chosen path (`pick_save` adds a missing extension of the `FileKind`); `read` and `write` accept only grants in the list; `write` replaces the file atomically, through a symbolic link to the file it points to, and refuses a read-only file. Up to `MAX_GRANTS` paths, most recently used first, saved as `file-grants.json` in the app data directory (`Files::load`) or kept in memory (`Files::in_memory`). `grant_of(path)` is 32 hex digits of BLAKE3. `FileError` serializes as `{reason, message}` for the UI.
- `TauriDialogs` (`src/dialogs.rs`): `Dialogs` over tauri-plugin-dialog, blocking, so only called on the blocking pool.
- `Unsaved` and the close confirmation (`src/close_guard.rs`): the UI reports unsaved changes with `set_unsaved`; closing the main window then asks first.
- Commands (`src/commands.rs`): `call`, `pick_open_file`, `pick_save_file`, `read_file`, `write_file` (grant in the `Partsmith-Grant` header, raw body) and `set_unsaved`, in `COMMAND_NAMES` order.
- `configure(builder)` adds the plugin, state and commands (shared by `run` and the command tests); `run()` adds `Files`, the close guard and the generated context.

## Commands

```sh
# These need OCCT_ROOT and, on Linux, the WebKitGTK development packages (delivery.md 3.2)
cargo test -p partsmith-desktop
cargo clippy -p partsmith-desktop --all-targets -- -D warnings
# The budgets of spec section 5 that Rust measures (Host::call overhead, Files::load)
cargo bench -p partsmith-desktop --bench budgets

cargo fmt -p partsmith-desktop

# The bundler, once
cargo install tauri-cli --version 2.12.2 --locked

# Run the app against the Vite dev server (run cargo tauri dev in desktop/src-tauri)
pnpm -C ui dev
cargo tauri dev

# Bundle it (run cargo tauri build in desktop/src-tauri)
pnpm -C ui build
cargo tauri build
```

## Rules

- The webview gets the least privilege that does the job: the six commands of `COMMAND_NAMES`, each granted in `capabilities/main.json`, and nothing else. No `core:`, `dialog:` or `fs:` permission, no `tauri-plugin-fs`.
- `src/command_names.rs` is the one list of command names; `build.rs` includes it for the app manifest.
- `permissions/autogenerated/` is written by tauri-build from `COMMAND_NAMES` on every build and is committed. tauri-build never deletes a file there, so delete a renamed command's file; `tests/config.rs` checks for exactly one file per command.
- Files are reachable only through a grant from a native dialog (`Files`); holding a grant string is not enough.
- `tauri.conf.json` and `capabilities/main.json` are exactly as desktop.md 2.8 and 2.9 give them; `tests/config.rs` checks both.
- `unsafe_code` stays forbidden; the Tauri macros expand to safe code.
