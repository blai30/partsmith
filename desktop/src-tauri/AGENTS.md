# partsmith-desktop

Tauri 2 desktop host: one engine `Session` behind the `call` command, native open and save dialogs, read and write access to exactly the files the user chose and the asset-named files of the `assets/` folder next to a chosen document, and the close guard. No modeling logic.

Spec: `docs/spec/desktop.md`. Decisions: ADR 0014 (Tauri, its dependencies, no fs plugin, no Tauri npm package), amended by ADR 0037 (the two asset commands, proposed, needs human review). The UI half lives in `ui/src/files/desktop-file-service.ts`, `ui/src/files/choose-file-service.ts` and `ui/src/app/close-guard.ts`.

## Interface

- `Host` (`src/host.rs`): one engine `Session` behind a mutex; `call(frame)` answers every request frame with a response frame and never panics. `Host::default()` displays meshes, as the web worker does.
- `Files` (`src/files.rs`): access to exactly the files the user picked. `pick_open` and `pick_save` go through a `Dialogs` implementation and grant the chosen path (`pick_save` adds a missing extension of the `FileKind`); `read` and `write` accept only grants in the list; `write` replaces the file atomically, through a symbolic link to the file it points to, refuses a read-only file, and on Windows tries a rename that another program blocks again for up to 630 ms (`retry_while_busy`, desktop.md 3.4 step 4.5). `read_asset` and `write_asset` take the grant of a `.ptsm` document and reach only the entries of `assets/` next to the granted path whose names pass `is_asset_name` (64 lowercase hex digits and an extension of `ASSET_EXTENSIONS`); they follow no symbolic link there, move no grant, and `write_asset` accepts only bytes whose BLAKE3 hash is the name and keeps an entry that already holds them (the entry check of file-format.md 3.11). Up to `MAX_GRANTS` paths, most recently used first, saved as `file-grants.json` in the app data directory (`Files::load`) or kept in memory (`Files::in_memory`). `grant_of(path)` is 32 hex digits of BLAKE3. `FileError` serializes as `{reason, message}` for the UI.
- `TauriDialogs` (`src/dialogs.rs`): `Dialogs` over tauri-plugin-dialog, blocking, so only called on the blocking pool.
- `Unsaved` and the close confirmation (`src/close_guard.rs`): the UI reports unsaved changes with `set_unsaved`; closing the main window then asks first.
- Commands (`src/commands.rs`): `call`, `pick_open_file`, `pick_save_file`, `read_file`, `write_file` (grant in the `Partsmith-Grant` header, raw body), `read_asset`, `write_asset` (grant in `Partsmith-Grant`, asset name in `Partsmith-Asset`, raw body) and `set_unsaved`, in `COMMAND_NAMES` order.
- `configure(builder)` adds the plugin, state and commands (shared by `run` and the command tests); `run()` adds `Files`, the close guard and the generated context.

## Commands

```sh
# These need OCCT_ROOT and, on Linux, the WebKitGTK development packages (delivery.md 3.2)
cargo test -p partsmith-desktop
cargo test -p partsmith-desktop --test integration config::   # one file of tests/, a module of tests/integration.rs
cargo clippy -p partsmith-desktop --all-targets -- -D warnings
# Tests 68 to 70 build only for Windows: the platforms workflow's rust-platforms job runs them on windows-2025 and the
# Unix tests on macos-15, then this clippy on both (delivery.md 2.14)

# The budgets of spec section 5 that Rust measures (Host::call overhead, Files::load)
cargo bench -p partsmith-desktop --bench budgets

cargo fmt -p partsmith-desktop

# The bundler, once
cargo install tauri-cli --version 2.12.2 --locked

# Run the app against the Vite dev server (run cargo tauri dev in desktop/src-tauri)
pnpm -C ui dev
cargo tauri dev

# Bundle it (run cargo tauri build in desktop/src-tauri)
pnpm -C ui build
cargo tauri build
```

## Rules

- The webview gets the least privilege that does the job: the eight commands of `COMMAND_NAMES`, each granted in `capabilities/main.json`, and nothing else. No `core:`, `dialog:` or `fs:` permission, no `tauri-plugin-fs`.
- `src/command_names.rs` is the one list of command names; `build.rs` includes it for the app manifest.
- On Windows (MSVC), `build.rs` turns off tauri-build's manifest resource, which reaches the app binary alone, and has the linker embed `windows-app-manifest.xml` into every executable of the crate, its tests included, since none starts without Common Controls version 6 (desktop.md 2.2). The file is a copy of tauri-build 2.7.2's `src/windows-app-manifest.xml`; a tauri-build update compares the two (`tests/config.rs`, test 71).
- `permissions/autogenerated/` is written by tauri-build from `COMMAND_NAMES` on every build and is committed. tauri-build never deletes a file there, so delete a renamed command's file; `tests/config.rs` checks for exactly one file per command.
- Files are reachable only through a grant from a native dialog (`Files`), and assets only next to a granted document; holding a grant string is not enough.
- `tauri.conf.json` and `capabilities/main.json` are exactly as desktop.md 2.8 and 2.9 give them; `tests/config.rs` checks both.
- `unsafe_code` stays forbidden; the Tauri macros expand to safe code.
