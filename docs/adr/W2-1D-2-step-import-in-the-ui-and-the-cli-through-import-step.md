# W2-1D-2: STEP import in the UI and the CLI through `import_step`

Status: Accepted (owner's rule of 2026-11-05): the M2 plan's item 22 and the choices below. No file format, protocol, naming, license or dependency change: the UI calls the existing command 28, `import_step`, and the CLI calls the engine's existing `Session::import_step`. It changes the wording of [ADR 0064](0064-assets-added-to-an-open-document-and-named-by-the-core.md) decision 5, which says that ui.md's `addPickedAsset` is the UI's one way to add a picked file: a picked STEP file for an import goes through `import_step`, and `addPickedAsset` stays for a file that an edit names, such as wave 3's fonts. ADR 0064 is on gate 19's list, so this note goes to human review with it. What a Save to a download target does with the imported file is [ADR W2-1D-3](W2-1D-3-a-download-save-also-downloads-the-imported-files.md).

## Context

- **What exists** (read at 0f578c1). The engine's `import_step` stores the bytes under `<blake3>.step`, adds one body named by the request's `name`, else the first solid's product name, else `Imported`, with the first solid's color, and adds an `import` feature with `op: new` at the rollback marker, as one undo entry `Import STEP` (engine.md 3.14 and 3.3; `crates/partsmith-engine/src/exchange.rs`). Protocol command 28 carries it, and the generated TypeScript types hold it (`ui/src/generated/protocol.ts`). Python's `Document.import_step` calls it. The UI has no import command (ui.md 1 and 2.10), and `CoreApi` has no `importStep`. `addPickedAsset` exists with no caller (`ui/src/app/actions/document-assets.ts`), as ui.md open issue 45 says. The CLI has five commands and no asset writer (`crates/partsmith-cli/src/arguments.rs`, `src/files.rs`).
- **The plan.** m2-plan.md item 22: an Import command in the UI and `partsmith import` in the CLI, "over the engine's existing `import_step` and wave 1's asset command". Gate 13: the UI on the web and the desktop and `partsmith import` give the same asset bytes and documents equal once generated ids are mapped, and an E-test imports a STEP part and fillets one of its edges without reopening the document.
- **The tension.** ADR 0064 decision 5 and ui.md 3.19 say the Import command calls `addPickedAsset` and then names the asset in an edit. That edit would have to add a body and an import record itself, without the product name and color that `import_step` reads (technical design section 12, "colors and names"), and the CLI would have to do the same for gate 13.

## Decision

1. **The UI imports through `import_step`.** `CoreApi.importStep(doc, bytes)` sends command 28 with the bytes as buffer 0 and no `name`, as a `change` task of the mutation queue (ui.md 2.5 and 2.6). The result names the new feature. The UI reads that feature's `asset` from the recipe of the `document_changed` the command emitted, and adds the bytes under that name to `DocumentState.assets`, so a core restart gives the core the file again (ui.md 4.4). No protocol schema changes.
2. **The command.** `file.import`, "Import...", in the Document menu after "Save as..." and in the palette, category File, no toolbar entry and no shortcut. Description: "Brings the solids of a STEP file into this document as a new body." Keywords: Insert (Fusion), Import (FreeCAD), STEP, STP. It picks with `files.pickToOpen('step')` and imports into the shown document at the rollback marker, as one undo entry `Import STEP`. While a feature command or a sketch session is open it is disabled with `finish_command_first`, as Export is (ui.md 3.18 rule 1). A file dropped on the window whose name ends in `.step` or `.stp` imports the same way.
3. **The body's name.** No host sends `name`, so the engine's rule names the body: the product name, else `Imported`. The CLI's `--name` sends one when the user asks.
4. **The CLI.** `partsmith import <STEP> -o <PTSM> [--name <NAME>] [--force] [--json] [--deny-warnings]` makes a new document: `new_document` in millimeters with no printer, `import_step`, `save_document`, in a headless session with `SequentialIds`. It writes the asset first, with file-format.md 3.11's entry check, then the document through cli.md 3.7's write. An existing output file is refused unless `--force`. An `import_warning` prints a warning and exits 0, or 1 with `--deny-warnings`, as `rebuild` does (cli.md 3.8).
5. **A missing file gets an action.** An import's `asset_missing` message offers "Choose file..." in the UI: it picks a STEP file and sends `add_assets` with the missing asset's name, which the core stores only when the bytes hash to it (ui.md 3.19). The core's message keeps its words.
6. **Stops.** A `canceled` answer (engine.md 3.26) shows the core's text as an info notification and adds nothing. A core that stops while the import runs drops it as it drops any change, with `changes_not_applied` (ui.md 4.4).
7. **How gate 13 is tested.** E-175 imports `S` into a new document in the UI, saves it through the download, and blesses `ui/e2e/fixtures/gui/import.ptsm` with its `assets/` file as E-160 blesses its documents. cli.md test 104 runs `partsmith import` on the same file and compares the two documents with their ids mapped in creation order, and the two assets byte for byte (delivery.md 2.8). The desktop's leg is a written manual check at the gate (desktop.md 6), since the desktop has no E-test harness.

## Alternatives considered

1. *The route.* (a) `import_step` with the bytes, the asset name read from the recipe; (b) `import_step` whose result gains `asset`; (c) `addPickedAsset`, then `import_step` naming the stored asset; (d) `addPickedAsset`, then `add_body` and `add_feature` in one edit; (e) a `feature.import` inspector with a file field. The rule takes (a). All five are open source. (a) is the safest: no schema change, and one engine path (name, color, undo label, marker placement) for the UI, the CLI and Python, so gate 13's equal documents hold by construction. (b) and (c) change the protocol schema for a value the recipe already holds. (d) loses the product name and color, and the CLI would have to copy it. (e) needs a new field kind and manifest hints for a feature whose only input is a file. Fusion's Insert and FreeCAD's Import are commands, not inspectors.
2. *Placement.* (i) Document menu and palette; (ii) also a toolbar entry; (iii) a feature command in Create; (iv) Open accepts `.step` and makes a new document. The rule takes (i): the least on screen (engineering principle 5), with the palette's Fusion and FreeCAD keywords finding it.
3. *Target document.* (i) the shown document at the marker; (ii) a new document; (iii) both. The rule takes (i): engine.md 3.14's tested behavior, undoable, and Fusion's Insert. The CLI makes a new document because it has no open one.
4. *The name.* (i) none, the engine's rule; (ii) the file name without its extension; (iii) ask. The rule takes (i): the STEP file's own product name, the same in every host.
5. *During a command.* (i) disabled with `finish_command_first`; (ii) joins the command's transaction. The rule takes (i), the precedent of Export, and an import is never part of another feature's edit.
6. *A dropped STEP file.* (i) import into the shown document; (ii) keep M1's "not a Partsmith model" error; (iii) open a new document with it. The rule takes (i), the same as the command.
7. *Recovery and `asset_missing`.* (i) accept the loss; (ii) store the bytes with the recovery entry; (iii) an action that picks the file and adds it; (iv) reword the core message. The rule takes (iii): the core's text stays, and the action also repairs a document whose assets folder was lost. (ii) would put large files in IndexedDB beside every autosave (ui.md open issue 48).
8. *The CLI's grammar.* A new document only, or also `--into` an existing one; an existing output replaced, refused unless `--force`, or always refused; `import_warning` exits 0 (1 with `--deny-warnings`), always 0, or 1. The rule takes a new document only, refusal unless `--force`, and `rebuild`'s warning rule. A `.ptsm` holds the user's work, so refusing is safer than export's replace. Adding to a document is what the UI's command and Python's `Document.import_step` do.
9. *Gate 13's test.* (i) a committed UI-written fixture compared by a CLI test; (ii) a committed CLI-written file compared inside an E-test; (iii) one CI job running both. The rule takes (i), [ADR 0048](0048-python-keywords-gui-round-trip-and-python-budgets.md) decision 2's pattern.

## Consequences

- ADR 0064 decision 5 now reads: a host adds a picked file that an edit names with its kind and no name (wave 3's fonts, through `addPickedAsset`), and a picked STEP file for an import through `import_step`. ui.md 3.19 says the same.
- Imports become common in documents the UI writes. Their Python export adds the file from the assets folder beside the script ([ADR W2-1D-4](W2-1D-4-export-to-python-in-the-app-and-assets-in-generated-scripts.md)).
- `ui.md` 1, 1.2 and 2.10 lose M1's "no import command". cli.md open issue 1 and architecture.md's command list change with it.
- Fusion and Onshape exports are still measured only through the project's own STEP files and OCCT's samples (kernel.md 3.8.1). A valid file ADR 0073's byte check refuses shows "Import failed. The file is not a valid STEP file." with Copy details.
