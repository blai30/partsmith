# W2-1B-2: Extrusions that end on a face or a shape, and revolutions between two angles

Status: Accepted (owner's rule of 2026-11-05); needs human review at the M2 gate for one public API change: `KernelErrorKind` gains `TargetNotReached` and `TargetPartlyReached` and `SweepFace` gains `Target`, variants that code outside `partsmith-occt-sys` may match on, as [ADR 0026](0026-kernel-facade-additions-for-errors.md) and [ADR 0053](0053-copy-features-refuse-a-body-that-is-not-valid.md) added kinds before. It specifies the kernel calls of the M2 plan's item 17 in kernel.md sections 2.6, 3.4.3 and 3.4.4 and settles the plan's choice "Revolve two sides and symmetric in the kernel". It changes no file format, protocol schema or naming algorithm and adds no dependency: `BRepAlgoAPI_Splitter` is in `TKBO`, `BRepOffsetAPI_DraftAngle` in `TKOffset` and `BRepClass_FaceClassifier` in `TKTopAlgo`, all linked (kernel.md section 3.12 item 3).

## Context

- **Spike 8.5** (kernel.md section 8.5, 2026-11-16) picked the split prism for an extrude up to a face or a body: `BRepPrimAPI_MakePrism` through the target, split by `BRepAlgoAPI_Splitter` at the face's surface or at the body, the pieces on the profile's side kept. It picked `BRepOffsetAPI_DraftAngle` on the prism's lateral faces for a taper, split the same way up to a face. It measured them on profiles of lines, arcs and circles, up to planes, a tilted plane, a cylinder and a box, with tapers of 5 degrees and a taper up to a tilted plane. It found that OCCT reports no status for a face the profile reaches only in part, so the shim's own check is the status. It did not measure cones, start faces, steep inward tapers, profiles of several regions or of conics and splines, or revolve up to a face.
- **The decisions of 2026-11-19** (wave 2's spec round, item 1) let stage 1 specify only measured constructions: planar and cylindrical targets, with every other surface kind refused by a message that names it, and up-to and tapers on profiles of conics, splines or several regions refused with messages of their own. Spike 8.10's criteria (kernel.md section 8.10) are written now, and track 4A widens from its Results.
- **Features need to tell the failures apart.** features/extrude.md (track 1C) words a target never reached and one reached in part as the newcomer error NC14, with different fixes. A kernel `InvalidInput` reaches the user only as "likely a bug" (kernel.md section 4.3), and features never parse the kernel's sentences.
- **Revolve** took one angle from the profile's position. Two-sided and symmetric revolutions (item 17) need a start other than the profile.
- **The rib** (item 28, wave 3) extrudes a face that `make_profile` does not build up to the body (kernel.md section 8.6, which reused spike 8.5's `up_to_body`).

## Decision

1. **One call for every end.** `extrude_to(profile, direction, start, end, taper, interrupt)` with `ExtrudeEnd::Offset`, `Face { shape, face }` or `Shape(shape)`, and a taper in radians, positive when the section grows along the direction. `extrude` stays, as the case of an offset with no taper: same checks, construction and bytes. `extrude_to` reads a profile's shape, plane and edge tags, never its regions, so item 28's thickened face extrudes through it.
2. **Spike 8.5's constructions, and only what it measured.** The split prism up to a planar or cylindrical face or up to a shape, and `DraftAngle` over an offset or up to a planar face. Everything else is refused with its own message (kernel.md section 3.4.3 item 1, open issue 23) until spike 8.10's Results widen it.
3. **Reach checks with kinds of their own.** After the split, the shim refuses a result that holds no image of the target (`TargetNotReached`), a face target whose end samples all lie outside the face (`TargetNotReached`), a kept piece that still holds the through prism's far cap, and a face target with some samples outside it (`TargetPartlyReached`). Their messages name no face index.
4. **Roles from history.** The face where an extrusion up to a face ends is the image of the cutting face, with role `EndCap`. An extrusion up to a shape ends on pieces of that shape's faces, each with `SweepFace::Target { face }`. Lateral faces and the start cap keep `extrude`'s roles. Edges and vertices are named by their faces, as for `extrude`.
5. **Revolve between two angles.** `revolve(profile, axis, start, end, interrupt)`: the shim rotates the profile to `start` (a location) and revolves it by `end - start`. The plan's option (a). M1's calls become `revolve(profile, axis, 0.0, angle, ..)` with the same bytes.
6. **No lock.** `BRepAlgoAPI_Splitter` and `DraftAngle` run without a mutex. Test 223 runs them on 8 threads, and a difference would bring a mutex and an open issue.

## Alternatives considered

Every option is open source, built on OCCT. The first criterion of the rule picks none of them. The rule then takes the safest, then the industry standard, then this work's recommendation. Each choice is Accepted (owner's rule of 2026-11-05).

1. *The call's shape.* Options: (i) a new `extrude_to` beside `extrude`; (ii) `extrude` takes the end and the taper, and every M1 caller changes; (iii) one call per end kind. The rule takes (i), the safest: M1's `extrude` and its 6 tests stay as they are, and one construction serves both calls. (iii) would repeat the taper and the checks three times.
2. *How a feature learns why the target was missed.* Options: (i) error kinds of their own; (ii) an `Ok` result with a reach status beside the shape; (iii) `InvalidInput` with sentences the feature compares. The rule takes (i), the safest: a missed target never returns geometry that a caller could use by mistake, and the feature matches a kind, as it does for `Canceled`. (ii) returns the whole through prism or a piece past the target as a result. (iii) ties features to the kernel's wording. Kinds are also the pattern of ADR 0026 and ADR 0053.
3. *What stage 1 takes* (decided by the decisions of 2026-11-19, item 1). Options: (i) only the measured constructions, the rest refused until spike 8.10; (ii) cones and the rest "if spike 8.10 passes". The rule takes (i), the safest: a test author gets one fixed behavior, and a spike result cannot reach code before its criteria were judged.
4. *Revolve two sides* (the plan's choice). Options: (a) the kernel takes a start and an end angle; (b) the feature rotates the profile's plane and builds the profile again. The rule takes (a): it mirrors `extrude`'s start and end, builds no profile twice, and keeps the roles of `SweepFace`.
5. *The taper's sign.* Options: (i) positive when the section grows along the direction; (ii) positive when it shrinks. The rule takes (i), spike 8.5's sign. The feature maps its own convention to it (features/extrude.md, track 1C's ADR on the taper key, sign and range).

## Consequences

- kernel.md sections 2.6, 2.13, 3.4.3, 3.4.4, 3.9 item 4, 3.10 item 9, 3.13, 4, 5 and tests 211 to 227 state it. `Operation` gains `ExtrudeTo`.
- features/extrude.md and features/revolve.md (track 1C) build on these calls, refuse what kernel.md section 3.4.3 item 1 refuses with their own messages first, and map `TargetNotReached` and `TargetPartlyReached` to NC14's messages and fixes.
- Track 4A widens section 3.4.3 item 1 and features/extrude.md from spike 8.10's Results, or an ADR keeps a class refused (open issue 23). Revolve up to a face waits for the same spike.
- The section 5 rows of `extrude_to` are set in wave 4 from measured medians ([ADR 0057](0057-budgets-set-from-the-measured-median-plus-20-percent.md)). `DraftAngle` polls never inside, so its cancel latency is measured and recorded in open issue 17.
- The core size of the change is recorded (kernel.md section 5, [ADR 0076](0076-occt-built-for-the-web-at-oz.md) decision 6).
