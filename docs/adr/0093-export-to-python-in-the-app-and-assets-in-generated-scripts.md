# 0093: Export to Python in the app, and assets in generated scripts

Status: Accepted (owner's rule of 2026-11-05): the M2 plan's item 23 and python-api.md open issue 4, with the choices below. It extends [ADR 0048](0048-python-keywords-gui-round-trip-and-python-budgets.md) decision 2 to the scripts the UI writes and to a document with an import. Decisions 4 and 5 change the code generation rules (python-api.md 3.8) and the round trip's scope (3.9): generated code for a document that reads assets adds them from the `assets` folder beside the script. That change goes to human review at the M2 gate (m2-plan.md gate 19, as the wave 2 decisions of 2026-11-19 ask in section 2 item 12). Decision 3 widens what the desktop's `allow-pick-save-file` and `allow-write-file` reach to `.py` files the user picks in the save dialog (desktop.md 8), with no new command, permission file or capability entry. That widening goes to human review at the M2 gate with the other desktop changes of M2 (m2-plan.md gate 19). No file format, protocol, naming, license or dependency change. No public Python name is added: generated code calls the existing `Document.add_asset` and the standard library's `pathlib.Path`.

## Context

- **What exists** (read at 0f578c1). The engine's `export_python` returns python-api.md 3.8's script for the current recipe, uncommitted edits included, and never fails for a recipe that loads (engine.md 3.16; `crates/partsmith-engine/src/python.rs`). Protocol command 29 carries it. `partsmith export --format py` writes it with the media type `text/x-python` (cli.md 3.4). The UI has no command for it (ui.md 1.2, "Python export UI"), and `FileKind` has no `py` (`ui/src/files/file-service.ts`; `desktop/src-tauri/src/files.rs`). M1's Export is disabled during a feature command, not during a sketch session (`needsDocumentOutsideCommand` in `ui/src/commands/builtin.ts`).
- **The success criterion.** Technical design section 1: every GUI-built model exports to Python that rebuilds the identical shape. m2-plan.md gate 4: the UI's Export to Python does it for the four parts.
- **Imports in scripts.** The import record has no dedicated Python form, since a script cannot carry the file's bytes (features/import.md, Python). Generated code writes the generic `feature("import", ..., asset="<name>", ...)` and fails with `asset_missing` in a fresh document. [ADR 0064](0064-assets-added-to-an-open-document-and-named-by-the-core.md) gave Python `Document.add_asset(path)`, and python-api.md open issue 4 left "where generated code finds the bytes" to item 33. Round trips and Python twins therefore leave out every document with an import (python-api.md 3.9; delivery.md 2.8). [ADR 0091](0091-step-import-in-the-ui-and-the-cli-through-import-step.md) makes such documents common in the UI.
- **Where the bytes are.** Every host writes a document's assets to the `assets` folder beside it (file-format.md 3.11). `run_code` sets `__file__` to its `filename`, and `run_script` passes the script's path (python-api.md 3.12). CadQuery and build123d scripts load STEP files by a path relative to the script.

## Decision

1. **The command.** `file.export_python`, "Export to Python...", in the Document menu after "Export..." and in the palette, category File, no toolbar entry and no shortcut. Description: "Saves this model as a Python script that rebuilds it." Keywords: Python, script, code, CadQuery, build123d. During a feature command it is disabled with `finish_command_first`, as Export is. During a sketch session it is disabled with `finish_sketch_first` ("Finish Sketch 1 first."), which Export does not check (ui.md 3.18, Export to Python step 1). The script then never holds a preview or an unfinished sketch. The plan recommends `finish_command_first` alone, and the sketch session's case extends it (alternative 3). It asks where to save first (`chooseSaveTarget('{name}.py', 'py')`), then calls `CoreApi.exportPython` (command 29, an `other` task of the mutation queue), then writes the code as UTF-8.
2. **The notices.** When features have status `error`, the script is still saved, and the warning `python_failed_features` names the first and gives their count: their code is in the script, and running it raises `FeatureError` at the first. An import whose errors are all `asset_missing`, and every feature whose root is such an import, do not count: the script adds the file this session lacks from beside it (decision 4). Otherwise, when the script reads assets, the info notification `python_saved_assets` says that the script reads them from the `assets` folder beside it and asks the user to keep the script in the document's folder (desktop.md open issue 15). For a document never saved, which has no such folder yet, `python_saved_assets_unsaved` says to save the model first (ui.md 3.18 step 4).
3. **A `py` file kind.** `py` "Python script", `text/x-python`, `.py`, in ui.md's `FILE_TYPES` and the desktop's `FileKind` (desktop.md 2.4). The media type is the CLI's (cli.md 3.4).
4. **Assets in generated code.** When valid records of the recipe read assets, the script imports `Path` from `pathlib` and adds each asset after the document line, in name order: `doc.add_asset(Path(__file__).parent / "assets" / "<name>")`. Run as a file, the script reads the `assets` folder beside it. Run with `run_code` and no file name, it reads `assets` in the working directory. A missing file raises `FileNotFoundError` with its path, before any record names it. The records keep their stored form. A document without assets gets the same script as before.
5. **Round trips with imports.** python-api.md 3.9's first form holds for documents with imports, run with a file name beside the document's `assets` folder. An example with an import qualifies for a Python twin once its features build (delivery.md 2.8).
6. **How gate 4 is tested.** E-160 and E-175 also export each GUI document they write to Python through the command and write the `.py` beside it in `ui/e2e/fixtures/gui/`, blessed with the document. `python/tests/test_gui_documents.py` runs the committed script: it makes one document whose text is the committed `.ptsm` byte for byte, and whose features and bodies match it (delivery.md 2.8, check 4). A script that a later change to the Python API leaves unable to rebuild its document is deleted and blessed again with its document. Wave 5 adds the four parts (m2-plan.md gate 4).

## Alternatives considered

1. *Placement.* (i) a command in the Document menu and the palette; (ii) a "Python" format in the export popover; (iii) both; (iv) wait for M4's code panel. The rule takes (i). All four are the project's own code. (i) is the safest: the export popover exports bodies with a printer orientation, and a script has neither. In (ii) and (iii) its controls would do nothing for a script. Fusion and FreeCAD put script and macro commands in menus apart from the mesh exports. (iv) misses gate 4. The plan recommends (i).
2. *File kind.* (i) a `py` kind; (ii) plain text with no kind. The rule takes (i). Both are the project's own code. (i) is the safer: the save dialog filters `.py` files, and the desktop dialog names the kind. The industry standard is the `.py` extension with the media type `text/x-python`, which the CLI already writes. The plan recommends (i).
3. *Failed and uncommitted features.* (i) disabled during a feature command (`finish_command_first`) and a sketch session (`finish_sketch_first`), saved with a warning when features failed; (ii) the same, disabled during a feature command only, as M1's Export is; (iii) export the preview; (iv) export silently. The rule takes (i). All four are the project's own code. (i) is the safest: the script holds only committed work and no sketch the user is still drawing, and the user learns which feature stops it. No industry standard decides it. The plan recommends disabling the command with `finish_command_first` and a warning when features failed, which is (ii). (i) extends it to the sketch session, as Import's availability does ([ADR 0091](0091-step-import-in-the-ui-and-the-cli-through-import-step.md) alternative 5). A sketch session commits each edit, and a script saved in the middle of one holds the sketch half drawn, a file the user keeps and runs later. The session's reason is `finish_sketch_first`, since `finish_command_first` names a command title and a cancel that a sketch session does not have.
4. *Imports in generated scripts.* (i) export with a warning; (ii) disable the command; (iii) generated code adds the asset from the assets folder beside the script; (iv) embed the bytes in the script. The rule takes (iii). All four use only the project's code and Python's standard library. (iii) is the safest: every GUI model then exports to a script that rebuilds (technical design section 1), while (i) and (ii) break the success criterion for every imported part and (iv) puts megabytes of base64 in a script meant to be read. `Path(__file__).parent` is how Python scripts find their data files, and CadQuery and build123d scripts load STEP files beside them the same way. The plan recommends (iii). Its reason said a missing folder fails with `asset_missing`'s message. `add_asset` raises `FileNotFoundError` naming the path it looked at instead, Python's own error for a missing file, which says more.
5. *Gate 4's test.* (i) the UI's `.py` written beside E-160's documents for pytest; (ii) an E-test that compares the download with the core's `export_python`; (iii) wave 5 alone. The rule takes (i). All three are the project's own code. (i) is the safest: the script the UI saved runs in real Python on every change. Committed files that a test checks (golden files) are the industry standard, and [ADR 0048](0048-python-keywords-gui-round-trip-and-python-budgets.md) decision 2 uses them. The plan recommends (i).

## Consequences

- A script with assets has a second import line, `from pathlib import Path`. A script without assets is byte for byte what M1 generated. Every existing twin and engine test holds.
- `examples/import/` gets Python twins for the examples whose features build, written by the Python bless (delivery.md 2.8).
- The scripts the UI writes join the fixtures the e2e bless writes.
- The Document menu gains Export to Python... The visual baselines V-23 and V-24, which show that menu open, are taken again and reviewed at the gate (ui.md 6.6), with [ADR 0091](0091-step-import-in-the-ui-and-the-cli-through-import-step.md)'s Import....
- A user who moves a script without its `assets` folder gets `FileNotFoundError` naming the path.
