# 0064: Assets added to an open document, and named by the core

Status: Accepted (owner's rule of 2026-11-05): the M2 plan's item 5 and the choices below. It changes the protocol schema: command 38, `add_assets`, with its request and result types, the type `AssetUse` and the member `missing_assets` of `document_changed`. It also changes the words of the error `asset_mismatch`. Both go to human review at the M2 gate (AGENTS.md Process, m2-plan.md gate 19). The desktop's font asset kinds and the font file kind of its open dialog are [ADR 0037](0037-save-checks-the-file-and-hosts-reach-the-assets-folder.md)'s amendment of 2026-11-07 on font assets, which goes to the same review. No file format, naming, license or dependency change. `PROTOCOL_VERSION` stays 1 (ADR 0024's additive rule). From M2 this ADR supersedes ADR 0037 decision 2 (the UI reads asset names from the `.ptsm` text), the reopen that ends decision 7, decision 7's wait during a feature command for the Choose folder that adds assets (choice 6), and the retry of decision 8.

## Context

- **The UI reads `.ptsm` text for one purpose.** Open gives the core the files of `assets/` whose names are string values in the document's JSON. `referencedAssetNames` in `ui/src/files/assets.ts` collects them. `readDocumentAssets` and `chooseDocumentFolder` in `ui/src/app/actions/document-assets.ts` call it (at a3f4573). ADR 0037 decision 2 logged this as the one exception to ui.md section 1's rule that the UI never parses `.ptsm` text. The owner accepted it on 2026-11-04 and left moving the reading into the core for after M1.
- **The core already knows the names.** The engine collects the asset names that the valid records read through `Registry::dependencies` (`asset_names` in `crates/partsmith-engine/src/assets.rs`). `open_document` keeps the supplied assets that a record reads. It refuses the whole document when one of them does not hash to its name (`referenced_assets`, `EngineError::AssetMismatch`). Nothing reports the names to a host.
- **No command adds an asset to an open document.** `open_document` and `import_step` are the only ways in (protocol.md commands 6 and 28). On the web, a document opened without its folder gets its assets only through "Choose folder". It reopens the settled recipe as a core restart does (`reopenWithAssets` in `document-assets.ts`, ui.md section 3.19). The undo history, the selection and an open feature command are lost (ui.md open issue 37).
- **A wrong file refuses every file.** One file under an asset's name that holds other bytes makes the core refuse the whole document. The UI then opens the text again without any asset (ADR 0037 decision 8). The core's message is `Asset {name} does not match its content hash.` It names the file by its hash, which the error guidelines keep out of messages. The UI cannot say which import lost its file (ui.md open issue 36).
- **Later waves add files the user picks.** Wave 2's Import command picks a STEP file in the UI and names it in an `import` record (m2-plan.md item 22). Wave 3's sketch text stores a user font as a content-hashed asset (item 27, choice 13). The UI has no BLAKE3. ADR 0037 declined to add it (Alternatives considered).
- **Python cannot add a file.** A script imports a STEP file only through `import_step`, which makes a new body and feature. Generated code for an `import` record fails with `asset_missing` in a fresh document (python-api.md open issue 4).

## Decision

1. **`add_assets`** (protocol.md command 38, engine.md section 3.14). `add_assets {doc, assets: Vec<AssetInput>}` puts files into the asset store of an open document. Each entry has `kind` (`step`, `ttf` or `otf`), `data` (a `u8` buffer) and an optional `name`. The engine names each file `<BLAKE3 hex of the bytes>.<kind>`. An entry with `name` is a file that a host read from the document's `assets/` folder under that name. It is stored only when that name is the one the engine computes. An entry without `name` is a file the user picked. It is always stored. The result lists each entry's name and whether it was stored, in the order given. The command changes no recipe, revision, dirty state, undo or redo stack, transaction or focus. When it stores a file that a valid record reads and the store lacked, the engine recomputes with the current focus and resolved profile. It emits that recompute's events. It works inside a transaction. Its recompute stops like any other (engine.md section 3.26).
2. **The core reports the names** (protocol.md section 2.7). `document_changed` gains `missing_assets`: each asset name that a valid record of the recipe reads and the session's store lacks, sorted by name, with the features that read it in timeline order. It is emitted whenever it changes, as every `document_changed` member is.
3. **The UI reads no `.ptsm` text** (ui.md sections 1, 2.15 and 3.19). `referencedAssetNames` and `ASSET_NAME` are removed. Open sends `open_document` without assets, reads the names of `missing_assets` from the folder, and adds what it read with one `add_assets` before it shows the document. Choose folder adds them to the open document. The undo history, the selection, the open command and the sketch session stay. A core restart still reopens the settled recipe with the files the core stored before (ui.md section 4.4). A test checks that no module under `ui/src` parses JSON text but the frame codec and the settings store (gate 13).
4. **A wrong file is refused alone.** In `add_assets`, a named entry whose bytes do not hash to its name is not stored (`stored: false`). The other entries are. The UI's `assets_mismatch` names the features that read a refused file. `open_document` still refuses a whole document for a wrong supplied file: the CLI and Python pass every asset-named file of a folder to it. Its `asset_mismatch` message now names the feature that reads the file, in words. Its detail names the file (engine.md section 4).
5. **Picked files** (waves 2 and 3). A host adds a file the user picked with its kind and no name, and takes the asset name from the result. It then names that asset in an edit, such as the `asset` of an `import` record or the font of a text entity. A stored file that no record reads stays in the store until the document closes. `save_document` returns only the assets a record reads, as in M1. ui.md's `addPickedAsset` is the UI's one way to do it. The specs of wave 2's Import command and wave 3's sketch text say where the UI picks the files.
6. **Python** (python-api.md sections 2.4 and 3.7). `Document.add_asset(path)` reads a STEP or font file, adds it and returns its asset name.

## Alternatives considered

The plan settled that a command adds an asset to an open document and that the core reads the names (m2-plan.md item 5). The spec met seven choices that the plan leaves open. The owner's rule settles each: the most open-source approach, the safest, the industry standard and the recommendation of this work. Every option is open source, and the first criterion picks none of them.

1. *How a host learns the names.* Options: (i) `document_changed` carries the missing names, and a host opens a document without assets and then adds the files it reads; (ii) a command that loads a text and returns the asset names it reads, before `open_document`, after which the host opens with the files as in M1; (iii) the names in the result of `open_document` only. The rule takes (i), the safest. The names are always those of the current recipe, also after an undo brings an import back or when Choose folder comes long after Open. The UI never parses the text, and the core loads it once. (ii) loads every text twice and still needs (i) or a query for Choose folder. (iii) is stale after the first edit. The cost of (i) is a first recompute in which each import fails at once with `asset_missing`, before any kernel call. The features after it that read its body build in the first recompute against the body without the import. They build again in the second recompute. A missing asset is part of the cache key (recompute.md section 3.4). The features that read neither its body nor its output are cached for the second recompute.
2. *Named and picked files.* Options: (i) one command whose entries all carry a kind and may carry a name; (ii) two commands, one for named files and one for picked files; (iii) named files only, with BLAKE3 in the UI. The rule takes (i), the recommendation of this work. One rule names every file, and the check of a named entry compares two names. (ii) doubles the commands for one store. (iii) adds a dependency to the UI, which ADR 0037 declined.
3. *A wrong file among several.* Options: (i) store the others and report the wrong one; (ii) refuse the whole command with `asset_mismatch`, as `open_document` does. The rule takes (i), the safest. One bad copy no longer hides the geometry of every other import (ui.md open issue 36).
4. *Files no record reads.* Options: (i) store them until the document closes; (ii) ignore them, as `open_document` does. The rule takes (i), the safest. A picked font or STEP file is added before the edit that names it. A canceled command or an undo can leave it unnamed for a while. With (ii) it would be lost. `save_document` writes only what a record reads. No extra file reaches the folder.
5. *The words of `asset_mismatch`.* Options: (i) the file of the feature that reads it, in words, with the asset's name in the detail; (ii) the hash in the message, as in M1; (iii) a new `asset` member of `ErrorInfo`. The rule takes (i), the industry standard this project writes down in its error guidelines: what happened, named as the user sees it, with hashes in the detail only. (iii) changes the error shape for hosts that already read `detail`.
6. *Choose folder during a feature command.* Options: (i) it runs at once and keeps the command, since adding files edits nothing; (ii) it waits for the command and refuses with `finish_command_first`, as M1's reopen did. The rule takes (i), the safest. The command's preview rebuilds with the files, and nothing the user typed is lost.
7. *A script's way in.* Options: (i) `Document.add_asset(path)`, which returns the name; (ii) none until generated code can add files too. The rule takes (i), the recommendation of this work. A script can name a STEP or font file in a record now. Generated code that adds the file needs a place where the script finds it, which item 33's Python work decides (python-api.md open issue 4).

## Consequences

- The UI depends only on the protocol for assets. ui.md section 1's exception is gone, and gate 13's test checks it (ui.md U-276).
- Choose folder keeps the undo history (gate 13, ui.md E-173). ui.md open issues 36 and 37 lose the parts that this ADR settles.
- partsmith-protocol gains command 38, `AssetInput`, `AssetKind`, `AddedAsset`, `AssetUse` and `DocumentChanged::missing_assets` (protocol.md tests 105 to 109, and test 34's list). `docs/format/protocol.schema.json` and `ui/src/generated/protocol.ts` are regenerated and logged in ADR 0016 when they are checked in.
- partsmith-engine gains `Session::add_assets`, `Session::missing_assets`, `NewAsset` and the new words of `EngineError::AssetMismatch`, which `validate` shares (engine.md tests 211 to 224 and 233). The CLI and Python print those words (cli.md tests 86 and 87, python-api.md tests 133 to 137).
- The UI gains `CoreApi.addAssets`, `DocumentState.missingAssets`, `assetKindOf`, `addPickedAsset`, a font `FileKind` and the new Open and Choose folder (ui.md U-276 to U-284 and E-173). U-217 retires with `referencedAssetNames`. U-219, U-220 (b), U-222 and U-229 change with the order of Open and Choose folder. Every check of what the core holds and what the user sees stays. The calls they check now include `add_assets`.
- The desktop gains the font kind of its open dialog and the font asset extensions (ADR 0037's amendment of 2026-11-07 on font assets, desktop.md tests 30, 54 and 79 to 83). file-format.md section 3.11 names the asset kinds, and its test 70 checks that the format needs no change for them.
- recompute.md section 3.4 puts each asset's presence into the cache key (item 9). A reopen with assets in the same session could reuse a result built without them, as M1's Choose folder did. That stops too. Adding a missing asset builds the import and the features after it that read its bodies or its output again (engine.md section 3.14, test 233).
- A document with imports opens with two recomputes on the hosts that read its folder after the open. The first fails each import at once, and the second builds them. The CLI and Python still pass every asset-named file to `open_document` and recompute once.
- Python's generated code still writes an `import` record without adding its file. Round trips still leave such documents out (python-api.md section 3.9).
- This changes the protocol schema. It goes to human review at the M2 gate.
