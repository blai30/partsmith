# 0054: The full-rebuild gate is judged on the macOS arm64 runner of the platforms workflow

Status: Accepted (owner, 2026-11-04): technical design section 14's full-rebuild gate is judged on the macOS arm64 runner of `platforms.yml` (`macos-15`), by a timed run of `bench50` from an empty cache added there. A median over 1 s goes to the owner with an ADR that raises the budget or schedules speed work. Wave F's bench-gate track built it as the job `full-rebuild` (decisions 2 to 6). No capability, schema, license or dependency change: the job uses actions that delivery.md 2.2 already pins and the benchmark the repository already has. Decision 5 amends ADR 0038's promotion rule for this one job, as the owner's decision requires: `full-rebuild` stays in `platforms.yml`. The first median on `macos-15` was 1.477 s (platforms run 14, 41926898084, on 0ae7337). Decision 6 for that median is Accepted (owner, 2026-11-05): option (a). [ADR 0057](0057-budgets-set-from-the-measured-median-plus-20-percent.md) sets the budget the runner holds from that median: 1.477 s plus a margin of 20 percent for runner noise, rounded up to 1.8 s. Speed work is recorded there as later work. The clause of release checklist item 2 on the median is Accepted (owner, 2026-11-05): option (b) of delivery.md section 8. The owner also gave wave G's workflows-docs track leave to apply the wording of `.github/workflows/AGENTS.md` for the job. Wave G built all three: ADR 0057 on 2026-11-05, the checklist clause and that wording on 2026-11-06.

## Context

- **A release gate with no machine.** Technical design section 14 makes its budgets release gates, measured on a 2022 mid-range laptop. A full rebuild of a 50-feature part has 1 s on the desktop. recompute.md section 5 holds the same row, `run` of `bench50` from an empty cache. `crates/partsmith-recompute/benches/budgets.rs` measures it. The reference laptop has never run it. The fixed hardware runner of technical design section 16 is Later (delivery.md 1.2).
- **What the row reads elsewhere.** On the 4-core development container the row read 4.37 s, then 2.96, 2.56, 2.10 and 2.45 to 3.03 s over October as the kernel and the features changed (recompute.md open issue 4). On 2026-11-04 it read 1.780, 1.892, 1.676 and 1.821 s (four runs of the benchmark, each the median of 7, at load 3 to 8, the last one through the step's script). A profile put OCCT's own share near 1 s.
- **The owner's question.** recompute.md open issue 4 asked for a decision on the budget against these numbers. On 2026-11-04 the owner chose where the number is judged instead: on the macOS arm64 runner of the platforms workflow. That workflow runs every week and on demand outside the deploy gate (ADR 0038).
- **What the workflow had.** `platforms.yml` builds or restores OCCT on `macos-15` in `occt-platforms` and runs debug tests there in `rust-platforms`, with its own Rust cache and 60 minutes. No job built anything in release on macOS outside a release's `bundle` job.

## Decision

1. **Where.** The full-rebuild gate is judged on `macos-15` in `platforms.yml` (the owner's decision).
2. **A job of its own.** `full-rebuild` (`Full rebuild of bench50 (macos-15)`) runs on `macos-15` after `occt-platforms`, with `if: ${{ !cancelled() }}` as `rust-platforms` has, 60 minutes, `bash` as the shell of its steps and `MACOSX_DEPLOYMENT_TARGET` 13.0 in its `env`. It restores OCCT with `fail-on-cache-miss: true`, installs the toolchain and uses a Rust cache of its own (saved on `main`, also after a failure, as `rust-platforms` saves its).
3. **The existing row.** Its last step runs `cargo bench -p partsmith-recompute --bench budgets -- "run of bench50 from an empty cache"`. Cargo builds the benchmark in the `bench` profile (the `release` profile with its thin LTO). The benchmark times only that row: one untimed run that checks no feature of `bench50` fails, then the median of 7 runs, each on a new `Recompute`. The benchmark's code does not change.
4. **What it reports.** The step reads the row that `Report` of `partsmith-budgets` prints for the operation and appends a table to the job summary: the runner, the operation, the median and the budget, with a verdict. A median over its budget adds a warning to the run. The step still exits 0. The benchmark's own exit status, 1 over budget, is not used. A run that prints no row (a failed build, a panic, a missing `bench50`) fails the step with an error (delivery.md 2.14 and section 4). The gate then has no number.
5. **Never promoted.** The job stays in `platforms.yml` when the other jobs move into `ci.yml` under ADR 0038's promotion rule. The owner's decision names the runner of `platforms.yml`. A job moved into `ci.yml` would no longer run there. This amends ADR 0038's promotion rule (its decision 2) for this one job. Whenever `occt-platforms`, or its `macos-15` row, moves into `ci.yml`, `platforms.yml` keeps a copy of the `macos-15` row, whatever else is left there. `full-rebuild` needs it. GitHub rejects a workflow whose `needs` names a job the file does not have (delivery.md 2.14, promotion step 1, test 104). Once no other job is left, the workflow and the release checklist's platforms run stay (promotion step 4). Before this change, step 4 deleted the workflow and dropped that clause.
6. **Over 1 s.** A median over 1 s on the runner goes to the owner with a new ADR, proposed, needs human review. Its options are (a) a budget that the runner holds and (b) speed work with the budget kept, such as reusing the fingerprints of kept faces through the kernel's history (recompute.md open issue 4). For the first median over 1 s, 1.477 s (platforms run 14), the owner chose option (a) on 2026-11-05. ADR 0057 sets its budget, 1.8 s, and carries *Accepted (owner, 2026-11-05)*, not *proposed, needs human review*. The job's summary then shows the budget `1.800s`, and the sentences of this decision about 1 s apply to 1.8 s. The release checklist does not change here: a release waits for a passing platforms run of its commit (delivery.md 3.6). That run's summary holds the commit's median. A median over the budget still lets the run pass. After the owner's first decision, a later median over the budget shows only as a warning on a passing run. Until 2026-11-06, nothing in the checklist stopped a release for it. A clause of checklist item 2 that asks for the median within its budget, or an ADR the owner decided that covers it, is Accepted (owner, 2026-11-05): option (b) of delivery.md section 8. Both copies of the checklist change together. One of them is in `.github/workflows/AGENTS.md`, the owner's file.

## Options considered

- **Where the timing runs:** (a) a job of its own (chosen: it runs beside `rust-platforms` on another runner and adds runner time but no wall time while it ends before the run's slowest job, the release build stays apart from `rust-platforms`' debug builds and its Rust cache, and `rust-platforms`' steps and 60 minutes stay as they are); (b) a step of the `macos-15` row of `rust-platforms`, with `if: runner.os == 'macOS'`, which needs no second runner but adds a release build after the debug tests in a job of 60 minutes, mixes release and debug builds in one Rust cache, and makes the row's timing depend on what ran before it on the same runner; (c) the release's `bundle` job, which runs only before a release and would give no weekly number.
- **What fails:** (a) nothing over budget, a warning and the summary (chosen: the owner decides on the number, and a red run would block every release, which waits for a passing platforms run, on a number the owner may accept); (b) the job over budget (it turns the owner's call into a failed run); (c) nothing at all, even without a number (it would hide a broken build or a missing `bench50` behind a green run).
- **How the number is read:** (a) the row the benchmark prints (chosen: no change to the benchmark or to `partsmith-budgets`, and a renamed row or another row format fails the step with an error in the next run, which delivery.md test 104 also guards by checking the row's name in `budgets.rs` and its layout in `report.rs`); (b) a machine-readable report from `partsmith-budgets`, a new interface with one reader.

## Consequences

- delivery.md 1.1, 2.14 (the job, the full-rebuild gate, promotion steps 1 and 4), 3.2, section 4 (the warning and the error), tests 49, 60 and 104 to 106, open issue 16 and section 8; technical design section 14; recompute.md section 5 and open issue 4; the gap list's B-11; `crates/partsmith-recompute/AGENTS.md` (the command and the row name the step reads) and `crates/partsmith-budgets/AGENTS.md` (the row format it reads); ADR 0038's status line and its log row (the amended promotion rule).
- Each platforms run gains a job on `macos-15`. On the development container, a cold release build of the benchmark took 1 min 32 s, a build with every dependency built 30 s, and the timed run 14 to 16 s. Its Rust cache, the release builds of the benchmark's dependencies (about 170 MB on disk here), shares GitHub's 10 GB with the other caches. The first runs record the job's times, the cache's size and the runner's median (delivery.md test 106, open issue 16, recompute.md open issue 4).
- A hosted runner is a virtual machine whose speed varies between runs and runner images. The median of 7 does not remove that. recompute.md open issue 4 records each median with the run that measured it.
- No release build of the workspace has run on macOS in CI yet (no release dry run so far). The job's first run is also the first macOS release build that links OCCT with thin LTO. Only that run shows it links.
- `.github/workflows/AGENTS.md` is the owner's file. Until 2026-11-06 its `platforms.yml` line did not name `full-rebuild`, and its promotion rule named no exception. Wave G's workflows-docs track then applied the wording of delivery.md section 8 with the owner's leave: the `platforms.yml` line names `full-rebuild` and its budget, the promotion rule keeps it and a copy of the `macos-15` row of `occt-platforms` in `platforms.yml`, and checklist item 2 ends with the clause on the median.
