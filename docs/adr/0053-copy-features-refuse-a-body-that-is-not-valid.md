# 0053: Copy features refuse a body that is not valid, and the kernel tells a mirror of an invalid solid from its own failure

Status: Proposed, needs human review: a public API change of `partsmith-occt-sys` (the variant `KernelErrorKind::InvalidInputShape` and the exception `Partsmith_InvalidInputShape`) and of `partsmith-features` (the variant `FeatureError::BodyNotValid` and the function `has_volume`, which moves there from `partsmith-engine`), the human gate of item ENG-8 of the M1 gap list. No file format, protocol schema, license, dependency or capability change: the message code `body_not_valid` travels in the diagnostic's `code` string, which no schema lists, and the kernel's kind never leaves the Rust API.

## Context

- **A user's file worded as a fault of Partsmith** (engine.md open issue 22, gap list ENG-8). `read_step` keeps a solid that repair could not fix and the import warns about it (ADR 0045). A mirror or scale builds every element anew. The kernel checks the whole result (kernel.md section 3.5 item 4), finds the copied solid still invalid after repair and raises `InvalidResult`. Its `transform` hint, `Report it with the details.`, then words the user's STEP file as a bug: `mirror(): Partsmith's geometry kernel could not build this mirror. Report it with the details.` This held for `mirror(Plane.YZ)` and `mirror(Plane.XY)` of `SELF_VOID` (a solid whose void is its own outer shell, without volume) and of `VOID_TWICE` (a void listed twice, with volume), and for a scale by 2 of either.
- **Material from nothing.** The patterns move their copies rigidly, which the kernel does not check, and fuse them. Three copies of `SELF_VOID`'s body 30 mm apart along X built with status ok as three full boxes, 72000 mm³ for the 20 x 30 x 40 mm box of engine.md test 162, 18000 mm³ for the 10 x 20 x 30 mm block of features/import.md. Copies that overlapped it, and a circular pattern of 4, warned that they added nothing, and a circular pattern into an empty body left that body with a shape that holds no solid, with status ok.
- **What the other features do.** Checked on 2026-11-03 through recompute and in the kernel: `move_body` moves such a solid as it is; the booleans, the joins of the solid features and `split_body` give results that range from right to wrong with no message of their own, under the import's warning (features.md open issue 23). Their kernel calls do not fail on these solids, except a fillet of `VOID_TWICE` and a shell of `SELF_VOID`, which fail with `InvalidResult`, whose hints do not blame Partsmith.
- **What checks cost.** On bench50's 426-face body (release build, this container, 2026-11-03), `BRepCheck_Analyzer` of the whole body took 91 ms, its area 12.7 ms, its volume 11 to 20 ms and its mirror 130 to 190 ms. On a 57-face body the check took 9.5 to 11 ms and the area 0.2 ms.

## Decision

1. **The kernel tells a mirror or scale of an invalid solid apart** (kernel.md sections 2.13, 3.5, 3.9 and 4, tests 144 and 145). When the repaired copy of a mirror or scale `transform` stays invalid, and only then, the shim checks the shape the transform was given in full, as the caller passed it, and raises `Partsmith_InvalidInputShape` (kind `InvalidInputShape`, detail kind `invalid_input_shape`) when that shape was not valid either. Valid results pay nothing, and a mirror or scale of a valid shape does not reach the check. The kind's hint is the same for every operation, `The shape it was given was already not valid, so repair the STEP file that shape came from, or export the file again.` In Partsmith's own use such a shape comes only from a STEP file whose solid repair could not fix. Every other operation keeps `InvalidResult` and its hint, none of which words the failure as a fault of Partsmith.
2. **The copy features refuse a body that is not valid** (features.md sections 3.5 and 4.1). Mirror, linear pattern and circular pattern read a source whose shape holds no solid as `BodyEmpty`. They fail with `body_not_valid` when their source body has no volume (`has_volume`, the limit of engine.md section 3.11, checked right after `BodyEmpty`), and mirror also when its kernel `transform` fails with `InvalidInputShape`. The message names the body and, when the solid came from an import, that import, and says what to do: `Body 'Block' holds a solid from 'Import 1' that is not valid, so this mirror cannot copy it. Repair the STEP file, or export it again from the program that made it.` It offers Show of the feature that put the solid in the body. They fail rather than build with a warning: a copy of a solid without volume is a full box or nothing, and nothing built from it is worth keeping. Failing needs no new warning type and leaves every body as it was.
3. **The feature that put the solid in the body is found by the feature itself.** It is `made_by`, the newest writer in the body's writer chain (`body_history`) whose state just before it holds no shape or a valid one, looked for only on the failure path. A body starts empty, and its oldest writer always qualifies. When its record is not an import (a feature whose result kept an invalid solid's unchanged faces), the message names no feature and says `Repair the STEP file it came from`. This needs no change of recompute's diagnosis. The protocol's `Message::root`, whose doc comment lists the messages that set it, does not change either.
4. **`has_volume` moves to `partsmith-features`**, which the engine's `measure` and the copy features share, with engine.md test 164's cases as its unit tests (features.md test 19). The copy features read the body's area from the face fingerprints of its topology, which a body built by a feature carries already.
5. **Tests.** kernel.md tests 144 and 145; features.md test 19 of section 6.5; features/mirror.md tests 14 to 16, features/linear_pattern.md test 25 and features/circular_pattern.md test 19; features/import.md's new fixture `SELF_VOID` (the edit of engine.md test 162 applied to `BYTES`) and test 17; python-api.md test 117.

## Options considered

The owner can still pick another of these:

- **(a) The kernel tells a mirror or scale of an invalid solid apart, and the copy features refuse a body without volume or one whose mirror the kernel finds invalid** (chosen). The least code that keeps every kernel hint true and stops a pattern of a body without volume from gaining material.
- **(b) No new kernel kind.** On `InvalidResult` from `transform`, the mirror asks `Shape::is_valid` of its source itself. No kernel API change, but the `transform` hint `Report it with the details.` stays untrue for any other caller.
- **(c) Build with a warning.** The patterns keep what the kernel's boolean makes of the copies and add a warning that the body is not valid. The full boxes stay in the model, and the mirror still has nothing to build.
- **(d) `Shape::is_valid` of every source, up front.** Exact for `VOID_TWICE`'s patterns too, which (a) leaves under the import's warning, but 91 ms on bench50's body for every copy feature that builds.
- **(e) `read_step` leaves out solids without volume** (ENG-7's other option, ADR 0045's review). Covers `SELF_VOID` everywhere, not a mirror of `VOID_TWICE`, and drops geometry the user may still want to see or export.
- **(f) The same rule in every feature that reads a body** (the booleans, `apply_op`, `split_body`), with a message that says the feature cannot use the body. Covers features.md open issue 23, for the area of every body on every build.
- **(g) Recompute's diagnosis names the import**, as it names the cause of `body_empty`, and sets the message's root. Hosts then group the copy's error under the import's warning. This changes recompute and the protocol's `root` documentation.
- **(h) The input check for every operation.** The booleans, fillet, chamfer, shell and split check their facade inputs as the caller passed them when their result stays invalid, and raise `InvalidInputShape` too. Every failing call on valid inputs then pays the check (91 ms on bench50's body), at each attempt of the "too large" search as well, and that search would have to stop on the new kind.
- **(i) A volume bound for the patterns.** A pattern whose result volume exceeds the copies' total volume by more than 1e-6 relative fails with `body_not_valid`, with no extra kernel call. It catches every gain recorded for `VOID_TWICE` too (features.md open issue 23).

## Consequences

- kernel.md sections 2.13, 3.5 (item 4 and the repair paragraph), 3.9 item 4, 4.1 and 4.3, tests 144 and 145 and open issue 16; features.md sections 2.1, 2.7, 2.8, 2.11, 3.5, 3.10 and 4.1, test 19 of section 6.5 and open issue 23; features/mirror.md, linear_pattern.md and circular_pattern.md sections 3.3 and 4 and their new tests; features/import.md's fixture `SELF_VOID` and test 17; engine.md section 3.11, test 164 and open issue 22, now resolved; python-api.md test 117.
- The code change is in `cpp/validity.cpp` (`ensure_valid_copy`) and `cpp/transforms.cpp` (the transform passes its input to the check), `cpp/shim.h`, `cpp/internal.h`, `cpp/shape.cpp` and `src/error.rs` of `partsmith-occt-sys`; in `builtin/copy.rs`, `src/error/mod.rs` and `src/output.rs` (`has_volume`) of `partsmith-features`; and in `src/inspect.rs` of `partsmith-engine`, which imports `has_volume`.
- Fillet, chamfer, shell, the booleans and split keep `InvalidResult` and their hints on an invalid input. A fillet, chamfer or shell then runs the "too large" search as for any other failure.
- A pattern of a solid that has volume but is not valid, such as `VOID_TWICE`, still builds what the kernel's boolean makes of it, under the import's warning (features.md open issue 23).
- Reverting is local: drop the variant and the transform's input check, and the copy features' checks and variant. Nothing is stored in documents or caches, and recompute's cache keys change only with the crate versions, as for any code change.
