# 0059: Curve chains for paths and open profiles, and the region union in the sketch crate

Status: Accepted (owner's rule of 2026-11-05): the M2 plan's item 3, with the choices below. It adds a record shape that format version 3 documents will hold: sketch.md's chain reference `ChainRef` (`key`, `fp` and `closed`) inside features.md's `ChainProfileRef` (`sketch` and `chains`). The first feature that takes curve chains stores it (the sweep, M2 item 18, wave 2). The shape goes to human review at the M2 gate with format version 3 (AGENTS.md Process, m2-plan.md gate 19, ADR 0061). It changes the public API of `partsmith-sketch` (the chain and union items, and two `SketchError` variants) and of `partsmith-features` (`BuildContext::chains`, its types, one error, one warning and `Noun::Curve`). The region union moves with no change in behavior. Wave 1 changes no protocol schema, naming algorithm, dependency or license. The protocol's wire form of a chain repair comes with the sweep's spec, as a protocol schema change for review at the gate.

## Context

- **Four features take curves that bound no region.** Sweep paths (M2 item 18, wave 2), ribs and webs (item 28, wave 3) and thin-wall extrude (item 29, wave 3) use lines and arcs of a sketch as a path or as an open profile. A sweep path or a thin wall can also be closed. M1 has no API for any of them. `build_profile` keeps closed regions only (sketch.md section 3.13.2): its step 6 removes dangling chains, and their open ends become `open_endpoint` findings. The sketch feature does not report those findings as warnings (features/sketch.md section 3.3 step 4). The plan changes the profile API once, before the four features depend on it (m2-plan.md section 2.1 item 3).
- **The union lives in the features crate.** At a3f4573, `crates/partsmith-features/src/profile.rs` builds the union of the regions a profile selects. `union` uses `half_edges`, `twins`, `successor`, the exact edge key `EdgeKey` and a union-find of its own, `Components`. `merge_pieces` merges the pieces of one entity with `continues`, `closes`, `ends`, `extend` and `whole_circle`. All of these read only `partsmith_sketch` types (`Region`, `ProfileLoop`, `ProfileEdge`, `ProfileCurve`). `ResolvedProfile::faces` then turns the loops into kernel curves (`planar_loop`, `tag`, `planar_curve`) and calls `make_profile`. features.md open issue 4 records why the union was put there: sketch.md section 1.2 listed a region-union helper as later work. The sketch crate already has a union-find whose sets are rooted at their lowest index, as those of `Components` are (`crates/partsmith-sketch/src/union_find.rs`).
- **What pins the union.** profile.rs holds 20 unit tests: 10 on `union`, 7 on `merge_pieces`, one each on `planar_curve` and `tag`, and `components_root_at_their_smallest_member`. `crates/partsmith-features/src/context/mod.rs` holds `profile_faces_of_a_region_with_a_hole` and `profile_faces_of_two_regions_are_their_union`. features/extrude.md tests 18 and 40 to 44 and features/revolve.md test 25 run in `crates/partsmith-recompute/tests/feature_extrude.rs` and `feature_revolve.rs` on the examples `extrude/union-of-regions`, `extrude/union-split-by-line`, `extrude/union-of-circle-halves`, `extrude/pieces-stay-separate`, `extrude/union-touching-itself`, `extrude/pieces-in-one-region` and `revolve/union-split-by-line`.
- **The union measured.** On 2026-11-07 the union code of a3f4573 was copied unchanged into a scratch crate that depends only on `partsmith-sketch`, then deleted. The code ran in a release build on the 4-core development container (load about 3), with 3 warm-ups and 21 timed runs as sketch.md section 5.4 times its scenarios. Three runs read medians of 0.735, 0.716 and 0.721 ms for the 722 regions of sketch.md's grid benchmark, and 0.364, 0.386 and 0.360 ms for the one region of its long outline. The 722 regions give one part with no hole and four outer edges. The grid's 361 cells alone give one part with 361 holes.
- **References in this project.** A stored reference is a semantic query plus a fingerprint, never an index (AGENTS.md invariants). A region is stored as its key, its fingerprint and its outline (`RegionRef`, sketch.md section 2.7). It is matched by the entities that bound it. The fingerprint decides only when no stored entity is left, as a reported guess ([ADR 0021](0021-resolve-references-by-meaning.md), [ADR 0022](0022-split-regions-keep-their-area.md)).

## Decision

1. **Curve chains in `partsmith-sketch`** (sketch.md sections 2.10, 3.18 and 4.5). A chain is a list of non-construction lines and arcs in order, each of which ends where the next one starts, within `PROFILE_TOLERANCE`. One circle alone is a chain too. A `ChainKey` names a chain by the ids of its entities in chain order, each with `~` when the chain runs against the entity's own direction: `e-1,~e-2,e-3`. It uses the entry grammar of region keys (spec README decision D8). It is not sorted and names each entity once. `build_chain` checks a key against the solved entities and orients its curves along the chain as `ProfileEdge`s, which share their junction points bitwise. It reports each junction with its turn angle. A junction is tangent when its turn is at most `ANGULAR_TOLERANCE` (1e-9 rad). A chain is closed when its last curve ends where its first starts. A chain that does not resolve gives a `ChainLoss`: entities that are no longer in the sketch, an entry that is not a line or an arc, construction geometry, a curve without length, two entries that do not meet, a junction where the chain turns back, or two entries that cross. The checks run in that order and the first that fails is reported.
2. **The stored reference** is `ChainRef { key, fp, closed }`. `fp` is the chain's start, end and length, written `s=<u>,<v>|e=<u>,<v>|l=<length>`. `closed` records that the picked chain was closed. It is omitted when false.
3. **Matching follows the key alone.** `match_chain` builds the stored key. A stored closed chain whose ends no longer meet is lost as two entries that do not meet. Connect the ends is its fix when those ends belong to different entities and lie at most `CONNECT_DISTANCE` apart. A stored open chain that the user closed is used closed. The fingerprint never chooses curves. It describes a lost chain in repairs and ghosts. `ChainMatch::Resolved` carries successions, always empty in wave 1. The ADR of M2 item 25 that amends ADR 0022 for the modify tools says how a chain follows a trimmed, split or extended entity.
4. **The chain a pick stands for.** `chain_through` extends a picked curve through every point where exactly two curve ends meet, in the picked curve's own direction. It stops at an open end and where three or more ends meet. A circle is a chain of its own. The engine calls it when a user picks a curve for a chain field. The protocol route comes with the first chain field (M2 items 18 and 32).
5. **A mirrored drawing.** `SketchParams::mirrored_chain` writes a chain reference for `mirrored()`: arcs and circles flip their `~`, lines keep it, the order is kept and the fingerprint's `v` values are negated (sketch.md section 3.17).
6. **The features side** (features.md sections 2.5, 2.6, 3.16 and 4). `ChainProfileRef { sketch, chains }` is the shared params type. `BuildContext::chains` resolves it into `ResolvedChains`. A lost chain among several is skipped with the warning `chain_missing`. When none is left, the error `chain_not_found` keeps every lost chain. An empty list is `EmptySelection` with the new `Noun::Curve`. The fixes are Connect the ends, Show and Pick, which hosts already run. `Repair::Chain { pointer, sketch, chain, loss }` is the contract of the chain repair. It lands with the sweep's spec, with its protocol wire form and the engine's projection (engine.md section 3.4). Until then `repairs()` gives none for chains.
7. **The consumers set their own behavior.** Whether a feature takes open chains, closed chains or several, and how it builds, names and words its result, is set by its own spec: the sweep (M2 item 18, wave 2), the rib and web (item 28, wave 3) and thin-wall extrude (features/extrude.md, item 29, wave 3). Their faces are named after `ProfileEdge::entity`, never after an edge's position.
8. **The region union moves** (sketch.md sections 2.11 and 3.19, features.md section 3.7). `union`, its helpers and `merge_pieces` with its helpers move from `crates/partsmith-features/src/profile.rs` into `partsmith-sketch` as the public `union_regions(regions) -> Result<Vec<UnionPart>, UnionError>`, with `UnionPart { outer, holes }` in place of the tuple. `Components` is replaced by the crate's `UnionFind`. `UnionError`'s text is the detail the features crate wrote before: `the selected profile regions do not form a planar arrangement`. `ProfileFaces`, `ResolvedProfile::faces`, `planar_loop`, `tag` and `planar_curve` stay in `partsmith-features`, which has the kernel. `faces` maps a `UnionError` to the same `Internal` error as before. The rules of features.md section 3.7's union paragraph move to sketch.md section 3.19 unchanged, with the algorithm the code runs written out. features.md section 3.7 keeps the kernel step and points there.
9. **What keeps pinning the union.** The 10 tests of `union` become sketch.md tests 289 to 298, with the same sketches and assertions, through `union_regions`. The 7 tests of `merge_pieces` move with it as unit tests, unchanged. The tests of `planar_curve` and `tag` stay in the features crate. `components_root_at_their_smallest_member` goes with `Components`. Its rule is pinned by `the_lowest_index_becomes_the_root` in `union_find.rs`. The two context tests, features/extrude.md tests 18 and 40 to 44, features/revolve.md test 25 and the seven examples stay as they are and pass unchanged. Every other test, example result and generated schema stays identical.
10. **Budgets** (sketch.md section 5.1). `union_regions` of the grid's 722 regions gets 0.87 ms and of the long outline 0.44 ms, by [ADR 0057](0057-budgets-set-from-the-measured-median-plus-20-percent.md)'s rule (the median of the three medians above plus 20 percent, rounded up to two significant digits). `build_chain` and `chain_through` on the long outline, a closed chain of 1000 lines, get a ceiling of 5 ms each. Wave 4's budget round sets those two rows again by ADR 0057's rule (m2-plan.md gate 10).

## Alternatives considered

Each choice is Accepted (owner's rule of 2026-11-05).

1. *How a stored chain names its curves.* The options: (a) the entity ids in chain order with their directions, plus a fingerprint; (b) the set of entity ids, with order and direction worked out from the geometry on each build; (c) one picked entity, extended again by `chain_through`'s rule on each build. The rule takes (a). Safest: the chain never grows when the user draws a new connected line, which (c) would do silently. It never changes direction on its own, which (b) could do when a junction moves. A missing curve is a reported loss. Most open-source: FreeCAD stores a sweep's spine as a sketch and a list of edges by index, which the invariants of this project forbid. Industry standard: Fusion stores the picked curves of a path. Chain selection there is an aid to picking. Option (c) lives on as the pick helper of decision 4.
2. *Construction geometry in chains.* The options: (a) non-construction curves only; (b) any line, arc or circle. The rule takes (a). Most open-source: FreeCAD leaves construction geometry out of a sketch's shape. A feature there cannot use it as a path. Safest: chains follow the same rule as profiles (sketch.md section 3.13.1), and construction geometry stays reference geometry. A curve that becomes construction geometry is a reported loss.
3. *What connects two entries.* The options: (a) their ends lie within `PROFILE_TOLERANCE`, as the arrangement joins vertices; (b) a coincident constraint joins them. The rule takes (a). Safest: a chain that looks connected is connected, and the result does not depend on how the drawing was constrained. Industry standard: kernels join wire edges by geometry. A solved coincidence holds within 1e-10 mm (sketch.md section 3.6.5), far inside the tolerance.
4. *Where a junction lies.* The options: (a) at the start of the edge that leaves it; (b) at the end of the edge that arrives; (c) at their midpoint. The rule takes (a), the recommendation. The chain's start stays the first entity's own point, also on a closed chain, and an open chain's end stays the last entity's own point. The arrangement snaps vertices the same way (sketch.md section 3.13.2 step 2): coordinates come from one entity and are never averaged. Edges that share a junction bitwise make a kernel wire without gaps.
5. *Chains that cross or turn back.* The options: (a) losses of the chain, checked in the sketch crate; (b) left to each consumer and its kernel calls. The rule takes (a). Safest: none of the four consumers can build along a curve that crosses itself or folds back. A check before the kernel names the curves and the point (the error guidelines, "Check before the kernel"). One message serves all four features.
6. *The tangent tolerance.* The options: (a) `ANGULAR_TOLERANCE`, 1e-9 rad, architecture.md's angular tolerance; (b) a looser angle such as 1e-6 rad. The rule takes (a), the project standard. A solved tangent with a touch point holds its direction within 1e-10 rad, since the row is scaled by at least 1 mm (sketch.md section 3.6.3).
7. *A closed chain that opens.* The options: (a) `closed` stored in the reference, and an opened chain is a loss; (b) the chain used as it now is, open; (c) closedness read from the stored fingerprint. The rule takes (a). Safest: a thin wall or a sweep built along a closed outline never turns open without a message. Option (c) would let the fingerprint decide, against ADR 0021. Closing a chain is the user's own act and keeps its use (decision 3).
8. *Matching after edits.* The options: (a) by the key alone in wave 1, with successions specified by the ADR of item 25; (b) replacements inferred now from the stored order, as region outlines infer them. The rule takes (a). Safest: no inferred guess before the modify tools that make replacements exist. Their ADR amends ADR 0022 for regions and chains together. The result type carries successions already. The API does not change again.
9. *The pick helper's rule.* The options: (a) through every point where exactly two curve ends meet; (b) through tangent junctions only; (c) no helper, every curve picked by hand. The rule takes (a), the industry standard: CAD tools extend a picked curve to the curves connected to it. A bent path or the outline of a thin wall is one pick, and the user sees the chain before it is stored. A tangent-only option can follow in the UI.
10. *The features-side type.* The options: (a) one shared `ChainProfileRef` with a list, as `ProfileRef` holds regions; (b) a type per feature. The rule takes (a). One resolver, one pair of messages and one repair serve all four consumers. A list entry that is lost is skipped with a warning and the rest still builds (the error guidelines, "Skip instead of failing").
11. *The union's API.* The options: (a) `union_regions` returns parts of `ProfileLoop`s, and the kernel step stays in the features crate; (b) the whole of `ResolvedProfile::faces` moves; (c) the union stays where it is. The rule takes (a). The sketch crate has no kernel (architecture.md). Option (b) cannot work. Option (c) leaves 2D profile code outside the crate that owns profiles. The plan's item 3 moves it.
12. *The union-find.* The options: (a) the crate's `UnionFind`; (b) `Components` moved as it is. The rule takes (a), the recommendation (engineering principles 5 and 6). Both root a set at its lowest index. The union's components and their order do not change.
13. *Budgets for code that does not exist yet.* The options: (a) a ceiling now, set again in wave 4; (b) no row until wave 4. The rule takes (a). Safest: a pick on a long polyline stays well inside a frame from the first build. 5 ms is under a third of the 16 ms frame budget of sketch.md section 5.1.
14. *The JSON member of `NotCurve`'s kind (2026-11-08, found by the track's tests).* `ChainLoss` is tagged with `kind` in JSON, and serde refuses a variant field of the same name. The options: (a) write the field as `entity_kind` in JSON; (b) rename the field, for example to `found`; (c) tag `ChainLoss` with `type`. The rule takes (a), the safest. The Rust API, the details of sketch.md section 4.4 and the `kind` tag that `RegionLoss` uses stay as they are. Neither a document nor the protocol carries a `ChainLoss` (sketch.md section 2.10, test 288).
15. *When Turn the drawing back rewrites chains (2026-11-08).* The options: (a) build the engine rewrite of a `ChainProfileRef` in wave 1; (b) build `mirrored_chain` with its sketch tests now and the engine rewrite with the sweep (M2 item 18, wave 2), whose spec adds its test. The rule takes (b), the safest. No wave 1 feature stores a chain profile. A wave 1 rewrite would have no user and no test (engine.md section 3.22).
16. *Where a chain keeps its end tangents (2026-11-08, found while building the track).* `start_tangent()` and `end_tangent()` give the tangents of sketch.md section 3.18.2 step 5, taken on the entities' own geometry. An edge's end moves to the next entry's start, up to `PROFILE_TOLERANCE` away. The options: (a) two private fields that `build_chain` sets, which the chain's JSON writes as `start_tangent` and `end_tangent`; (b) tangents read from the first and last edges; (c) two more public fields. The rule takes (a), the safest. With (b), a line whose end moved gives a tangent that is off by up to `PROFILE_TOLERANCE` divided by the line's length, in radians. The public fields stay as sketch.md section 2.10 lists them, and neither a document nor the protocol carries a `Chain`.
17. *Equal keys in one chain list (2026-11-08, found while building the track).* features.md section 3.16 uses two entries with equal keys once. An entry stored closed can be lost while a later entry with the same key, stored open, resolves. The options: (a) an entry is left out when a chain that resolved earlier in the list has its key; (b) an entry is left out when any earlier entry has its key. The rule takes (a), the safest. The lost entry keeps its `ChainMissing` warning, and the chain that resolved is still used. With (b), the list could resolve to no chain at all. features.md sections 2.6 and 3.16 say (a).
