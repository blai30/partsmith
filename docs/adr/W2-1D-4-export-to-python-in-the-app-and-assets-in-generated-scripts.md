# W2-1D-4: Export to Python in the app, and assets in generated scripts

Status: Accepted (owner's rule of 2026-11-05): the M2 plan's item 23 and python-api.md open issue 4, with the choices below. It extends [ADR 0048](0048-python-keywords-gui-round-trip-and-python-budgets.md) decision 2 to the scripts the UI writes and to a document with an import. Decision 3 changes the code generation rules (python-api.md 3.8) and the round trip's scope (3.9): generated code for a document that reads assets adds them from the `assets` folder beside the script. That change goes to human review at the M2 gate (m2-plan.md gate 19 and the spec round's decision 12). Decision 2 widens what the desktop's `allow-pick-save-file` reaches (desktop.md 8). No file format, protocol, naming, license or dependency change. No public Python name is added: generated code calls the existing `Document.add_asset` and the standard library's `pathlib.Path`.

## Context

- **What exists** (read at 0f578c1). The engine's `export_python` returns python-api.md 3.8's script for the current recipe, uncommitted edits included, and never fails for a recipe that loads (engine.md 3.16; `crates/partsmith-engine/src/python.rs`). Protocol command 29 carries it. `partsmith export --format py` writes it with the media type `text/x-python` (cli.md 3.4). The UI has no command for it (ui.md 1.2, "Python export UI"), and `FileKind` has no `py` (`ui/src/files/file-service.ts`; `desktop/src-tauri/src/files.rs`).
- **The success criterion.** Technical design section 1: every GUI-built model exports to Python that rebuilds the identical shape. m2-plan.md gate 4: the UI's Export to Python does it for the four parts.
- **Imports in scripts.** The import record has no dedicated Python form, since a script cannot carry the file's bytes (features/import.md, Python). Generated code writes the generic `feature("import", ..., asset="<name>", ...)` and fails with `asset_missing` in a fresh document. [ADR 0064](0064-assets-added-to-an-open-document-and-named-by-the-core.md) gave Python `Document.add_asset(path)`, and python-api.md open issue 4 left "where generated code finds the bytes" to item 33. So round trips and Python twins leave out every document with an import (python-api.md 3.9; delivery.md 2.8). [ADR W2-1D-2](W2-1D-2-step-import-in-the-ui-and-the-cli-through-import-step.md) makes such documents common in the UI.
- **Where the bytes are.** Every host writes a document's assets to the `assets` folder beside it (file-format.md 3.11). `run_code` sets `__file__` to its `filename`, and `run_script` passes the script's path (python-api.md 3.12). CadQuery and build123d scripts load STEP files by a path relative to the script.

## Decision

1. **The command.** `file.export_python`, "Export to Python...", in the Document menu after "Export..." and in the palette, category File, no toolbar entry and no shortcut. Description: "Saves this model as a Python script that rebuilds it." Keywords: Python, script, code, CadQuery, build123d. While a feature command or a sketch session is open it is disabled with `finish_command_first`, as Export is (ui.md 3.18 rule 1), so the script never holds a preview. It asks where to save first (`chooseSaveTarget('{name}.py', 'py')`), then calls `CoreApi.exportPython` (command 29, an `other` task of the mutation queue), then writes the code as UTF-8. When features have status `error`, the script is still saved, and a warning says which (`python_failed_features`, ui.md 4.3): their code is in the script, and running it raises `FeatureError` at the first. When the document reads assets, the info notification `python_saved_assets` says that the script reads them from the `assets` folder beside it, so it belongs in the document's folder (desktop.md open issue 15).
2. **A `py` file kind.** `py` "Python script", `text/x-python`, `.py`, in ui.md's `FILE_TYPES` and the desktop's `FileKind` (desktop.md 2.4). The media type is the CLI's (cli.md 3.4).
3. **Assets in generated code.** When valid records of the recipe read assets, the script imports `Path` from `pathlib` and adds each asset after the document line, in name order: `doc.add_asset(Path(__file__).parent / "assets" / "<name>")`. Run as a file, the script reads the `assets` folder beside it. Run with `run_code` and no file name, it reads `assets` in the working directory. A missing file raises `FileNotFoundError` with its path, before any record names it. The records keep their stored form. A document without assets gets the same script as before.
4. **Round trips with imports.** python-api.md 3.9's first form holds for documents with imports, run with a file name beside the document's `assets` folder. An example with an import qualifies for a Python twin once its features build (delivery.md 2.8).
5. **How gate 4 is tested.** E-160 also exports each GUI document it writes to Python through the command and writes the `.py` beside it in `ui/e2e/fixtures/gui/`, blessed with the document. `python/tests/test_gui_documents.py` runs the committed script: it makes one document whose text is the committed `.ptsm` byte for byte, and whose features and bodies match it (delivery.md 2.8, test 71). Wave 5 adds the four parts (m2-plan.md gate 4).

## Alternatives considered

1. *Placement.* (i) a command in the Document menu and the palette; (ii) a "Python" format in the export popover; (iii) both; (iv) wait for M4's code panel. The rule takes (i). The export popover exports bodies with a printer orientation, and a script has neither, so (ii) would hide half its controls. (iv) misses gate 4.
2. *File kind.* (i) a `py` kind; (ii) plain text with no kind. The rule takes (i): the save dialog filters `.py` files, and the desktop dialog names the kind.
3. *Failed and uncommitted features.* (i) disabled during a command, saved with a warning when features failed; (ii) export the preview; (iii) export silently. The rule takes (i), the precedent of ui.md 3.18 rule 1 for an export.
4. *Imports in generated scripts.* (i) export with a warning; (ii) disable the command; (iii) generated code adds the asset from the assets folder beside the script; (iv) embed the bytes in the script. The rule takes (iii). Every GUI model then exports to a script that rebuilds (technical design section 1), and `Path(__file__).parent` is how Python scripts find their data files. (iv) puts megabytes of base64 in a script meant to be read. (i) and (ii) break the success criterion for every imported part. The plan's reason said a missing folder fails with `asset_missing`'s message. `add_asset` raises `FileNotFoundError` naming the path it looked at instead, Python's own error for a missing file, which says more.
5. *Gate 4's test.* (i) the UI's `.py` written beside E-160's documents for pytest; (ii) an E-test that compares the download with the core's `export_python`; (iii) wave 5 alone. The rule takes (i), ADR 0048 decision 2's pattern: the script the UI saved runs in real Python.

## Consequences

- A script with assets has a second import line, `from pathlib import Path`. A script without assets is byte for byte what M1 generated, so every existing twin and engine test holds.
- `examples/import/` gets Python twins for the examples whose features build, written by the Python bless (delivery.md 2.8).
- The scripts the UI writes join the fixtures the e2e bless writes.
- A user who moves a script without its `assets` folder gets `FileNotFoundError` naming the path.
