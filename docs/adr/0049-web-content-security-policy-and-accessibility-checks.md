# 0049: The web build sends a content security policy and two hardening headers, and keyboard and target size are tested without axe

Status: Proposed, needs human review: decision 1 is the security review of gap list item UI-2, since it changes what the deployed web app may load and run. Decisions 2 and 3 settle gap list item UI-3 without a dependency (no axe), which needs no gate; decision 3 also widens and bounds the scope of ui.md 3.24's target size rule, a design-system matter the owner may change with options 3(b) to 3(d). No file format, protocol, license, dependency or desktop capability change.

## Context

- **The web build had no policy.** `ui/public/_headers` set only `Cross-Origin-Opener-Policy` and `Cross-Origin-Embedder-Policy` (delivery.md 2.7), while the desktop has a strict content security policy and a dev policy (desktop.md 2.8). Cloudflare Pages adds `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin` and `Access-Control-Allow-Origin: *` to every response by default, and a header named in `_headers` replaces its default (Cloudflare's Pages documentation, "Serving Pages" and "Headers", read 2026-10-30). `pnpm dev` and `pnpm preview`, against which the E-tests run, sent neither a policy nor those two headers.
- **What the web app loads** (read from the tree and the build on 2026-10-30): its own HTML, scripts, stylesheet and fonts (ADR 0031); the core worker `assets/core.worker-*.js`, a same-origin module worker, which imports `core/partsmith_core.mjs` and fetches and compiles `core/partsmith_core.wasm` with `WebAssembly.instantiateStreaming`; the sketch overlay's chunk through `import()`. No `data:` URL is in the build's CSS or JavaScript, no source names another origin, and the UI links nowhere. Element styles are set through the CSSOM (`element.style`) for the runtime positions of ui.md 3.12. Downloads are object URLs clicked through an `<a download>`.
- **Measured in Chromium** (the installed Playwright Chromium, a scratch preview of the current build sending the headers of decision 1): with the policy, opening `cube.ptsm`, entering and leaving its sketch, a print check, the dark theme and the Parameters panel raised no `securitypolicyviolation` in the page or in the core worker, while an `img` from another origin and a `fetch` to another origin from the worker each raised one, so both enforce the policy; E-161 as written passed against a scratch server that sent the policy and failed against one that did not. Without `'wasm-unsafe-eval'` the core did not load ("Refused to compile or instantiate WebAssembly module because 'unsafe-eval' is not an allowed source of script"). The 225 E-tests that do not check Playwright's projects passed against that preview (E-156 checks the repository's own configuration, which the scratch run did not use); that run left out the `@visual` and `@perf` tests, as `pnpm e2e` does, and the test pages of `viewport.spec.ts`, P-12 and the engine page came from a dev server without a policy. Playwright applies a screenshot's `stylePath` as a `<style>` element, which `style-src 'self'` refuses (one `style-src-elem` violation, and the style not applied), so the visual tests' `visual.css` stops hiding the rebuild time under the policy; with `bypassCSP` the style applied and nothing was refused. The test reaches the core worker only after it started, so a `securitypolicyviolation` listener installed there misses a refusal during its startup that does not stop the core (a refused `fetch` put at the top of the worker's script, routed in a scratch copy of E-161, which then passed), and Playwright's `console` events carry no policy message; a `ReportingObserver` made with `buffered: true` is also given the reports made before it existed, in the worker and in the page, and reported that refusal. With a check of the page's buffered reports at the end of every E-test, a scratch run of the whole Chromium suite found none but E-161's two refusals on purpose.
- **The dev server.** Under the production policy the dev page never renders, since `@vitejs/plugin-react` puts its Fast Refresh preamble in an inline script and Vite inserts stylesheets as `<style>` elements; with `'unsafe-inline'` added to `script-src` and `style-src` the app ran and its HMR socket connected under `connect-src 'self'`. The same server serves the desktop's dev window: `cargo tauri dev` loads `http://localhost:5173` directly, because Tauri 2.12.3 proxies the dev server only on mobile (`PROXY_DEV_SERVER = cfg!(all(dev, mobile))` in `tauri/src/manager/webview.rs`) and adds a policy only to the pages it serves itself, so `devCsp` never reaches that window and a policy sent by Vite would be the only one there; its `connect-src 'self'` would refuse Tauri's IPC (`ipc:`, `http://ipc.localhost`), which then falls back to `postMessage` with console errors.
- **Keyboard and targets, measured on `cube.ptsm` at 1280 by 720** in the same preview: Tab follows ui.md 3.24's regions, with stops 3.24 did not list (Toggle browser first in the top bar, the timeline's collapse button before its strip, the sketch overlay's constraint glyphs and dimension labels after the 3D view in sketch mode), and the selection inspector's stops are Clear selection, the body's color, its material input, its Visible switch and the suggestions Move body, Mirror and Split body. Opening a command's inspector from the timeline moved focus into it, and Escape gave it back to the timeline item; closing the Parameters panel from inside gave focus back to its opener. Two returns dropped focus to `document.body`, against 3.24's rule that focus never drops to the page: dismissing a notification with the keyboard, and Escape in a command started from a suggestion of the selection inspector, whose button goes with the selection the command takes (ui.md 3.7 step 4). Every visible button, input, select and element with a control role (`button`, `slider`, `treeitem`, `option`, `menuitem`, `menuitemradio`, `menuitemcheckbox`), an input measured with its labels, was at least 24 by 24 CSS pixels in fifteen states (the menus, popovers, inspector, sketch, print and Problems panel of E-163), except the browser row's color swatch ("Color of Cube", 16 by 16, `size-4`), the Problems panel's feature label ("Fillet 1", 41.69 by 20, a text button) and the timeline's rollback marker (8 by 40, the `w-2` handle of ui.md 3.9, a pointer target whose function "Roll back to here" and the marker's keys also give). The view cube's cells, sized in the plane of their face, measured as little as 16 by 28 pixels on screen at the home view and about 1 pixel for faces seen edge on; constraint glyphs measured 18 by 18 and dimension labels 18 high, as ui.md 3.16.2 sets them; repair candidate markers are `size-5`.

## Decision

1. **Five response headers in production and the preview, and no policy on the dev server.** `ui/public/_headers` holds, for `/*`, the two isolation headers, `Content-Security-Policy: default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; font-src 'self'; img-src 'self'; connect-src 'self'; worker-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`, `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer`. The policy is the desktop's with four changes: `'wasm-unsafe-eval'` for the core's compile (which allows no JavaScript `eval`), `worker-src 'self'` for the core worker, `connect-src 'self'` in place of the IPC sources, and `img-src` without `data:`, which nothing loads. No source names a host, and the Cloudflare features that inject scripts (Web Analytics' automatic beacon, Rocket Loader, Zaraz, Email Obfuscation) stay off. `EXPECTED_HEADERS` of `check:dist` pins the file (delivery.md 2.6, test 14), with the messages of delivery.md section 4 reworded for the five headers. The Vite plugin, renamed `webHeaders`, reads `public/_headers` when the configuration loads and sends its headers on every response: all five on `pnpm preview`, and on `pnpm dev` all but `Content-Security-Policy` (option (h)), since the dev page needs inline script and style and the same server serves the desktop's dev window, where a dev policy would be the only one and would refuse Tauri's IPC (test 65 reads the file and checks both, 304s included). The visual tests run with Playwright's `bypassCSP`, the one way their screenshot style applies under the policy. E-161 checks in Chromium that the page and the core worker report no violation from their start (a `ReportingObserver` made with `buffered`, `reportedViolations` of ui.md 6.3, which also gives the reports made before the test reaches the worker) and that both enforce the policy, and every other E-test imports a `test` from `e2e/helpers.ts` whose `page` fails a test that ends with a violation reported in the page, so the states all the E-tests visit are checked. Spec: delivery.md 1.1, 2.1, 2.6, 2.7, section 4, tests 14 and 65, open issue 19 and section 8; ui.md 6.5 (E-161) and 6.6; desktop.md 2.8 and open issue 5.
2. **Keyboard: E-162, the exact tab order, and two focus returns.** ui.md 3.24 lists every stop the app has (Toggle browser, the timeline's collapse and problems buttons, the sketch overlay's glyphs and labels after the 3D view in sketch mode) and says that the selection inspector, which follows the selection, leaves focus where the selection was made. Two product changes keep focus off the page: a notification that goes away with focus inside it, when nothing else took focus, gives it to the 3D view, as a closed side panel whose opener is gone does (ui.md 3.22 and 3.24, U-238); and a command's inspector that closes when the control that had focus before it is gone gives focus to the 3D view (ui.md 3.24, U-239). E-162 walks the regions on `cube.ptsm` forward and back and checks the focus returns of the side panel, the notification and a command's inspector, both to the timeline item and to the 3D view, and the top-center slot in sketch mode.
3. **Targets: E-163 without axe, two targets enlarged, and the marks left out.** E-163 measures every rendered button, input, select, textarea and element with a control role at 1280 by 720 and scale 1 in fifteen states (the empty document; a selection with the Parameters panel, a draft parameter and an error notification; the Document menu; the export popover; the palette; the color popover; the Units and printer menus; the timeline item menu; the viewport menu; the section popover; a command's inspector with More; sketch context; print context; and the Problems panel with an inspector's error banner), a form control by the box that holds it and its labels. The browser row's swatch becomes a `size-6 -m-1` button showing a bordered `size-4` square (ui.md 3.10), 24 by 24 like the row's other buttons while the row keeps its layout, and the Problems panel's feature label a `min-h-6 min-w-6 -my-0.5` button, 24 pixels high in the 20 pixels of its line, so its row keeps its layout and the label stays level with its status icon (ui.md 3.9). 3.24 states which marks keep their own sizes and E-163 leaves them out: the view cube's cells (sized in their face's plane, 3.14; the face views and the iso view are also commands), the repair candidate markers (pointer-only repeats of the banner's buttons), the sketch's constraint glyphs and dimension labels (3.16.2, ui.md open issue 42) and the timeline's rollback marker (3.9; WCAG 2.2's equivalent exception, open issue 42). No axe dependency is added.

## Options the owner can still pick

For decision 1:

- (a) **The five headers, enforced** (chosen).
- (b) **Report only first** (`Content-Security-Policy-Report-Only` for a release, then the enforcing header): needs an endpoint to collect the reports, a Pages Function or a third-party service, which the app has none of.
- (c) **A `Permissions-Policy`** turning off what the app never uses (camera, microphone, geolocation, payment and others): one more line; the browser already asks the user before any of them.
- (d) **Trusted Types** (`require-trusted-types-for 'script'`): the app's own code writes no HTML strings into the DOM (no `innerHTML`, `insertAdjacentHTML` or `dangerouslySetInnerHTML` in `ui/src` outside tests), but the policy would hold every library to that too, and the minimum Firefox and Safari of ui.md 1.1 do not enforce it, so it would protect Chromium users only.
- (e) **`X-Frame-Options: DENY`** beside `frame-ancestors 'none'`: only browsers older than ui.md 1.1's minimums need it.
- (f) **`Cross-Origin-Resource-Policy: same-origin`, and removing Pages' `Access-Control-Allow-Origin: *`** (a `! Access-Control-Allow-Origin` line in `_headers`): keeps other sites from embedding or reading the build's files, which are public and open source anyway; the removal also needs a check that Pages accepts it on every response.
- (g) **`Referrer-Policy: strict-origin-when-cross-origin`**, Pages' default, in place of `no-referrer`: no difference while the app requests and links nothing elsewhere.
- (h) **No policy on the dev server** (chosen): the least code, and the desktop's dev window keeps Tauri's IPC; dev runs and the e2e test pages then show a load from elsewhere only when CI's preview does.
- (i) **The desktop's `img-src` without `data:`**: nothing loads a `data:` image there either; it is a desktop policy change (desktop.md 2.8) and is left to that spec.
- (j) **`Strict-Transport-Security`**: `pages.dev` is already on browsers' preload list; a custom domain gets it from its Cloudflare zone settings, not from `_headers`.
- (k) **A dev policy**: the production policy with `'unsafe-inline'` added to `script-src` and `style-src`, as the desktop's `devCsp` does, and `ipc: http://ipc.localhost` added to `connect-src`, since it would also be the policy of `cargo tauri dev`; it shows a load from elsewhere in dev runs and on the test pages, at the cost of a second policy that `webHeaders` derives from the file and test 65 writes out.

For decision 2:

- (a) **The 3D view** (chosen) for a notification that goes away with focus inside it, as for a side panel whose opener is gone.
- (b) **The next notification**: focus goes to the first button of the nearest notification that remains, and to the 3D view only when none remains, so a keyboard user who clears several errors does not go back through every region for each; a few more lines in `Notifications.tsx` and one more case in U-238.

For decision 3:

- (a) **The marks keep their sizes** (chosen): no layout change; the sketch's glyphs and labels stay under WCAG 2.2's 24-pixel minimum, and stacked glyphs also fail its spacing exception.
- (b) **24-pixel targets for glyphs and dimension labels**: a `size-6` button around each unchanged chip (labels `min-h-6`), and glyphs stacked 24 pixels apart instead of 20 (`GLYPH_STACK_PIXELS` in `src/sketch/screen.ts`), so stacked targets do not overlap; changes ui.md 3.16.2, the overlay's layout and its tests, then E-163 measures the marks as well.
- (c) **A `w-6` rollback marker**: a 24-pixel handle around the unchanged `w-0.5` line, which widens every gap of the timeline strip by 16 pixels; changes ui.md 3.9 and the timeline's layout tests, then E-163 measures the marker.
- (d) **Axe** (`@axe-core/playwright` as a development dependency, MPL-2.0, with an ADR row): its WCAG rules, the target size rule with its spacing exception among them, would run in the E-tests. It adds a dependency for human review and checks less of the tab order than E-162.

## Consequences

- Every E-test that opens the app runs under the production policy, since the preview sends it, and ends by checking that its page reported no violation, so a change that loads or runs something the policy refuses in a state any E-test visits fails that test; a refusal in the core worker fails E-161, or any test when it stops the core. The visual tests send no policy (`bypassCSP`), and neither do the test pages a dev server serves. `ui/AGENTS.md` states what the policy refuses. A feature that needs another origin (remote help, analytics, a CDN) changes `ui/public/_headers`, `EXPECTED_HEADERS` and test 14 together, with delivery.md 2.7 and a new ADR that supersedes decision 1 of this one (delivery.md 2.7).
- `_headers` grows from 90 to 409 bytes; its longest line is 253 characters, under Pages' 2,000.
- Firefox and WebKit run the `@engines` E-tests under the same preview in the platforms workflow, so a refused core, chunk or stylesheet there fails them, but E-161 runs in Chromium alone, the deployed headers were not read from Pages, and the performance tests have not run under the policy (delivery.md open issue 19, a human check).
- Neither enlarged target moves its row: the swatch takes the 16 pixels of a row icon and the feature label the 20 pixels of its line, so no baseline of ui.md 6.6 changes for them (a screenshot of the Problems panel on `fillet-error.ptsm` in Chromium was byte for byte the one taken before ADR 0049, measured 2026-10-30).
- Reverting decision 1 is restoring the two-line `_headers`, `EXPECTED_HEADERS`, the messages, the plugin, test 65 and the visual tests' `bypassCSP`, and removing E-161 and the check of `test` in `e2e/helpers.ts`. Reverting decision 2's product changes removes the notification's focus handling and the inspector's fallback with U-238, U-239 and E-162's two steps; decision 3's two enlarged targets are one class list each.
