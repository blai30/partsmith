# 0063: Cancel through a host flag outside the session

Status: Accepted (owner's rule of 2026-11-05): the M2 plan's choice 20, option (a), with option (b) as the web fallback of the section Fallback below, and the choices below. It changes the protocol schema (the feature state `not_run`, the error code `canceled` and command 37, `rebuild`) and the desktop host (the host command `cancel_call` with its permission `allow-cancel-call` in `capabilities/main.json` and its entry in the app command manifest). Both go to human review at the M2 gate (AGENTS.md Process, m2-plan.md gate 19). No file format, naming, license or dependency change. `PROTOCOL_VERSION` stays 1 (ADR 0024's additive rule).

## Context

- **A token nobody sets.** partsmith-features defines `CancelToken` (`crates/partsmith-features/src/context/mod.rs`, an `Arc<AtomicBool>`). partsmith-recompute checks it before each active feature (`crates/partsmith-recompute/src/run.rs`) and reports `Status::NotRun` with `Report::canceled`. Built-in features check it between kernel steps (`builtin/common.rs` `check_canceled`, patterns, holes, dress-up). The engine always passes a new token (`CancelToken::new()` in `crates/partsmith-engine/src/state.rs`, `validate.rs` and `datum_base.rs`). `status.rs` maps `NotRun` to `rolled_back`, since it never occurs.
- **The kernel has no progress hook.** No facade call of partsmith-occt-sys passes a `Message_ProgressRange` to OCCT at a3f4573. A boolean, a fillet or a STEP read runs to its end.
- **A protocol command cannot reach a running call.** The web worker is blocked in `ps_call` and handles no message until it returns (protocol.md section 2.11). The core has no second thread: `crates/partsmith-wasm/build.rs` links it without `-pthread` or shared memory. On the desktop, `Host::call` holds the `Session` mutex for the whole call (`desktop/src-tauri/src/host.rs`, desktop.md open issue 9).
- **What M1 does.** The web stops a call that has run for 10 s by terminating its worker. The undo history and the caches are lost, and the edits of an open command are dropped (ui.md section 4.4, open issue 30). The desktop can only wait or quit.
- **Slow features arrive.** Modeled threads, sweeps and embossed text run far longer than M1's features. Technical design section 14 makes previews cancellable: "If the user changes a value again before the preview finishes, the old job is dropped."
- **The page can share memory with the worker.** The deployment sends `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` (`ui/public/_headers`), and the dev server sends the same headers (`ui/vite.config.ts`). A cross-origin isolated page can post a `SharedArrayBuffer` to its worker, and either side can read it while the other runs.
- **The plan settled the route.** Choice 20 picked option (a). OCCT's progress indicator and the engine's `CancelToken` are polled against a flag the host holds outside the session. On the desktop the flag is an atomic that a new host command sets without the `Session` mutex. On the web it is a word of a `SharedArrayBuffer` that partsmith-occt-sys reads through an Emscripten JavaScript import. Option (a) puts only the `not_run` status in the protocol. Choice 20 rejected (b), the worker restart, except as the web fallback, and (c), a cancel between features only. Choice 20's "only `not_run`" is about the route: no protocol command reaches a running call. The error code `canceled` and the command `rebuild` are not part of that route. They answer what a stop leaves behind: a command with no partial result, and a document that is not fully built. Choices 3 and 4 below settle them under the owner's rule. They go to the gate's review beside `not_run`, as the Status says.

## Decision

1. **The flag names a request** (engine.md section 3.26). A host's flag holds the id of the request to stop, or 0. `CancelFlag` of partsmith-engine is `never()` (the default), `word()` (an `Arc<AtomicU64>` that `cancel(request)` sets, for the desktop and native tests) or `page()` (the web page's word, on `wasm32-unknown-emscripten` only). `SessionOptions` gains `cancel: CancelFlag`. While `execute` handles request `N` (N at least 1), every check asks whether the flag holds `N`. Typed methods called directly never stop.
2. **Where a request stops.** Recompute stops before an active feature (recompute.md section 3.5 step 2), at a build's own checks (`BuildContext::is_canceled`) and inside the kernel calls that poll OCCT's progress range (kernel.md, by handoff). `export` stops before each body, inside its tessellation and inside its STEP write. partsmith-io passes the request's interrupt to the kernel's STEP writer and reader (io.md, by handoff). `import_step` stops before and inside its STEP read, before any edit, and in the recompute of its edit like any other request. `analyze_print` stops before each body and inside the tessellation of a body's mesh. The display tessellation never stops. No other command checks.
3. **What a cancel keeps** (engine.md section 3.26). A recompute that stops leaves the request's edits applied exactly as an uncanceled request would: the document, its revision, the dirty state, the undo and redo stacks, the transaction, the focus and the drag states. The features from the one that was stopped on report `not_run`, with no messages. The response is the command's usual result. `export` and `analyze_print`, and an `import_step` stopped before its edit, answer the error `canceled` and change nothing. An `import_step` stopped in its recompute keeps its edit, as any stopped recompute does.
4. **The result cache** (recompute.md section 3.7). A canceled run caches the results of the features that finished, caches nothing for the build that stopped, and evicts nothing.
5. **An incomplete document.** A document whose latest recompute was canceled is incomplete. `rebuild` (command 37, `{doc}`, result `{}`) recomputes it with its recipe, focus and profile and changes nothing else. `export` and `analyze_print` rebuild an incomplete document first. Every other command, `measure` included, reads the states the latest recompute left, as the viewport shows them. When that first rebuild stops, or the command stops after it, the command fails with `canceled` and keeps only the results the rebuild cached.
6. **The desktop** (desktop.md sections 2.2, 2.6 and 2.9). The ninth host command, `cancel_call { request: u64 }`, calls `Host::cancel(request)`, which stores the id in the host's `CancelFlag::word()` without taking the `Session` mutex. `COMMAND_NAMES` gains `cancel_call` after `set_unsaved`. `tauri-build` generates `permissions/autogenerated/cancel_call.toml` from the app command manifest, and `capabilities/main.json` grants `allow-cancel-call`.
7. **The web** (protocol.md sections 2.10 and 2.11). When `globalThis.crossOriginIsolated` is true, the worker transport makes an 8-byte `SharedArrayBuffer` and posts it to the worker as `{ type: 'cancel_word', word }` before any call. The worker host gives the module a `BigInt64Array` of length 1 over it as `Module.partsmithCancelWord`. The page stores the id of the request to stop with `Atomics.store` and clears it with `Atomics.compareExchange` once that request's response arrives. The worker and the core only read it. partsmith-occt-sys defines the import `partsmith_cancel_word` with `EM_JS` in its shim. The import returns the word as a double. partsmith-occt-sys reads it through the C++ function `page_cancel_word` and compares the value with the request id in Rust (kernel.md section 3.13 item 7). partsmith-wasm's `session_options()` gives the module's session `CancelFlag::page()`. The module keeps its three exports, `-sEXPORTED_FUNCTIONS` is unchanged, and the core is still built without shared memory.
8. **The UI** (ui.md sections 2.4, 2.5, 3.7, 3.9, 3.21 and 4.4). A Stop button beside "Rebuilding" in the status bar stops the oldest request with no response. A newer preview value stops the preview in flight. Esc on an open feature command stops its preview before `cancel_transaction`. The still-working panel offers Stop first. A `not_run` feature shows as not built, and a notification offers Rebuild.
9. **Python and the CLI** (python-api.md and cli.md). Their sessions keep `CancelFlag::never()`. They offer no stop. Ctrl+C behaves as in M1.
10. **Budget** (engine.md section 5). From the cancel to the response, a request that stops at a check answers within 200 ms on the desktop and 600 ms on the web. The engine's two rows measure it during `open_document` of the reference part: with the cancel 100 ms in, and late in it, when the display meshes of nearly every body remain to be made. ui.md's P-13 measures the web Stop from the page. Other requests are bounded by kernel.md's longest gap between two polls. The specs of waves 2 to 4 add rows for the modeled-thread preview, the sweep and the emboss (gate 11).

## Fallback

If the review at the gate rejects the `SharedArrayBuffer` word (m2-plan.md risk 9), the worker transport posts no `cancel_word` and its `cancel` returns false. The web then stops a call as in M1: the still-working panel offers "Stop and restart core", which terminates the worker and loses the undo history (ui.md section 4.4). A preview superseded by a newer value runs to its end. The desktop keeps its cancel between features and inside polling calls, with the undo history. The same applies to a page that is not cross-origin isolated. Options: (i) this fallback; (ii) a cancel only between requests on the web, which stops nothing that runs; (iii) a protocol cancel command, which cannot reach a running call. The rule takes (i), the safest: the user always has a way out, and nothing else changes. Accepted (owner's rule of 2026-11-05). It takes effect only on that review's rejection.

## Alternatives considered

The plan settled the route (choice 20). The spec met eight choices the plan leaves open. The owner's rule settles each: the most open-source approach, the safest, the industry standard and the recommendation of this work. Every option is open source, and the first criterion picks none of them.

1. *What the flag holds.* Options: (i) the id of the request to stop; (ii) a boolean that stays set until the next request clears it; (iii) a counter of stops. The rule takes (i), the safest. A Stop that arrives after its request ended can never stop a later one. With (ii) and (iii), a late Stop stops the next request, which may be a commit or a `cancel_transaction`.
2. *What a stopped recompute does with the request's edits.* Options: (i) keep them, report the features not built as `not_run` and record the undo entry; (ii) revert the request as if it had failed. The rule takes (i), the industry standard: SolidWorks and Fusion keep the change and mark the model as not rebuilt. It is also the safest: nothing the user typed is lost, and Undo still works. Option (ii) would turn a Stop into a hidden undo.
3. *Commands with no partial result.* Options: (i) `export`, `import_step` and `analyze_print` answer a new error `canceled` and change nothing; (ii) they never stop. The rule takes (i), the safest: an export of a large part has a way out, and no partial file is written.
4. *How the rest gets built.* Options: (i) a `rebuild` command, with the commands that make an output rebuilding first; (ii) only the next edit rebuilds; (iii) every later command rebuilds first. The rule takes (i), the industry standard: Fusion's Compute All, FreeCAD's Recompute and SolidWorks's Rebuild. It is also the safest: no file is exported and no check runs on a model that is not fully built. Option (iii) would restart a long build behind a hover's `list_elements`.
5. *The cache after a cancel.* Options: (i) keep what finished and evict nothing; (ii) evict as after any run; (iii) drop what the canceled run added. The rule takes (i), the recommendation of this work: the next run reuses every result it had before the stop.
6. *The web word.* Options: (i) 8 bytes viewed as a `BigInt64Array` holding the request id; (ii) 4 bytes holding the low 32 bits of the id; (iii) a stop counter. The rule takes (i), the safest: it holds every id up to `Number.MAX_SAFE_INTEGER` exactly. `Atomics` works on `BigInt64Array` in every engine ui.md 1.1 supports (ECMAScript 2020).
7. *Where the JavaScript import lives.* Options: (i) an `EM_JS` function in partsmith-occt-sys's shim; (ii) a `--js-library` file that `crates/partsmith-wasm/build.rs` links. The rule takes (i), the safest: the import, its declaration in the bridge's existing `unsafe extern "C++"` block and its C++ reader stay in partsmith-occt-sys (kernel.md section 3.13 item 7), the one crate allowed C++ and `unsafe`. partsmith-wasm's exports, `unsafe` code and link arguments change nothing. Only its safe `session_options()` passes `CancelFlag::page()` (ADR 0010's note of 2026-11-07).
8. *Where the user stops.* Options: (i) a Stop button in the status bar from the moment "Rebuilding" shows, a newer preview value, Esc on an open command and the still-working panel; (ii) only the still-working panel after 10 s. The rule takes (i), the industry standard: Fusion shows a cancel beside its compute progress, and technical design section 14 drops the old preview job when a value changes.

## Consequences

- Gate 11 holds on this route: a stop keeps the result cache, the document and the undo log, and the web keeps its worker and its undo history.
- partsmith-occt-sys gains `Interrupt`, the polling of OCCT's progress range in the calls kernel.md lists, the kind `KernelErrorKind::Canceled` and the import `partsmith_cancel_word` (kernel.md, by handoff to the kernel step). partsmith-features gains `CancelToken::from_interrupt`, `CancelToken::interrupt` and `BuildContext::interrupt`, and maps a canceled kernel error to `FeatureError::Canceled` (features.md, by handoff). partsmith-io's `read_step` and `write_step` take the interrupt and pass it to the kernel. A stopped call comes back as `IoError::Kernel` with the kernel error of kind `Canceled` (io.md, by handoff).
- partsmith-recompute evicts nothing after a canceled run (recompute.md tests 75 to 79). partsmith-engine gains `CancelFlag`, `SessionOptions::cancel`, `Session::rebuild`, `EngineError::Canceled` and section 3.26 (engine.md tests 195 to 210, 231 and 232, and the two budget rows). partsmith-protocol gains `FeatureState::NotRun`, `ErrorCode::Canceled` and command 37 (protocol.md tests 96 to 98; tests 99 to 103 cover the worker, the module and its link arguments). `docs/format/protocol.schema.json` and `ui/src/generated/protocol.ts` are regenerated and logged in ADR 0016 when they are checked in.
- The desktop host gains `cancel_call`, `Host::cancel`, its permission file and its capability entry (desktop.md tests 75 to 78, with test 11 listing nine names, and protocol.md test 104 for the Tauri transport). ADR 0014's command list grows by one, as ADR 0037 grew it by two.
- The UI gains `Transport.cancel`, `CoreClient.stop`, the `signal` of `CoreClient.request`, the Stop button, the not-built state and the `rebuild_stopped` notification (ui.md U-266 to U-275, U-297, E-171, E-172 and P-13). M1's restart stays for a web core that cannot stop.
- partsmith-print gets no cancel check inside one body. A print check of one very large body runs to its end (engine.md open issue 24).
- Python and the CLI change nothing in behavior (python-api.md test 132, cli.md test 85).
- The desktop has no end-to-end harness (desktop.md section 1.2). Its Stop is tested at the host and the transport, and checked by hand at the gate.
- This changes the protocol schema and adds a desktop capability. Both go to human review at the M2 gate.
