# W2-2D-2: The printer clearance of threads and holes

Status: Accepted (owner's rule of 2026-11-05): the M2 plan's open choice "How printer.fit reaches threads and holes, and which class applies", decided as the wave 2 decisions of 2026-11-19 accept it ([m2-wave2-decisions.md](../design/m2-wave2-decisions.md) section 3, "Choices cited by name"). It amends [ADR 0065](0065-feature-help-start-values-and-new-body-fields-in-the-manifests.md) decision 5, what registration accepts: an `expr` start value may name the printer's four fit classes. It also amends decision 3: such a start value still means the same in every document unit, but it may differ between printers. That rule is carried by the protocol's manifests, and goes to human review at the M2 gate with ADR 0065. It changes no schema: `StartValue` keeps its three forms. No file format, naming algorithm, license or dependency change.

## Context

- **Choice 16** adds "FDM clearance from `printer.fit.*` expressions" to the thread and hole tables. Technical design section 11 asks for "enlarged clearance" in FDM-tuned threads, and its section 10 example writes `param("clearance", printer.fit.slip)`.
- **The fit classes** are per side: a pin of diameter d goes into a hole of d + 2c (print.md section 3.2). Each profile has press, snug, slip and loose, on FDM and on resin. print.md's `FitClass` describes slip as "Parts that slide or rotate freely" and snug as "Tight fit that assembles by hand".
- **Printer values reach a build only through declared expressions** ([ADR 0069](0069-component-scopes-by-containment-and-occurrence-paths.md) rule 7). Recompute rebuilds a feature when a context name of one of its expressions changes value (recompute.md test 31).
- **Start values.** ADR 0065 decision 3 asks that an `expr` start value mean the same in every document unit. Its decision 5 leaves what registration accepts to features.md section 3.3. That section refuses a start value with a dotted name: `fixed_value_problem` in `crates/partsmith-features/src/schema.rs` evaluates it with `EmptyContext`. features.md test 54 checks that `printer.nozzle` is refused.

## Decision

1. **A clearance expression.** A modeled thread, a modeled tapped hole and an ISO 273 clearance hole take their clearance from an expression field with the unit `length`, declared as an `ExprUse` (features/thread.md section 6). Track 3A names the field in each record.
2. **Its start value is `printer.fit.slip`.** The manifest gives the field `{"kind": "expr", "expr": "printer.fit.slip"}`. A user can type any length of at least 0, `0` or `printer.fit.snug` among them.
3. **Per side, on every diameter.** The value moves a modeled thread's major, minor and pitch diameters by twice the clearance, away from its mate, and adds twice the clearance to an ISO 273 hole's diameter. It is at least 0: the feature refuses a value below 0 with `OutOfRange`, whatever the expression names (features/thread.md section 5.6, alternative 5).
4. **The start-value rule.** Registration evaluates an `Expr` start value with a context in which `printer.fit.press`, `printer.fit.snug`, `printer.fit.slip` and `printer.fit.loose` are each 1 mm, and nothing else resolves. Every other rule of features.md section 3.3 stays: `printer.nozzle` and `printer.layer_height` are still refused (test 54 unchanged), and so is a start value that depends on the document units. Tests 75 to 77 cover the new names.
5. **Cosmetic threads take no clearance** ([ADR W2-2D-4](W2-2D-4-cosmetic-threads-and-head-sizes-and-inch-clearance-holes-wait-for-m3.md)).

## Alternatives considered

Each choice states its options, the pick and the owner's rule's reasons in order: the most open-source approach, the safest, the industry standard, then this work's recommendation. Every option is open source. The first criterion picks none of them.

1. *How the printer reaches the build.* (i) A clearance expression whose start value is `printer.fit.slip`, an amendment of ADR 0065; (ii) a fit-class field and a new `Dependencies` member for context names; (iii) a fixed number as the start value. The rule takes (i), the safest. The value travels the route printer values already take (ADR 0069 rule 7). A profile change rebuilds the feature with no new contract in features.md or recompute.md. The user sees the expression and can edit it. (ii) needs a synthetic expression use whose pointer the model's parameter rename helper would follow into no field (features.md section 3.2, `FeatureInspector`) or a new dependency kind. (iii) loses the re-tuning that choice 16 asks for.
2. *Which class.* (a) `slip` for every thread and hole; (b) `snug`; (c) a class per feature chosen in a field. The rule takes (a), the safest. Slip is print.md's class for parts that rotate freely, and a screw turned by hand rotates in its mate over every turn of its thread. Gate 20's prints must screw together by hand. Snug is a tight fit that assembles by hand. On a 60-degree thread a radial clearance c leaves `c / 2` between mating flanks (features/thread.md section 5.3): 0.1 mm at `generic-fdm`'s slip and 0.05 mm at its snug, along the whole helix. Spike 8.2 built its threads with 0.2 mm of radial clearance, `generic-fdm`'s slip (kernel.md section 8.2). (c) is (a) with a field more, and the expression already takes any class.
3. *Which holes take it.* (a) Modeled threads, modeled tapped holes and ISO 273 holes; (b) threads only, ISO 273's values as tabulated. The rule takes (a), the safest. ISO 273's diameters are clearances for machined holes. A printed hole comes out smaller than modeled, and the printer's clearance on top keeps a standard screw from binding in it. A user who wants ISO 273 as tabulated types 0.
4. *Which start-value names.* (a) The four fit classes; (b) every `printer.*` name. The rule takes (a), the safest. The fit classes exist on every printer technology. `printer.nozzle` has no value on a resin printer (print.md section 3.5), and a start value that named it would fail there.
5. *A clearance below 0.* (a) Refused for threads and holes; (b) refused for threads, allowed for clearance holes; (c) allowed. print.md section 3.1 allows a negative fit class, an interference press fit. The rule takes (a), the safest. Below 0, a thread crosses its class's maximum-material limit and meets a standard mate along its flanks. A clearance hole below 0 is smaller than ISO 273's, and a standard screw may bind in it. A user who wants another hole types its diameter, as in M1. On a profile whose `slip` is below 0, the start value gets the feature's range message on the clearance field, which names the bound.

## Consequences

- features.md section 3.3's start-value rule and tests 75 to 77 change by spec first. features.md test 54 stays as it is (the wave 2 decisions of 2026-11-19, section 2 item 13).
- The code change is in `fixed_value_problem`: its context becomes a map of the four names, `BTreeMap<String, Quantity>` (expressions.md section 2), in place of `EmptyContext`.
- Two printed threads that mate each other each take the clearance. They leave twice the clearance between them, and a user types half on each to leave one (features/thread.md section 6 item 4, open issue 1).
- The UI, the CLI and Python need no change: a host writes an `expr` start value into the field as it does today (ui.md section 2.12), and Python writes `printer.fit.slip` as it is (python-api.md section 3.2).
- print.md sections 3.2 and 3.5 name the features that read the fit classes.
