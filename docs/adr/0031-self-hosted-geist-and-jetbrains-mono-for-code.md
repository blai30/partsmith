# 0031: Geist with a serifed I and tabular figures for interface text and numbers, JetBrains Mono for code only, both self-hosted

Status: Accepted (owner decision, 2026-10-15), needs human review (license policy: two SIL OFL 1.1 font files ship with the app; the Windows rendering check of ui.md open issue 33). Supersedes the font loading of [ADR 0013](0013-oxc-tooling-and-theme-stylesheet.md): its Google Fonts import, Inter for interface text and JetBrains Mono for values.

## Context

ADR 0013 loaded Inter and JetBrains Mono from Google Fonts through a CSS `@import`, and set every value (numbers, dimensions, expressions) in JetBrains Mono. ui.md open issue 10 listed what that costs: offline (the desktop app without a network, air-gapped use, CI) the app falls back to system fonts and the visual tests cannot run; every launch sends the user's IP address to Google; the `@import` chain delays the first paint; and the desktop content security policy has to allow two remote hosts. ADR 0030 left new fonts to a separate study.

The font study (a specimen page of October 2026, Linux Chromium renders) first required a slashed zero that survives tabular figures and picked TASA Orbiter. Its revised brief dropped that requirement: numbers may use the plain zero people know, and units such as mm and deg are set in the interface face. It then compared three faces for numbers beside a Geist interface: A, Geist itself; B, Geist Mono with its plain-zero set; C, JetBrains Mono with its dotted zero. A review of the renders ranked A first, because numbers and units share one face, size and baseline, and a plain zero can never meet a letter O in a numeric field. The owner chose A on 2026-10-15.

## Decision

- **Interface text and units: Geist 1.800** (the variable `Geist-Variable.woff2` of the npm package `geist` 1.7.2, unmodified, 69,652 bytes), SIL Open Font License 1.1 with no Reserved Font Name. `font-feature-settings: 'ss05'` gives the capital I serifs, so I never passes for l, 1 or |. Both are set once, at the root, through Tailwind 4's theme variables `--font-sans` and `--font-sans--font-feature-settings`, which Tailwind's preflight applies to the root element and form controls inherit.
- **Numbers: Geist.** Tabular figures (`tabular-nums`, which sets `font-variant-numeric`) wherever digits line up: inspector fields and the Parameters panel's values, the timeline's details, the status bar's counts and timings, measurement readouts, tables and dimension labels. Proportional figures in sentences, counts in prose and button labels. The zero is Geist's plain zero; no slashed or dotted zero appears in any number. `tnum` is never set through `font-feature-settings`, which is one list and would drop `ss05`.
- **Code only: JetBrains Mono 2.304**, SIL OFL 1.1 with no Reserved Font Name. Code means parameter names and expressions shown as code (the Parameters panel's name and expression fields, the palette's and the browser's parameter rows), the inspector's read-only JSON of unsupported values, and later the Python export view and technical details (error details, ids). Its `@font-face` sets `size-adjust: 96%`, which brings its x-height level with Geist's; `font-feature-settings` is `normal` (through `--font-mono--font-feature-settings`), so its dotted zero stays, since code mixes letters and digits; editable code sets `font-variant-ligatures: no-contextual`. Inspector fields stay in Geist even while they hold an expression, so a field never switches faces while the user types.
- **Titles** keep the interface face at semibold. There is no display face.
- **Self-hosted files** in `ui/public/fonts`, each with its license text: Geist whole, since it sets every name the user types and a Latin subset would drop its Cyrillic and Vietnamese letters; JetBrains Mono converted from the release's variable TTF to WOFF2 and subset to the Latin and Latin Extended ranges with every layout feature that acts on them (56,316 bytes in place of 113,316). ui.md 2.16.7 records each file's bytes and SHA-256 and the fontTools command, and U-202 pins them.
- **Loading.** `ui/src/index.css` holds two `@font-face` rules (`font-display: swap`) and the four font theme variables besides the Tailwind import and the dark variant (ui.md 2.16.1), which replaces ADR 0013's approved block; the Google Fonts import is removed. `ui/index.html` preloads the Geist file. JetBrains Mono loads the first time code text is laid out. The desktop policy allows `font-src 'self'` and no font host in `style-src` (desktop.md 2.8).
- **No font classes in code.** `FONT_CLASSES` leaves `ui/src/theme/roles.ts`: the families are named only in the stylesheet, and components use the inherited interface face, `font-mono` and `tabular-nums`.

## Consequences

- No request leaves the app for fonts: no IP address goes to Google, the desktop app looks the same offline, the visual tests run without a network, and the content security policy names no remote source.
- The first paint waits on one preloaded same-origin file of 69,652 bytes instead of a CSS request to Google followed by font requests. A session that never shows code never downloads JetBrains Mono.
- Values and words share one texture: units sit on the number's baseline in the same face, and the frontend guideline's warning against monospace labels holds by construction. Code still reads as code.
- Every visual baseline changes (ui.md 6.6), and V-21 adds one with code on screen; all need a reviewer's approval at the gate.
- Both variable files are unhinted. Windows at 12 and 13 CSS pixels is unchecked; if the gate finds Geist soft there, the fallback is the `geist` package's hinted static Regular, Medium and SemiBold files (45,244, 46,372 and 46,596 bytes), the three weights the UI uses (ui.md open issue 33).
- Glyphs Geist lacks (the macOS key glyphs and the diameter sign) come from the system font, one character at a time.
- delivery.md 2.7 still says that Google Fonts sends `Cross-Origin-Resource-Policy: cross-origin`, so the fonts load under `require-corp` (ADR 0013). That no longer applies: the fonts are same-origin files of the build, which need no CORP header (ui.md 2.16.7). The change that made this decision could not edit delivery.md, so its owner deletes the sentence or replaces it with "Fonts are same-origin files of the build (ui.md 2.16.7, ADR 0031), so they need no CORP header."
- Two OFL-1.1 fonts now ship in the web build and the desktop bundles. CLAUDE.md's license policy names only permissive dependencies and OCCT, so this needs the human license review at the next gate, and the third-party notices list both fonts (m1-gap-list B-2). No npm package or crate is added; fontTools ran once by hand to produce the JetBrains Mono file.
