# 0091: STEP import in the UI and the CLI through `import_step`

Status: Accepted (owner's rule of 2026-11-05): the M2 plan's item 22 and the choices below. No file format, protocol, naming, license or dependency change: the UI calls the existing command 28, `import_step`, and the CLI calls the engine's existing `Session::import_step`. It changes the wording of [ADR 0064](0064-assets-added-to-an-open-document-and-named-by-the-core.md) decision 5, which says that ui.md's `addPickedAsset` is the UI's one way to add a picked file: a picked STEP file for an import goes through `import_step`, "Choose file..." adds a picked file under a missing import's asset name with `add_assets`, and `addPickedAsset` stays for a file that an edit names, such as wave 3's fonts. ADR 0064 is on gate 19's list, and this note goes to human review with it. What a Save to a download target does with the imported file is [ADR 0092](0092-a-download-save-also-downloads-the-imported-files.md).

## Context

- **What exists** (read at 0f578c1). The engine's `import_step` stores the bytes under `<blake3>.step`, adds one body named by the request's `name`, else the first solid's product name, else `Imported`, with the first solid's color, and adds an `import` feature with `op: new` at the rollback marker, as one undo entry `Import STEP` (engine.md 3.14 and 3.3; `crates/partsmith-engine/src/exchange.rs`). Protocol command 28 carries it, and the generated TypeScript types hold it (`ui/src/generated/protocol.ts`). Python's `Document.import_step` calls it. The UI has no import command (ui.md 1 and 2.10), and `CoreApi` has no `importStep`. `addPickedAsset` exists with no caller (`ui/src/app/actions/document-assets.ts`), as ui.md open issue 45 says. The CLI has five commands and no asset writer (`crates/partsmith-cli/src/arguments.rs`, `src/files.rs`).
- **The plan.** m2-plan.md item 22: an Import command in the UI and `partsmith import` in the CLI, "over the engine's existing `import_step` and wave 1's asset command". Gate 13: the UI on the web and the desktop and `partsmith import` give the same asset bytes and documents equal once generated ids are mapped, and an E-test imports a STEP part and fillets one of its edges without reopening the document.
- **The tension.** ADR 0064 decision 5 and ui.md 3.19 say the Import command calls `addPickedAsset` and then names the asset in an edit. That edit would have to add a body and an import record itself, without the product name and color that `import_step` reads (technical design section 12, "colors and names"), and the CLI would have to do the same for gate 13.

## Decision

1. **The UI imports through `import_step`.** `CoreApi.importStep(doc, bytes)` sends command 28 with the bytes as buffer 0 and no `name`, as a `change` task of the mutation queue (ui.md 2.5 and 2.6). The result names the new feature. The UI reads that feature's `asset` from the recipe of the `document_changed` the command emitted, and adds the bytes under that name to `DocumentState.assets`. A core restart then gives the core the file again (ui.md 4.4). No protocol schema changes.
2. **The command.** `file.import`, "Import...", in the Document menu after "Save as..." and in the palette, category File, no toolbar entry and no shortcut. Description: "Brings the solids of a STEP file into this document as a new body." Keywords: Insert (Fusion), Import (FreeCAD), STEP, STP. It picks with `files.pickToOpen('step')` and imports into the shown document at the rollback marker, as one undo entry `Import STEP`. During a feature command it is disabled with `finish_command_first`, as Export is. During a sketch session it is disabled with `finish_sketch_first` ("Finish Sketch 1 first."), which M1's Export does not check (ui.md 3.19, Import, and 3.18, Export to Python step 1). The plan recommends `finish_command_first` in both cases, and the new message departs from its wording for the sketch session (alternative 5). A file dropped on the window whose name ends in `.step` or `.stp` imports the same way.
3. **The body's name.** No host sends `name`, and the engine's rule names the body: the product name, else `Imported`. The CLI's `--name` sends one when the user asks.
4. **The CLI.** `partsmith import <STEP> -o <PTSM> [--name <NAME>] [--force] [--json] [--deny-warnings]` makes a new document: `new_document` in millimeters with no printer, `import_step`, `save_document`, in a headless session with `SequentialIds`. It writes the asset first, with file-format.md 3.11's entry check, then the document through cli.md 3.7's write. An existing output file is refused unless `--force`. The import's messages print after the files are written. Its status gives the exit code by `rebuild`'s rule: 1 for `error`, or for a warning with `--deny-warnings`, else 0 (cli.md 3.8). With `--json` a failure prints a JSON document too.
5. **A missing file gets an action.** An import's `asset_missing` message offers "Choose file..." in the UI: it picks a STEP file and sends `add_assets` with the missing asset's name, which the core stores only when the bytes hash to it (ui.md 3.19). The core's message keeps its words.
6. **Stops.** A `canceled` answer (engine.md 3.26) shows the core's text as an info notification and adds nothing. A core that stops while the import runs drops it as it drops any change, with `changes_not_applied` (ui.md 4.4).
7. **How gate 13 is tested.** Gate 13 asks for each STEP example. E-175 runs once for each STEP file under `examples/` (two today, `S` and the sketch examples' `C`): it imports the file into a new document in the UI, saves it through the download, and blesses `ui/e2e/fixtures/gui/import-<the first 8 hex digits of its name>.ptsm` with its `assets/` file as E-160 blesses its documents. cli.md test 104 runs `partsmith import` on each file and compares the two documents with their ids mapped in creation order, and the two assets byte for byte (delivery.md 2.8). The desktop's leg is a written manual check at the gate (desktop.md 6) that saves each STEP file's import from the desktop app and runs cli.md test 104 on those files, since the desktop has no E-test harness.

## Alternatives considered

1. *The route.* (a) `import_step` with the bytes, the asset name read from the recipe; (b) `import_step` whose result gains `asset`; (c) `addPickedAsset`, then `import_step` naming the stored asset; (d) `addPickedAsset`, then `add_body` and `add_feature` in one edit; (e) a `feature.import` inspector with a file field. The rule takes (a). All five are open source. (a) is the safest: no schema change, and one engine path (name, color, undo label, marker placement) for the UI, the CLI and Python. Gate 13's equal documents then hold by construction. (b) and (c) change the protocol schema for a value the recipe already holds. (d) loses the product name and color, and the CLI would have to copy it. (e) needs a new field kind and manifest hints for a feature whose only input is a file. Fusion's Insert and FreeCAD's Import are commands, not inspectors.
2. *Placement.* (i) Document menu and palette; (ii) also a toolbar entry; (iii) a feature command in Create; (iv) Open accepts `.step` and makes a new document. The rule takes (i). All four are the project's own code. (i) is the safest: it puts the least on screen (engineering principle 5), the palette finds it by its Fusion and FreeCAD words, and as a command outside the feature commands it never joins another feature's edit. The industry standard is a file command: FreeCAD's Import is in its File menu. The plan recommends (i).
3. *Target document.* (i) the shown document at the marker; (ii) a new document; (iii) both. The rule takes (i). All three are the project's own code. (i) is the safest: it is engine.md 3.14's tested behavior, one undo entry the user can take back. Fusion's Insert and FreeCAD's Import add the file to the open design. The plan recommends (i). The CLI makes a new document because it has no open one.
4. *The name.* (i) none, the engine's rule; (ii) the file name without its extension; (iii) ask. The rule takes (i). All three are the project's own code. (i) is the safest: one rule, the STEP file's own product name, in every host, and gate 13's equal documents need no name sent. FreeCAD's STEP import also labels a part with its product name. The plan recommends (i).
5. *During a command or a sketch session.* (i) disabled, with `finish_command_first` during a feature command and `finish_sketch_first` during a sketch session; (ii) disabled with `finish_command_first` in both; (iii) joins the command's transaction or the sketch session. The rule takes (i). All three are the project's own code. (i) and (ii) are the safest: an import is never part of another feature's edit, and a sketch session edits one sketch. Between them, (i) is the safer: `finish_command_first` reads "Finish or cancel {title} first." with a feature command's title, and a sketch session has neither a command title nor a cancel (it ends with Finish sketch, and its edits are already in the document, ui.md 3.16). A reason that offers a cancel the user cannot find fails docs/guidelines/errors.md's check that a message says what to do. No industry standard decides the message. The plan recommends (ii), disabling the command in both cases with `finish_command_first`. (i) keeps the plan's behavior and departs from its wording for the sketch session only, with the new message `finish_sketch_first` ("Finish Sketch 1 first.", ui.md 4.3). Export to Python takes the same availability ([ADR 0093](0093-export-to-python-in-the-app-and-assets-in-generated-scripts.md) alternative 3).
6. *A dropped STEP file.* (i) import into the shown document; (ii) keep M1's "not a Partsmith model" error; (iii) open a new document with it. The rule takes (i). All three are the project's own code. (i) is the safest: a drop runs the command's one path, with its availability, its undo entry and its messages, where (iii) would need a second way to make a document and (ii) leaves the user with an error for a file Partsmith can read. No industry standard decides it. The plan recommends (i).
7. *Recovery and `asset_missing`.* (i) accept the loss; (ii) store the bytes with the recovery entry; (iii) an action that picks the file and adds it; (iv) reword the core message. The rule takes (iii). All four are the project's own code. (iii) is the safest: the one action repairs every case where the file is gone (a recovered Untitled document, a lost assets folder, a download Save), and the core's text stays as its tests hold it. (ii) would put large files in IndexedDB beside every autosave (ui.md open issue 48), and (iv) changes the text every host shows. The industry standard for a linked file that is gone is an action that finds it again, as Blender's Find Missing Files and InDesign's Relink do. The plan recommends (iii).
8. *The CLI's grammar.* A new document only, or also `--into` an existing one; an existing output replaced, refused unless `--force`, or always refused; `import_warning` exits 0 (1 with `--deny-warnings`), always 0, or 1. The rule takes a new document only, refusal unless `--force`, and `rebuild`'s warning rule. All are the project's own code. They are the safest: a `.ptsm` holds the user's work, refusing it is safer than export's replace, and a new document only never edits a document in place. Adding to a document is what the UI's command and Python's `Document.import_step` do. The industry standard for a file a command would replace is a flag that allows it (`ln -f`, `git branch -f`), and `--deny-warnings` is `rebuild`'s flag, after rustc's `-D warnings`. The plan recommends all three.
9. *Gate 13's test.* (i) a committed UI-written fixture compared by a CLI test; (ii) a committed CLI-written file compared inside an E-test; (iii) one CI job running both. The rule takes (i). All three are the project's own code. (i) is the safest: the fixture is what the real UI saved, a reviewer sees it change in the diff, and `cargo test` compares it on every change without a browser. (ii) checks only on e2e runs, and (iii) ties the `rust` job to a browser run. Committed expected files compared by a test (golden files) are the industry standard, and [ADR 0048](0048-python-keywords-gui-round-trip-and-python-budgets.md) decision 2 uses them. The plan recommends (i).
10. *A read-only asset file with other bytes.* The CLI writes assets for the first time and needs a rule for an entry under the asset's name that is read-only and holds other bytes (file-format.md 3.11's entry check replaces any such file). (a) Refuse it with `the file is read-only. Make it writable first.`, as the desktop does (desktop.md 3.4 step 9.3) and as the CLI refuses every read-only file it would replace (cli.md open issue 14); (b) replace it, as Python does on Linux and macOS ([ADR 0037](0037-save-checks-the-file-and-hosts-reach-the-assets-folder.md) decision 5). The rule takes (a). Both are the project's own code. (a) is the safest: a read-only file was protected on purpose, and the owner's rule of 2026-11-05 already makes the CLI refuse one (cli.md open issue 14). Tools that rewrite files, such as rustfmt and Prettier, fail on a read-only file too. The plan names file-format.md 3.11's entry check and no read-only rule. The CLI then joins the desktop, and Python stays the one host that replaces such a file. cli.md open issue 15 records that difference, which waits for a change of ADR 0037 decision 5, and file-format.md 3.11's "What binds which host" gains the CLI (the spec round's hand-off to that file's owner).

## Consequences

- ADR 0064 decision 5 now reads: a host adds a picked file that an edit names with its kind and no name (wave 3's fonts, through `addPickedAsset`), a picked STEP file for a new import through `import_step`, and a picked file for an import whose file is missing with `add_assets` under that import's asset name ("Choose file...", decision 5). ui.md 3.19 says the same.
- Imports become common in documents the UI writes. Their Python export adds the file from the assets folder beside the script ([ADR 0093](0093-export-to-python-in-the-app-and-assets-in-generated-scripts.md)).
- `ui.md` 1, 1.2 and 2.10 lose M1's "no import command". cli.md open issue 1 and architecture.md's command list change with it.
- The Document menu gains Import... here and Export to Python... in [ADR 0093](0093-export-to-python-in-the-app-and-assets-in-generated-scripts.md). The visual baselines V-23 and V-24, which show that menu open, are taken again and reviewed at the gate (ui.md 6.6).
- A dropped file that is neither a `.ptsm` nor a STEP file gets a new message, `drop_unknown_file`. E-5 and `shell.test.tsx`'s dropped `notes.txt` change by spec first.
- Fusion and Onshape exports are still measured only through the project's own STEP files and OCCT's samples (kernel.md 3.8.1). A valid file ADR 0073's byte check refuses shows "Import failed. The file is not a valid STEP file." with Copy details.
