# 0045: STEP import counts the shapes it leaves out and the solids it cannot repair, and the import feature words the counts

Status: Proposed, needs human review: a public API change of `partsmith-occt-sys` (two fields of `StepImport`) and of `partsmith-features` (the fields of `FeatureWarning::ImportWarning` and the new `ImportContent`), the human gate of item IMP-1 of the M1 gap list. No file format, protocol schema, license, dependency or capability change: the warning keeps its code `import_warning`, and its detail travels in the diagnostic's existing `detail` field (ADR 0024).

## Context

- **Kernel sentences as messages** (gap list IMP-1, features/import.md open issue 3). `read_step` reported what it left out or could not repair only as English sentences in `StepImport::warnings`, and the import feature showed each one as an `ImportWarning` message. A STEP file with one free face beside a solid read `Skipped 1 shapes that are not closed solids.`, which is not grammatical, and a solid that repair could not fix was named by its position in the file (`Solid 2 is not valid after repair; booleans with it may fail.`), which docs/guidelines/errors.md keeps out of messages. Both are kernel text, which features.md test 14 keeps out of every message the feature specs render, while features.md section 4.2 had `ImportWarning` render it, so features/import.md test 10 could check its text against the message lint only, with two skipped faces so that the plural read correctly.
- **No test reached the repair warning.** No fixture made a solid that `ShapeFix_Shape` leaves invalid. Written to STEP and read back, BOX with a vertex moved by 0.001 to 30 mm in its BRep bytes (the fixture of kernel.md test 110), with a vertex, a line or a plane moved in the STEP text, with a face turned over or listed twice, and a box whose cavity crosses its wall or lies outside it all came back valid, often with no warning at all. Two fixtures stay invalid after repair: a solid whose void is its own outer shell, which has no volume, and a solid whose void is listed twice, whose volume counts the cavity twice (1008 mm³ instead of 3504 for kernel.md test 140's `HOLLOW`) and which builds through recompute and `partsmith rebuild`. The second became kernel.md test 140's `VOID_TWICE`.
- **What follows from an invalid solid.** Later features do not always fail on it. A join of `VOID_TWICE`'s block with the plate of features/import.md test 7 (40 x 40 x 10 at position (0, 5, 0)) built with no message but the import's warning, volume 20000 and 11 faces: the cavity was gone. The valid `HOLLOW` joined to the same plate gives volume 18272, 17 faces and `closed_void`. So the message says that features that change such a solid may fail or give a wrong shape.
- **Who reads the sentences.** The import feature, and `partsmith-io`, whose `read_step` passes them through unchanged as `ImportedStep::warnings` (io.md section 3.8). The engine's `import_step` ignores them: the feature's warnings reach hosts when the document recomputes.

## Decision

1. **Counts in `StepImport`** (kernel.md sections 2.12 and 3.8.1 read item 3). `skipped_shapes: usize` counts the open shells, and the faces outside shells, wires outside faces, edges outside wires and vertices outside edges, left out because they are not closed solids, and `invalid_solids: usize` the solids of `bodies` still invalid after repair. `warnings` stays, documented as technical text for details and logs that no host shows as a message: one sentence per invalid solid in body order, then one for the skipped shapes, now `Skipped 1 shape that is not a closed solid.` for one shape. `partsmith-io` and the engine are unchanged.
2. **The feature words the counts** (features.md sections 2.8 and 4.2, features/import.md sections 3.3 and 4). `ImportWarning { content: ImportContent, count: usize, detail: String }`, at most two, before the body rules' warnings and in the order of the kernel's sentences: `InvalidSolids` (`This import kept 1 solid of the STEP file that is not valid and could not be repaired, so features that change it may fail or give a wrong shape.`, for more `This import kept {count} solids of the STEP file that are not valid and could not be repaired, so features that change them may fail or give a wrong shape.`), then `SkippedShapes` (`This import left out 1 shape of the STEP file that is not a closed solid.`, for more `This import left out {count} shapes of the STEP file that are not closed solids.`). The invalid solid comes first because it is what changes later features, and the first message is the one hosts lead with (ui.md section 3.9: a timeline item's status reads `Warning: {first message}`). Both carry the same detail, `read_step: ` followed by every sentence of `StepImport::warnings` joined with single spaces, which `FeatureWarning::detail()` returns. The code stays `import_warning`, with no field, fix, suggestion or repair, like the warning it replaces.
3. **Fixtures made at test time.** `VOID_TWICE` and `BOTH` (kernel.md tests 140 and 141) are `write_step`'s text with one entity added and one list changed, built by the kernel's and recompute's tests, so no STEP file is committed and no example changes.
4. **Tests.** kernel.md test 135 checks the counts, and tests 139 (one skipped shape), 140 (a solid repair cannot fix) and 141 (both) are new; features/import.md test 10 checks the new text and its detail, tests 12 to 14 are new; features.md test 18 renders both kinds in the singular and the plural, each with its own detail, and those four are the `ImportWarning` samples the message lint renders.

## Options considered

The owner can still pick another of these:

- **(a) Reword only the kernel's sentences** (`Skipped 1 shape that is not a closed solid.`, a repair sentence without the solid's position), with no API change and no gate; users would still read kernel text, and features.md section 4.2 would still contradict test 14.
- **(b) Counts that the feature words, the sentences kept for the detail** (chosen): the only option that keeps kernel text out of messages without changing `partsmith-io`.
- **(b2) Counts only.** `StepImport::warnings` and io's `ImportedStep::warnings` go, and the feature writes its own detail from the counts (for example `read_step skipped_shapes=1`). One source of truth, but a public API change of `partsmith-io` too (io.md section 3.8 and its tests), and the detail loses the position of the solid that repair could not fix.
- **(b3) One detail per warning.** Each warning's detail holds only its own sentences, split by the order kernel.md section 3.8.1 fixes (the solids' sentences, then the skipped shapes'). More precise when both happen, but the feature then depends on that order, and a new kind of sentence would land in the wrong detail without failing.
- **(b4) Other words.** The two messages state what happened and what may follow, and name no fix, since none applies in every case: the shapes left out may be construction geometry the user does not need, and the program that wrote the file may not be at hand. A second sentence such as `Repair it in the program that made the file, then import it again.` is the alternative for the invalid solids.
- **(c) Positions instead of a count of invalid solids** (`invalid_solids: Vec<usize>`), so that a host could show which lump is invalid. No host needs it in M1, and the count is its length.

## Consequences

- kernel.md sections 2.12 and 3.8.1, tests 135, 139, 140 and 141 and open issue 15; features.md sections 2.1, 2.8 (`ImportContent`, its derives, the detail rule) and 4.2, test 18 and open issue 21; features/import.md sections 3.3 and 4, tests 10, 12, 13 and 14 and open issue 3; io.md section 3.8 (the doc comment of `ImportedStep::warnings`). The code change is in `cpp/exchange.cpp` (one more counter and the singular sentence), `src/ffi.rs` and `src/exchange.rs` of `partsmith-occt-sys`, and `error/warning.rs`, `error/message.rs` (`ImportContent`, beside `IgnoredReason`), its re-export from `error/mod.rs` and `lib.rs`, and `builtin/import.rs` of `partsmith-features`; the public-interface lines of `crates/partsmith-occt-sys/AGENTS.md` (`StepImport`'s counts) and `crates/partsmith-features/AGENTS.md` (`ImportContent` beside `IgnoredReason`), and the doc comment of `ImportedStep::warnings` in `crates/partsmith-io/src/step.rs`, follow. The tests are in `tests/exchange.rs` of the kernel, the features crate's message tests and its lint samples (`tests/common/samples.rs`, whose `ImportWarning` sample becomes test 18's four), and `tests/feature_import.rs` of recompute.
- `partsmith-io` passes no counts, so a host that shows import warnings must take the feature's; option (b2) would change this.
- Reverting is local: restore `ImportWarning { message }` and the mapping of each kernel sentence to one warning, and drop the two fields; nothing is stored in documents or caches.
- Hosts show the feature's sentences, and the kernel's in Copy details, `--json` and the Python exception's `detail`. One import warning with both kinds of content becomes two warnings with one count each, where the kernel gave one sentence per invalid solid.
