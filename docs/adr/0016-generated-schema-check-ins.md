# 0016: Generated schema check-ins

Status: Accepted, needs human review

## Context

CLAUDE.md requires every change to the file-format schema or the protocol schema to be recorded in the ADR log and reviewed by a human at the next gate. Both schemas are generated from the Rust types with `schemars` (ADR 0006) and checked in under `docs/format/`, where tests compare them with the generated text so drift fails CI.

## Decision

This ADR is the log of schema check-ins. Each entry names the file, the date, the change and the specs that define it. A planned entry names a change that accepted specs make and the code has not generated yet; it is dated when the generated schema is checked in.

| Date | File | Change |
| --- | --- | --- |
| 2026-10-12 | `docs/format/protocol.schema.json` | First check-in, generated by `partsmith_protocol::protocol_schema()` (protocol.md section 2). Requests are closed: field-less command variants and the shared types read from requests (`Orientation`, `AssetData`, export tolerances) reject unknown fields through strict request-side copies (`allOf` with `unevaluatedProperties: false`), while results and events accept unknown fields (protocol.md section 3.6). `Request` stays a named definition so the generated TypeScript exports it. `ElementKind` is shared with `partsmith-naming` rather than redefined. |
| 2026-10-12 | `docs/format/protocol.schema.json` | Every variant of `$defs/Edit` gains `"additionalProperties": false`: edits are read only from requests, so they reject unknown fields (model.md section 2.9). A `FeatureRecord` inside an edit stays open, since its unknown keys are params. The generated TypeScript is unchanged. |
| Planned ([ADR 0024](0024-diagnostics-with-actions-causes-and-ghosts.md), needs human review) | `docs/format/protocol.schema.json` | Diagnostics with actions, causes, details, candidates and ghosts (protocol.md sections 2.4 to 2.9, engine.md sections 3.4 and 3.21 to 3.25): `Diagnostic` gains `actions` (omitted when empty), `cause`, `detail`, `root` and `reason`; new `Cause`, `FixAction`, `FixKind` (`apply`, `pick`, `show`, `undo`, `finish_transaction`), `FixRef` (closed, since requests carry it), `LossReason`, `Removal`, `Absence`, `InstanceIndex`, `Ghost`, `GhostKind`, `GhostFrame`, `RepairCandidate`, `RegionCandidate` and `Use`; `Repair` variants gain `description`, `candidates` and `ghost`; `ElementDescriptor` gains `fallback` and `axis_direction`; `Pick` gains the optional `body` of headless picks; `ErrorInfo` gains `detail` and `actions` (omitted when empty); `DocumentChanged` gains `bare_numbers`; `SketchSolution` gains `messages`; the commands `apply_fix`, `set_document_units` and `list_uses` with their results; the error code `stale_fix`. The shared `Reference`, `RegionRef`, face sketch plane and axis types gain the optional format version 2 fields `nb`, `merged`, `outline`, `fallback_frame` and `direction` ([ADR 0025](0025-file-format-version-2.md)). Every addition is optional or new, so `PROTOCOL_VERSION` stays 1. Becomes a dated entry when `partsmith schema --write` checks it in; the UI regenerates its TypeScript types then. |

## Consequences

Reviewers see every schema change in one place. `partsmith schema --write` regenerates both files, and the schema tests in `partsmith-protocol` and `partsmith-cli` fail when the checked-in text is stale.
