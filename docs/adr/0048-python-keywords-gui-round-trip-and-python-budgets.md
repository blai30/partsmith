# 0048: Python keywords for the GUI's extrude, chamfer and pattern options; documents the UI writes go through the Python round trip; the Python budgets are a pytest marker that warns over budget

Status: Proposed, needs human review for decision 1, which adds keywords to the public Python API (gap list PY-2, a human gate). Decisions 2 and 3 change tests, test fixtures and one CI step only, with no capability, schema, license or dependency change, and are accepted. Decision 3 does not depend on decision 1. Decision 2's generic-call checks (check 3 of the documents the UI writes, delivery.md 2.8, and the third check of delivery.md test 71) depend on decision 1, as python-api.md test 113 does: they hold only while the keywords exist, so option (C) removes them with the keywords.

## Context

- **Three GUI options had no Python keyword** (gap list PY-2). Technical design section 10 says that every GUI feature has a Python constructor with the same parameters. The inspector offers, and documents store, an extrude with two sides (features/extrude.md, field Opposite distance), a chamfer with two distances and Flip (features/chamfer.md, fields Second distance and Flip) and a linear pattern reversed along either direction (features/linear_pattern.md, fields Reverse and Second reverse). Python could build them only with the generic `feature("extrude", ...)` form, whose params are raw JSON (references as dictionaries, expressions as strings), and the hooks of `partsmith-features` wrote them that way. On 2026-10-28, 9 of the corpus's twins held a generic call: the 8 of these options (`chamfer/edge-order`, `chamfer/two-distances`, `chamfer/two-distances-flipped`, `extrude/two-sides`, `extrude/two-sides-one-zero`, `extrude/two-sides-reverse`, `linear_pattern/reverse` and `linear_pattern/second-reverse`), and `hole/deleted-point`, whose hole names a point its sketch no longer has. The gap list asked for the keywords, or for an ADR that keeps the generic form on purpose.
- **The GUI to Python round trip never ran on a document the UI wrote** (gap list EX-10). Technical design sections 10 and 16 put a round trip from the GUI through Python to `.ptsm` in CI. python-api.md 3.9's round trip runs on the engine fixtures, the documents of its test 86 and the examples, all written by hand: sequential ids, unnamed features, starting values never left as they are, and references written into tests. What only the UI writes (random ids, starting values, references and axis directions copied from picks, bodies a command makes, renames) was never checked.
- **The Python budgets were never measured** (gap list PY-3). python-api.md section 5 has five rows and no benchmark. The engine's budgets are a `cargo bench` harness run by hand (engine.md section 5), and the UI's are Playwright tests run by hand (ADR 0043), since no reference machine exists yet (delivery.md section 1.2). The gap list asked for a `budgets` marker beside `packaging`, or a `python/benches/budgets.py`, run in the python job without failing on a slow runner unless the spec says so. The dependency it named for row 5, the reference stability plan's PY2 (full references from selections), is merged.
- **Measured on 2026-10-28** in the development container (4 cores, the build `maturin develop --release` installs), with the rules python-api.md section 5 now gives: `import partsmith` 61 ms; overhead per call 0.18 ms for `box`, 0.48 ms for `faces().top()` and 0.08 ms for `volume`; `run_script` of the fifty-feature twin 3872 ms, over its 1300 ms, while the engine's own `open_document` row of that document measured 2698 ms against its 1 s on the same container; the slowest of eight filters over 1014 faces 2.09 ms; `refs()` of 12 edges 0.96 ms.

## Decision

1. **Keywords named after the GUI's fields** (option (A) below). `extrude(..., opposite_distance=...)` stores a `two_sides` extent with `distance` as `expr` and `opposite_distance` as `opposite_expr`; `chamfer(..., second_distance=..., flip=False)` stores `two_distances`, with `"flip": true` when flipped; `linear_pattern(..., reverse=False, second=..., second_reverse=False)` stores `"reverse": true` in the first or second direction. Each keyword is the field's manifest label in snake case. The combinations a record cannot hold raise `ValueError` before anything is sent: `opposite_distance` without `distance` or with `symmetric=True`, `flip=True` without `second_distance`, and `second_reverse=True` without `second` (python-api.md 3.5 gives the sentences and the order of the checks). The hooks of extrude, chamfer and linear pattern write these keywords, in signature order, so generated code uses the generic form only for `import`, plugins, invalid records and records that name something the generator has no variable for (python-api.md 3.5, features.md test 23, which now takes an `import` record as its record without a dedicated form). The 8 twins above are regenerated by the Python bless, never by hand: delivery.md 2.8's twin check 4 fails while a twin has more generic calls than its generated script, and a bless rewrites such a twin, as it rewrites one that fails check 1.
2. **Three documents written by the UI, checked on both sides** (option (a) below). E-160 (ui.md 6.5) makes `extrude-sides.ptsm`, `picks.ptsm` and `starting-values.ptsm` in the real UI from `parametric.ptsm`, `cube.ptsm` and a new document, and saves each through the download. On every e2e run it makes them again and checks a list of facts per document on the download: generated ids, the extents, distances, reverses, starting values, picked edge and face references with the face's fallback, the axis direction, new-body targets and the names its steps make. Only then, with `PARTSMITH_BLESS=1` (refused in CI, as for the examples), does it write the download to `ui/e2e/fixtures/gui/`, so a broken UI never overwrites a good document. It then checks the same facts on the committed file, and that the committed file has the download's JSON structure (the same keys in the same order and the same array lengths) and values, generated ids, references and numbers set aside (numbers within 1e-9), so a field the UI starts writing fails the run until the document is blessed again. `python/tests/test_gui_documents.py` (delivery.md 2.8, test 71) runs python-api.md 3.9's first form on each committed document, and checks that every feature is ok and that the generated script has no generic call. The files are not compared byte for byte, because their ids are random and an edge's name lists its faces in byte order, so references change with the ids.
3. **A `budgets` pytest marker that warns over budget** (option (i) below). `python/tests/test_budgets.py` holds one test per row of python-api.md section 5, marked `budgets` and left out of `pytest python/tests` like `packaging`. Each takes the median of 7 timed runs after an untimed one, prints its row, and over budget emits a `UserWarning` and passes, on every machine, since neither CI's runners nor development machines are the reference machine; section 5 says what each row times. A strict run, on the reference machine, adds pytest's own `-W "error:Over budget:UserWarning"`, which turns those warnings into failures, so no environment variable changes what the tests do. The python job runs `pytest python/tests -m budgets -s` (delivery.md 2.4), so every CI run shows the numbers and fails only when a row cannot be measured. Row 5 is measured too, since the plan item it waited for is merged.

## Options the owner can still pick

For decision 1:

- (A) **Keywords named after the fields** (chosen): five keywords, four `ValueError` sentences, and three hook branches that replace three `return None`s.
- (B) **The second direction's reverse inside `second`**: `second=(Axis.Y, 2, 15, True)` instead of `second_reverse=True`, which the gap list's "including inside `second`" may have meant. No combination can be wrong (there is no `second_reverse` without `second`), but a bare `True` in a tuple says nothing about what it turns on, which Python's style guides warn against. A change of the tuple's shape and of one hook line.
- (C) **Keep the generic form on purpose** (the gap list's alternative): no API change. Reverting decision 1 means removing the keywords, their checks and the three hook branches, and restoring the three hook unit tests that pinned `None` (the `two_sides` assert of `python_writes_the_sketch_and_distance` in `extrude.rs`, `two_distances_have_no_dedicated_python_form` in `chamfer.rs` and `a_reversed_direction_has_no_dedicated_form` in `linear_pattern.rs`); giving features.md test 23 its two-sided extrude back; removing python-api.md tests 107 to 113 and the dedicated-form clause of test 82; dropping check 3 of the documents the UI writes (delivery.md 2.8) and the third check of delivery.md test 71, since `extrude-sides.ptsm` and `picks.ptsm` then generate generic calls again; dropping twin check 4 (delivery.md 2.8, test 72 and its section 4 row), so the bless rewrites a twin that fails check 1 only; and running the Python bless, whose check 1 then fails on the 8 regenerated twins (they call keywords that no longer exist) and rewrites them.
- (D) **Other names**: `opposite=` for the extrude, or one argument per pair (`distance=(20, 10)` for two sides, `distances=(1, 3)` for a chamfer). Shorter, but each departs from the names the inspector shows, and a pair hides which side gets which value.

For decision 2:

- (a) **Committed documents made by the UI, with facts checked on both and their structure compared** (chosen).
- (b) **No committed documents**: E-160 uploads its downloads as an artifact and the python job, then needing the `e2e` job, runs the round trip on them. Always current, but it puts the python job behind the WebAssembly build, lengthening CI's critical path.
- (c) **Documents made by hand once in the app, with no E-test**: the least code, but nothing would tell when the UI starts writing something else.
- (d) **A byte comparison after renumbering ids**: fails whenever a renumbered edge name sorts its faces differently, so it needs the naming rules in the test.

For decision 3:

- (i) **A pytest marker that warns over budget** (chosen): no argument parsing, report code or environment switch; `-k` selects rows, and `-W` makes a run strict.
- (ii) **A script, `python/benches/budgets.py`**, like `cargo bench -p <crate> --bench budgets -- <words>` with `partsmith-budgets`'s report: the same output as the Rust benches, about twice the code.
- (iii) **Failing CI over budget**: row 3 would fail every run today, on a runner that is not the reference machine.
- (iv) **By hand only, like the engine's rows**: no CI time, but nothing would notice a bench that no longer runs.
