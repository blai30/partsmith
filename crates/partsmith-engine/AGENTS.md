# partsmith-engine

`Session`: open documents, apply commands, undo and redo, recompute, tessellate, export, analyze, generate Python.

Spec: `docs/spec/engine.md`.

## Public interface

- `Session::new(SessionOptions)`: the single entry point. `SessionOptions` sets the display flag, id generator (`SequentialIds` for tests), cache budget (`DEFAULT_CACHE_BUDGET`), undo limit and tessellation quality; `SessionOptions::headless()` (display off, `SequentialIds`) serves the CLI, Python and tests.
- Frames: `Session::call(&[u8]) -> Vec<u8>` decodes a PSM1 request frame and returns the response frame; `Session::execute(Request, buffers) -> Reply` does the same on decoded values. Each command runs on a snapshot and a panic poisons only its document.
- Documents: `new_document`, `open_document`, `save_document`, `mark_saved`, `close_document`, `document`, `revision`.
- Edits: `apply_edits`, `rename_parameter`, `begin_transaction`, `set_focus`, `commit_transaction`, `cancel_transaction`, `undo`, `redo`, `apply_fix` (an offered `apply` action of a message or, with `FixRef::cause`, of its cause, as one batch labeled with the action's label; `stale_fix` when the revision differs or the latest statuses, or for a sketch finding the stored sketch's latest solution, no longer offer it), `set_document_units(doc, units, keep_sizes) -> UnitsChanged { revision, kept }` (the model's units edit set as one batch labeled `Change units to {symbol}`; the current units change nothing). Every `document_changed` carries `bare_numbers`; `count_bare_numbers(&Document) -> usize`, hidden from the documentation, is the count `document_changed` makes through the session's memoized inspections, there only so the budgets bench can time it alone.
- Sketches: `solve_sketch` (with the solve's messages: issues, then profile findings at `/profile_findings/{i}`; a solve of the stored sketch that ran in the latest recompute offers each finding's `Connect the ends` as an action, a candidate solve and one of a suppressed or rolled-back sketch offer none), `drag_sketch` (messages without actions), `end_sketch_drag` (a commit of a face sketch writes the placement the drag was placed at as its `fallback`, in the coordinates that keep the sketch's motion: body coordinates with `fallback_frame: body`, unless a fallback in world coordinates lies on a face that moved; one whose geometry did not change writes nothing).
- Queries: `feature_statuses` (each message with its actions, cause, detail, root and reason, and every repair with its description and candidates; display fields, ghosts among them, absent), `list_uses` (what every feature uses, from the document alone: its feature links and the features and sketch entities that generate the names of its stored references, sorted by timeline position, field, feature and entity), `parameter_values`, `evaluate`, `list_elements` (short references; a flat face's `fallback` and the `axis_direction` of a line edge or a cylinder, cone or torus face in body coordinates), `pick_reference` (full references with anchors and merged names; a headless pick names `mesh_id` 0, its `body` and its position in `list_elements` order), `resolve_references`, `measure`, `feature_catalog`, `engine_info`, `registry`.
- Print and output: `printer_profiles`, `put_printer_profile`, `printer_profile` (a document's resolved profile id), `set_tessellation`, `tolerance`, `analyze_print`, `export` (STL, 3MF, OBJ, STEP), `import_step`, `export_python`.
- Files without opening them: `validate` (a `ValidationReport` of `ValidationDiagnostic`s, which `ValidationDiagnostic::new` builds without a position or feature message; a feature message of the rebuild step carries its own code and a `FeatureMessage` with the feature, the projected message and its candidates) and `format` (the canonical text).
- Free items: `ptsm_schema`, `protocol_schema`, `ENGINE_VERSION`, `message_location(position, field)`, where a feature message is in the document (`/features/<position>` followed by its field), and `message_candidates(repairs, field)`, the candidates of a feature message among its feature's repairs (those of element repairs at or under its field, none without a field); `validate` reports both with each message, and hosts that read statuses use them too.
- Errors: `EngineError` with `code()`, `edit_index()`, `detail()` (the technical text: a load message, a parser's text, a panic message), `actions()` (`Finish "{label}" and {then}` for `TransactionOpen`) and `to_info()` for the protocol `ErrorInfo`; `EngineError::from_load` turns a model `LoadError` into `parse_error` or `unsupported_format_version`. `Parse` carries the line, column and JSON Pointer `validate` reports for the same text. `Internal` names its command (`apply edits`); an invariant failure a typed method reports names `this command`, and `execute` names its request's command.

## Internals

- `session.rs` owns `OpenDocument`s (`document.rs`, with the canonical text and params of a recipe); `editing.rs`, `sketching.rs`, `inspect.rs`, `analysis.rs`, `exchange.rs`, `python.rs`, `units.rs` and `fixes/` add `Session` methods per area; `units.rs` holds `set_document_units` and `OpenDocument::bare_numbers` (counted once per revision), both through the session's `Inspections` (`Inspections::count` is one counting pass, which `Session::count_bare_numbers` also runs); `inspections.rs` holds `Inspections`, the registry's inspection of feature records memoized by their content (id, kind and params) for the whole session, each count one pass after which the inspections used longest ago beyond 4096 go, so one edit inspects only the records it changed and a document opened again inspects none (`MemoizedInspector` reads them, falling back to the registry); `ids.rs` holds `NewIds`, the ids of the records a command creates (`NewBody`'s body, `ConnectEnds`' constraint, an import's body and feature) from the session's generator, never one the document or its feature params use (read through the memoized inspections) or one made before; `dispatch.rs` maps protocol commands to them and names the command of an internal error. `assets.rs` names assets by content hash and checks and stores the ones a document references. `error.rs` holds `EngineError`, its load error conversion and its wire form; `counts.rs` `saturating_u32`, the saturating conversion of the engine's `usize` counts and positions to the protocol's `u32` (buffer and triangle indices, element counts, edit and action indices, lines and columns).
- `state.rs` reads model, display and preview body states from the recompute report; a state is identified by (feature cache key, body id). It also selects the bodies an analysis or export works on (`select_bodies`) and tells a feature that ran, built or failed, from one suppressed, rolled back or not run (`ran`).
- `display.rs` builds element tables (which share the body state's topology, `BodyState::topology`, carried from the feature that built the state, so no kernel topology query, and build its element set, `BodyState::element_set`, so whatever builds the table pays for it once and every pick finds it built) and display meshes and keeps them in an LRU cache under the byte budget; `events.rs` diffs what a document last emitted against its current state to produce events.
- `elements.rs` builds descriptors: `describe` for a whole table (`list_elements`, computed once per table, one kernel geometry query per kind), `describe_element` for one element (`pick_reference`, one kernel query), both through the same `Describer` so a pick equals its listed entry. Names, adjacency, features and short references come from the table and its topology, never from `BodyState::elements`; `fallback` and `axis_direction` undo the motion the body state's naming map records for the face, or for an edge its first face term (its adjacent face with the smallest display id), each face's undoing motion found once per table and reused by its edges; `pick_reference` (`inspect.rs`) then stores the full reference, `Reference::from_element` against the element set of the table.
- `sketch.rs` and `triangulate.rs` turn solved sketches into `sketch_solved` displays with region fills and their messages (each solve issue and profile finding rendered by the sketch crate with the sketch's label, the solve's entities, measured values and dimension values, `solve_values` for a solve of a run: those its conflict error or redundancy warning carries; a finding's field is `finding_field`, `/profile_findings/{i}`, which `is_finding_field` tells from feature params); a sketch command's `invalid_params` error carries the sketch crate's message, rendered with the sketch's label, the params that raised it (a candidate's own) and the document units (`SketchWords`, whose `context` builds every `MessageContext` the engine renders sketch messages in: solutions, `invalid_params`, the constraint titles of fix labels and cause lines, and `validate`'s sketch step; `stored_drawing` reads a sketch record's drawing without validating it, and `point_entity` the entity of a point or generator); `sketching.rs` holds the sketch commands, the stored sketch's latest solution (`stored_solution`: its build output, or the engine's own solve when it failed), and the context a stored sketch is solved in (its dimension values and placement: where the latest run placed it when it built there on the same plane, else the engine's own resolution with the hint frame); a drag keeps the plane its commit writes (`commit_plane`: the placement the drag was placed at as the fallback, in the coordinates that keep the sketch's motion in the run that placed it). `frames.rs` holds frames on the model: placements and directions in body coordinates (`undoing`), a face sketch's motion (`sketch_motion`), the face plane a fix or a drag commit stores in the coordinates that keep that motion (`kept_face_plane`), a face sketch's hint (`placement_hint`) and the face placement rule on the flat face a reference resolves to (`face_placement`).
- `status.rs` derives feature statuses, parameter values and document diagnostics. `run.rs` holds `RunView`, a finished run with its names and its features in timeline order, and `FeatureView`, one feature of it. `diagnostics.rs` projects one feature message (section 3.4): `FeatureView::project` gives the protocol diagnostic and its repairs (the stored element and its candidates described in one `describe_elements` call with the faces the candidates keep, a kept face that is a candidate too only once), and `render_feature_error` renders a feature error with the document's names outside a run; `words.rs` gives repairs their words (regions by centroid, candidates by kept face and distance). `params.rs` reads and changes params by JSON Pointer, and finds the references they store (`stored_references`: objects with a `q` key, each with the `body` of the nearest object around it). `fixes/` is section 3.22: `mod.rs` the offers (`Offer`: label and run) and `apply_fix`, `labels.rs` each fix's label (by the words of the message's repairs, an attach's face described on its own when no repair lists it, and constraints by the titles the message gives them for the sketch's latest solve, `MessageContext::titles` of the constraints its fixes name), `findings.rs` the fixes of a stored sketch's profile findings (`offer_finding_fixes`: `Connect the ends ({gap} apart)` with the gap of the solved points, and its coincident constraint; `apply_fix` finds the finding by the exact field and code of its message), `edits.rs` the edits each fix builds from the current records (a new body named `Body {n}`, a constraint deleted or made a reference by its id, a key renamed, a move beside a feature found by id, `index_beside`; a cause's reverts build theirs with the same `index_beside`, `updated`, one `update_feature` of a record with its params changed, and `constraint_pointer`), with the re-anchoring of `KeepMatch` (the elements the feature's followed, guessed or widened warning stores, only the first in a field that holds one reference) and `KeepRegions` (the profile's regions now, and every reference a later feature stores whose resolution in the state just before it has a `via` that lists a succession key the old regions produced, stored as `KeepMatch` stores them; `apply_fix` resolves them in a recompute without the stop point and the rollback marker when later features did not run), `frames.rs` those of `Attach` (the sketch's current placement projected onto the face; `attach_keeps_motion` says when it is offered) and `TurnDrawingBack` (the drawing mirrored, then the regions and points of every feature that uses it as they read on the mirrored drawing, found by `params::visit_sketch_uses`: objects whose `sketch` key names it, and the references later features store to faces made from a point that now reads differently, renamed by `renames.rs`'s `PointRenames`), both with the fallback in the coordinates that keep the sketch's motion. `validate.rs` implements `validate` and `format`, validating each record once; its sketch step renders each solver issue with the sketch crate's message for that solve; its rebuild step projects feature messages like the statuses, at revision 0.
- `history.rs` holds `History`, the undo log with a serial per entry, the entry whose command made the latest change of the recipe (`latest_change`: the entry recorded or redone, or the open transaction's, whose serial `begin_transaction` reserves; none after an undo or a canceled transaction) and the count of commands that changed the recipe (`commands`: each change by another entry than the change before, and each undo or canceled transaction, so a transaction's edits count once). `causes/` is section 3.21: after every recompute `OpenDocument::observe` makes the recompute's `Baseline` (`baseline.rs`: the registry, the recipe, the features that ran, the printer values, the built sketches and the command count, shared by every feature that ran in it and by the ghosts; the timeline index, the dependency graph and the evaluated parameters are made the first time a cause reads them and kept with it, so each recipe's records are validated once however many causes compare it) and gives it to `Causes`, which keeps it per feature as its last run with its message keys, and leaves a `Tombstone` (label and position) for each feature that left the document; a key the feature did not have the last time it ran gets a cause made from that run's baseline (`made_cause` of their `Comparison`, built once per message with the features the message names): `changes.rs` compares the two recipes' graphs (`Graph`: links and body providers, `upstream` walked by timeline position, the parameters a feature uses, whether the units decide a size of it) into the changes that can reach the feature (records with their fields, sketch entities and constraints, construction and driving flags included), the primary one (groups 1 to 5) and the count of the others, a feature that moved being one off a longest common subsequence of the two timelines that keeps the message's feature (skipped when the timelines keep their order); `words.rs` words the change (`Evaluation` gives values on either side); `actions.rs` keeps the change's revert, `Show`, undo entry (only when one command made every change since the clean snapshot), clean placement and entity ghost (`MadeCause`) and makes the actions again from the current records each time statuses are made (`CauseLines`, which `feature_statuses` builds from the open document; reverts, `Keep the sketch where it was`, `Undo` while its entry is the newest and no transaction is open, `Show` when no revert is offered; one whose edits equal an action of the message that sets a field or a body, removes an entry, or suppresses, unsuppresses or moves a feature is left out, `fixes::offered_edits`). `commit_transaction` without a focus has `Emitted` send `recomputed` again when a cause of its entry offers `Undo` from then on. `ghosts.rs` is section 3.23: `Ghosts` keeps, in display sessions, each feature's last run (the recompute's baseline, the states before the feature and the pointers of its repairs) and captures from it the ghost of each reference or region lost since (`element_display` of what the stored reference resolved to in that run's state before the feature, or the region's outline as that run's solution had it, split like region fills with `triangulate.rs`'s `arc_points`), keeps it per feature and pointer while the loss lasts, and `add_to` sends it, and each cause's ghost, with the statuses of `recomputed` (repairs before causes in each status). `uses.rs` is section 3.24 (`list_uses`). `params::declared_dependencies` is a record's validated dependencies.
- `test_support.rs` (tests only): `box_session` and `id` for the unit tests. `tests/common` holds the acceptance tests' fixtures and request helpers (among them `begin`, `focus` and `commit` beside `apply`, and `typed_handle` for the typed methods); `benches/budgets.rs` includes it with `#[path]` and times only `Session::call`; of test 152's rows it times phase 1's `apply_fix` (the `SetField` of the lid fillet's largest radius) and parameter change that loses five references (a fillet on the third copy of the lid pattern, whose count it makes a parameter), and phase 3's `set_document_units` with `keep_sizes` (on the reference part with the lengths of its last five features written without a unit, so Keep sizes rewrites them and they build again) and `bare_numbers` after one edit (`Session::count_bare_numbers` of the 300-feature document with a new size in its last box, in a headless session that opened it, so every other record's inspection is reused), and phase 4's `list_uses` of the reference part and ghost capture of one lost edge (two cached `apply_edits` inside a transaction that end in the same state, one that loses an edge of the third lid and captures its ghost and one that keeps it, the sample their difference); the loss row checks that its message has a cause and its repairs ghosts. `tests/corpus` (a module of the test binary, beside `tests/common`, whose `mod.rs` re-exports its parts: `records.rs` the records and shared setups, `scenarios.rs` the corpus scenarios and the other edited documents the tests open, `newcomer.rs` the newcomer error corpus, `picks.rs`, `edits.rs` and `statuses.rs`, the readers) writes the scenarios of the reference stability corpus and the newcomer error corpus that tests 115 to 153 open as `.ptsm` texts, picks their setups' references in a headless session the way hosts pick them (`picked`: each feature focused, each element picked with `pick_reference`, each region from `solve_sketch`), applies their edits as one `apply_edits` (`after_edit`, through `apply_changes`) or in a transaction (`begin_edit`, `edited_in_a_transaction_focused_on`), and reads statuses, actions and repairs; `diagnostics_and_repairs.rs`, `references_and_validation.rs`, `fix_actions.rs`, `reference_causes.rs` (tests 136 to 140, the corpus twins' cause lines), `ghosts_uses_and_units.rs`, `newcomer_errors.rs` (test 150) and `frames_and_determinism.rs` (test 151) use it next to `common`, `fix_actions.rs`, `newcomer_errors.rs` and `ghosts_uses_and_units.rs` share its `opened` (a text opened, with its handle, reply and saved text), `fix_actions.rs`, `reference_causes.rs` and `newcomer_errors.rs` its `apply_as_one_entry`, `assert_undo_restores`, `assert_ok_without_messages` and `solution_messages`, and `fix_actions.rs` and `reference_causes.rs` its `assert_stale`; its `cause`, `labels_and_kinds` (compared with `owned_pairs`), `repair_ghost`, `ghost_points` and `assert_ghost_segments` read causes and ghosts.

## Commands

```sh
export OCCT_ROOT=/opt/occt/7.9.3/native
cargo test -p partsmith-engine
cargo test -p partsmith-engine --lib
cargo test -p partsmith-engine --test integration python_codegen::
cargo clippy -p partsmith-engine --all-targets -- -D warnings
cargo fmt -p partsmith-engine
# performance budgets of engine.md section 5 (release build); fails when one is over
cargo bench -p partsmith-engine --bench budgets
cargo bench -p partsmith-engine --bench budgets -- pick list   # only operations whose names contain a word
```

## Rules

- The single entry point for every host; hosts contain no modeling logic.
- Acceptance tests in `tests/` come from the spec; do not weaken them.
