# partsmith-engine

`Session`: open documents, apply commands, undo and redo, recompute, tessellate, export, analyze, generate Python.

Spec: `docs/spec/engine.md`.

## Public interface

- `Session::new(SessionOptions)`: the single entry point. `SessionOptions` sets the display flag, id generator (`SequentialIds` for tests), cache budget (`DEFAULT_CACHE_BUDGET`), undo limit and tessellation quality; `SessionOptions::headless()` (display off, `SequentialIds`) serves the CLI, Python and tests.
- Frames: `Session::call(&[u8]) -> Vec<u8>` decodes a PSM1 request frame and returns the response frame; `Session::execute(Request, buffers) -> Reply` does the same on decoded values. Each command runs on a snapshot and a panic poisons only its document.
- Documents: `new_document`, `open_document`, `save_document`, `mark_saved`, `close_document`, `document`, `revision`.
- Edits: `apply_edits`, `rename_parameter`, `begin_transaction`, `set_focus`, `commit_transaction`, `cancel_transaction`, `undo`, `redo`, `apply_fix` (an offered `apply` action as one batch labeled with the action's label; `stale_fix` when the revision differs or the latest statuses no longer offer it).
- Sketches: `solve_sketch`, `drag_sketch`, `end_sketch_drag` (a commit of a face sketch writes the placement the drag was placed at as its `fallback`, in the coordinates that keep the sketch's motion: body coordinates with `fallback_frame: body`, unless a fallback in world coordinates lies on a face that moved; one whose geometry did not change writes nothing).
- Queries: `feature_statuses` (each message with its actions, detail, root and reason, and every repair with its description and candidates; display fields absent), `parameter_values`, `evaluate`, `list_elements` (short references; a flat face's `fallback` and the `axis_direction` of a line edge or a cylinder, cone or torus face in body coordinates), `pick_reference` (full references with anchors and merged names; a headless pick names `mesh_id` 0, its `body` and its position in `list_elements` order), `resolve_references`, `measure`, `feature_catalog`, `engine_info`, `registry`.
- Print and output: `printer_profiles`, `put_printer_profile`, `printer_profile` (a document's resolved profile id), `set_tessellation`, `tolerance`, `analyze_print`, `export` (STL, 3MF, OBJ, STEP), `import_step`, `export_python`.
- Files without opening them: `validate` (a `ValidationReport` of `ValidationDiagnostic`s, which `ValidationDiagnostic::new` builds without a position or feature message; a feature message of the rebuild step carries its own code and a `FeatureMessage` with the feature, the projected message and its candidates) and `format` (the canonical text).
- Free items: `ptsm_schema`, `protocol_schema`, `ENGINE_VERSION`, `message_location(position, field)`, where a feature message is in the document (`/features/<position>` followed by its field), and `message_candidates(repairs, field)`, the candidates of a feature message among its feature's repairs (those of element repairs at or under its field, none without a field); `validate` reports both with each message, and hosts that read statuses use them too.
- Errors: `EngineError` with `code()`, `edit_index()`, `detail()` (the technical text: a load message, a parser's text, a panic message), `actions()` (`Finish "{label}" and {then}` for `TransactionOpen`) and `to_info()` for the protocol `ErrorInfo`; `EngineError::from_load` turns a model `LoadError` into `parse_error` or `unsupported_format_version`. `Parse` carries the line, column and JSON Pointer `validate` reports for the same text. `Internal` names its command (`apply edits`); an invariant failure a typed method reports names `this command`, and `execute` names its request's command.

## Internals

- `session.rs` owns `OpenDocument`s (`document.rs`, with the canonical text and params of a recipe); `editing.rs`, `sketching.rs`, `inspect.rs`, `analysis.rs`, `exchange.rs`, `python.rs` and `fixes/` add `Session` methods per area; `dispatch.rs` maps protocol commands to them and names the command of an internal error. `assets.rs` names assets by content hash and checks and stores the ones a document references. `error.rs` holds `EngineError`, its load error conversion and its wire form; `counts.rs` `saturating_u32`, the saturating conversion of the engine's `usize` counts and positions to the protocol's `u32` (buffer and triangle indices, element counts, edit and action indices, lines and columns).
- `state.rs` reads model, display and preview body states from the recompute report; a state is identified by (feature cache key, body id). It also selects the bodies an analysis or export works on (`select_bodies`).
- `display.rs` builds element tables (which share the body state's topology, `BodyState::topology`, carried from the feature that built the state, so no kernel topology query, and build its element set, `BodyState::element_set`, so whatever builds the table pays for it once and every pick finds it built) and display meshes and keeps them in an LRU cache under the byte budget; `events.rs` diffs what a document last emitted against its current state to produce events.
- `elements.rs` builds descriptors: `describe` for a whole table (`list_elements`, computed once per table, one kernel geometry query per kind), `describe_element` for one element (`pick_reference`, one kernel query), both through the same `Describer` so a pick equals its listed entry. Names, adjacency, features and short references come from the table and its topology, never from `BodyState::elements`; `fallback` and `axis_direction` undo the motion the body state's naming map records for the face, or for an edge its first face term (its adjacent face with the smallest display id), each face's undoing motion found once per table and reused by its edges; `pick_reference` (`inspect.rs`) then stores the full reference, `Reference::from_element` against the element set of the table.
- `sketch.rs` and `triangulate.rs` turn solved sketches into `sketch_solved` displays with region fills; `sketching.rs` holds the sketch commands and the context a stored sketch is solved in (its dimension values and placement: where the latest run placed it when it built there on the same plane, else the engine's own resolution with the hint frame); a drag keeps the motion of its stored face in the run that placed it, which its commit stores the placement with. `frames.rs` holds frames on the model: placements and directions in body coordinates (`undoing`), a face sketch's motion (`sketch_motion`), the face plane a fix or a drag commit stores in the coordinates that keep that motion (`kept_face_plane`), a face sketch's hint and the flat face a reference resolves to (`FlatFace`).
- `status.rs` derives feature statuses, parameter values and document diagnostics. `run.rs` holds `RunView`, a finished run with its names and its features in timeline order, and `FeatureView`, one feature of it. `diagnostics.rs` projects one feature message (section 3.4): `FeatureView::project` gives the protocol diagnostic and its repairs (the stored element and its candidates described in one `describe_elements` call with the faces the candidates keep, a kept face that is a candidate too only once), and `render_feature_error` renders a feature error with the document's names outside a run; `words.rs` gives repairs their words (regions by centroid, candidates by kept face and distance). `params.rs` reads and changes params by JSON Pointer, and finds the references they store (`stored_references`: objects with a `q` key, each with the `body` of the nearest object around it). `fixes/` is section 3.22: `mod.rs` the offers (`Offer`: label and run) and `apply_fix`, `labels.rs` each fix's label (by the words of the message's repairs; fixes whose edits later phases build are not offered), `edits.rs` the edits each fix builds from the current records, `frames.rs` those of `Attach` (the sketch's current placement projected onto the face; `attach_keeps_motion` says when it is offered) and `TurnDrawingBack` (the drawing mirrored, then the regions and points of every feature that uses it as they read on the mirrored drawing, found by `params::visit_sketch_uses`: objects whose `sketch` key names it, and the references later features store to faces made from a point that now reads differently, renamed by `renames.rs`'s `PointRenames`), both with the fallback in the coordinates that keep the sketch's motion, with the re-anchoring of `KeepMatch` (the elements the feature's followed, guessed or widened warning stores, only the first in a field that holds one reference) and `KeepRegions` (the profile's regions now, and every reference a later feature stores whose resolution in the state just before it has a `via` that lists a succession key the old regions produced, stored as `KeepMatch` stores them; `apply_fix` resolves them in a recompute without the stop point and the rollback marker when later features did not run). `validate.rs` implements `validate` and `format`, validating each record once; its rebuild step projects feature messages like the statuses, at revision 0.
- `test_support.rs` (tests only): `box_session` and `id` for the unit tests. `tests/common` holds the acceptance tests' fixtures and request helpers; `benches/budgets.rs` includes it with `#[path]` and times only `Session::call`; of test 152's rows it times phase 1's `apply_fix` (the `SetField` of the lid fillet's largest radius) and parameter change that loses five references (a fillet on the third copy of the lid pattern, whose count it makes a parameter), and its module documentation lists the rows phases 3 and 4 add. `tests/corpus` (a directory, so Cargo builds no test target of its own) writes the scenarios of the reference stability corpus and the newcomer error corpus that tests 115 to 153 open as `.ptsm` texts, picks their setups' references in a headless session the way hosts pick them (`picked`: each feature focused, each element picked with `pick_reference`, each region from `solve_sketch`), applies their edits as one `apply_edits` (`after_edit`), and reads statuses, actions and repairs; `diagnostics_and_repairs.rs`, `references_and_validation.rs`, `fix_actions.rs` and `errors_and_versions.rs` include it next to `common`. Each module documentation lists the tests later phases of the reference stability plan add.

## Commands

```sh
export OCCT_ROOT=/opt/occt/7.9.3/native
cargo test -p partsmith-engine
cargo test -p partsmith-engine --lib
cargo test -p partsmith-engine --test python_codegen
cargo clippy -p partsmith-engine --all-targets -- -D warnings
cargo fmt -p partsmith-engine
# performance budgets of engine.md section 5 (release build); fails when one is over
cargo bench -p partsmith-engine --bench budgets
cargo bench -p partsmith-engine --bench budgets -- pick list   # only operations whose names contain a word
```

## Rules

- The single entry point for every host; hosts contain no modeling logic.
- Acceptance tests in `tests/` come from the spec; do not weaken them.
