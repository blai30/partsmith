# partsmith-features

`Feature` trait, `Registry`, `BuildContext`, `FeatureOutput`, and the built-in features (sketch, extrude, revolve, fillet, chamfer, shell, hole, primitives, booleans, patterns, mirror, datums, and more).

Spec (the definition of done): `docs/spec/features.md` and `docs/spec/features/<type>.md`. Acceptance tests in `tests/` come from features.md sections 6.2 and 6.3; document tests of section 6.4 and of every feature spec live in `crates/partsmith-recompute/tests/`. Do not weaken them.

## Public interface

The modules of features.md section 2.1 are public: `feature`, `deps`, `params`, `context`, `output`, `error` (errors, warnings and message parts), `registry` (with `register_builtins`), `python` and `builtin` (one module per type). The crate root re-exports everything below.

- Constants: `VERSION`, `FEATURE_API_VERSION`, `OCCT_VERSION` (re-exported). Manifest types re-exported from `partsmith_model::manifest`: `FeatureManifest`, `Category`, `FieldHint`, `FieldUnit`, `SelectionKind`, `OptionHint`.
- Contract: `Feature` (with provided `validate` and `python`), `DynFeature`, `Dependencies` (`Link`, `AssetLink`, `ExprUse`; helpers `add_feature`, `add_body_read`, `add_body_written`, `add_expression`, `add_asset`, `add_plane`, `add_axis` keep the no-duplicate rules).
- Shared params: `BodyOp`, `CopyOp` (`is_default`), `ProfileRef`, `PlaneRef` (`Default` is origin XY, `is_default`), `AxisRef`, `OriginAxis`, `PlacementExt` on `partsmith_sketch::Placement` (`offset`, `flipped`, `local_to_world`, `to_kernel`), and `point` and `vector` (kernel `Point` and `Vector` of `[f64; 3]`). Primitives share `PrimitivePlacement` (`add_dependencies`, `frame`, `python_keywords`, `hints`) with `default_position` and `is_default_position` (section 3.14).
- Context: `BuildContext::new(BuildInputs)` with `feature`, `units`, `field` (a `FieldRef` labeled from the manifest), `eval_length/angle/scalar`, `eval_count(field, expr, minimum)` (checks the minimum, then the u32 range, then the whole number, so every suggested fix works; patterns pass 1), `body`, `sketch`, `datum`, `asset`, `profile`, `resolve`, `resolve_all`, `plane`, `face_placement` (the face placement rule with a caller's hint; the inner `Err` is a `FallbackReason` for an empty body, a missing or ambiguous reference or a face that is not flat), `axis`, `is_canceled`. `Values::evaluate` and `iter`; `BodyState` (`empty`, `new`, `shape`, `naming`, `is_empty`, and `elements` and `volume`, each cached and shared by clones; `apply_op` and hole read the body's volume through it); `Resolved`; `ResolvedProfile` with `faces()` (the union of the resolved regions as kernel faces, `ProfileFaces { profile, entities }` where curve tag `i` is `entities[i]`); `CancelToken`.
- Output: `FeatureOutput`, `OutputData`, `BodyUpdate`, `BodyChange`, `SketchResult` (`point`, `to_world`), `DatumResult`, `Tool`, `VOLUME_TOLERANCE` (1e-9, the relative volume of the body rules), and `apply_op` (the body semantics of section 3.5 with the boolean naming rule). `apply_op` passes every tool to one kernel `fuse`, `cut` or `common` call (intersect keeps what lies inside every tool), fuses several tools for op new, and returns `Internal` without tools.
- Naming bridge: `topology_info` (kernel topology and fingerprints for `partsmith_naming`), `name_shape`, `modified_sources`, `name_by_history` (the boolean rule with the `<feature>/face` fallback).
- Messages: `FeatureError` (with `internal(message)` and `From<KernelError>`, which gives `Kernel { error }` so `?` works on kernel calls) and `FeatureWarning` (`render`, `code`, `field`, `suggestion`, `repair`; `Display` renders with ids and millimeters), `FieldRef` (`new`, `pointer`), `Bound`, `Noun`, `IgnoredReason`, `FallbackReason`, `Repair`, `Names`, `DocumentNames`, `format_value`. `too_large_search` is the bisection of section 4.3.
- Registry: `Registry` (`new`, `with_builtins`, `register`, `register_dyn`, `get`, `types`, `validate_and_canonicalize`, `params_schemas`, `dependencies`, `build`, `python`, `python_generic`, `label`, and `FeatureInspector`), `Canonical`, `Validated`, `RegistryError`, `register_builtins`.
- Python: `PythonCall` (`new`, `render`), `PythonValue` (`from_json`, `expression`, `length`, `angle`, `reference`, `region`, `plane`, `axis`, `render`), `PythonNames`.

## Internals

- `deserializer.rs` reads typed params straight from the JSON map with its own serde error type, so `InvalidParams` details name the deepest field path without parsing serde messages. Unknown root keys are the input keys the params schema does not know: `schema::known_keys` collects the root `properties` and those of every root `$ref`, `anyOf`, `oneOf` and `allOf` branch, so the fields of a flattened enum are known keys, reserved-name checked and need hints.
- `schema.rs` holds the registration checks (open object root, reserved keys, `$defs` conflicts, manifest against schema through `$ref`, `anyOf`, `oneOf`, `allOf`, `items` and `prefixItems`).
- `profile.rs` builds the region union by dropping boundary pieces that two selected regions share (matched exactly, both directions) and chaining the rest through the arrangement's own loop successors; components (joined by shared pieces) give one outer loop each. `merge_pieces` then joins consecutive pieces of a loop (the last and the first included) that come from one entity, run the same way and meet exactly, into one line or arc; a loop that is one entity all the way round becomes its circle. Pieces of an entity with another piece between them stay separate (naming numbers them `#n`).
- `error/` holds `FeatureError` (`mod.rs`), `FeatureWarning` (`warning.rs`), `FieldRef` and field paths (`field.rs`), and the message parts (`message.rs`: names, `format_value`, and the suggested-limit text, which cuts two significant digits from the shortest decimal form so it never exceeds the value).
- `test_support.rs` (tests only) has a `Fixture` that owns a context's inputs, named box and primitive tools, `ScriptNames` for Python hooks, and helpers that build a feature from JSON params over a `Fixture` without a timeline (`params`, `params_with`, `fixture`, `build`, `updates`, `update`, `updated_shape`, `assert_volume`, `assert_bounds`, `python`, `python_with`). Unit tests cover what a feature computes on its own; whole documents of built-in features are tested in `partsmith-recompute`.
- `tests/common/mod.rs` has the `Probe` and `Slab` test features, `ContextFixture`, and `built_body`, which builds a solid record of the built-in registry (a box or a cylinder of the feature specs) into a body state.
- `tests/budgets.rs` times the framework budgets of features.md section 5 with `std::time::Instant` in release builds; the `BodyState::elements` budget of a 200-face body is ignored while the kernel's `Shape::elements(Face)` alone is over it.

## Built-in features

Each type lives in `src/builtin/<type>.rs` and is registered by adding `Registry::register::<Type>` to `BUILTINS` in `src/builtin/mod.rs`. All 20 types of features.md section 3.13 are registered, so the acceptance tests that need them run by default.

Registered types:

- Primitives (features.md section 3.14): `box` (`BoxFeature`, since `Box` is the standard library's pointer), `cylinder` (`Cylinder`), `sphere` (`Sphere`), `cone` (`Cone`), `torus` (`Torus`). Each params struct puts its sizes first, then the shared `plane` and `position` (`PrimitivePlacement`), then `op`; sizes are checked in field order before any kernel work, a size below `LINEAR_TOLERANCE` (1e-6 mm) being `OutOfRange` (`GreaterThan(0)`) like 0 (`primitives::positive_size`), faces are named `<feature>/<role>` from the kernel's `PrimitiveFace` roles (`common::primitive_tool`), and the tool goes through `apply_op`. The box shifts the kernel's corner-anchored frame by half its length and width; a cone treats a radius below `LINEAR_TOLERANCE` (1e-6 mm) as an apex and builds a kernel cylinder when its radii differ by less than that.
- Sketch-based features (features/sketch.md, datum_plane.md, extrude.md, revolve.md, hole.md): `sketch` (`SketchFeature`, params `partsmith_sketch::SketchParams`, no Python hook because the engine writes sketch blocks), `datum_plane` (`DatumPlane`), `extrude` (`Extrude`, with `ExtrudeExtent`), `revolve` (`Revolve`, with `RevolveExtent`) and `hole` (`Hole`, with `HoleType` and `HoleExtent`). A sketch on a face is placed by `BuildContext::face_placement` with its stored fallback as the hint, and keeps that fallback with a `PlaneFallback` warning when the body is empty or the face is missing, ambiguous or not flat; it evaluates only driving dimensions and maps the solver's result to `SketchInvalid`, `SketchConflict`, `SketchNotSolved` or a `RedundantConstraints` warning. Extrude and revolve sweep `ResolvedProfile::faces()` and name the tool with `common::sweep_tool`; through all goes 1 mm past the farthest bounding box corner along the direction (`common::farthest_corner` and `common::THROUGH_ALL_MARGIN`, shared with hole, decision D21). Revolve checks that the axis lies in the sketch plane and that the profile stays on one side of it on the sketch regions, before any kernel work, and treats an angle within 1e-9 rad of 360 deg as a full turn. Hole evaluates and checks the diameter, then the depth, then the head, then the tip, and requires a head to end at least `LINEAR_TOLERANCE` above the shoulder (`ends_above_shoulder`), reporting the bounds the user typed (the depth, or the head diameter whose cone ends at it). It builds one tool per distinct point by revolving a half cross-section in the plane of the sketch x axis and the drilling direction, its segments tagged by role (`entry`, `counterbore`, `counterbore-floor`, `countersink`, `bore`, `bottom`, `tip`, and the axis segment, which sweeps no face); a point whose tool shares at most `VOLUME_TOLERANCE` of the body's volume gets `HoleMissesBody`, and the other tools are cut with one `apply_op`. The body's bounding box is read once; a tool whose box misses it shares nothing, and the shared volumes of the others come from one kernel `common` with the compound of all of them when their boxes are more than `LINEAR_TOLERANCE` apart (each solid of the result counts for the tool whose box is nearest to its center), else from one `common` per tool (`shared_volumes`). Tools apart from each other thus cost two booleans on the body (the `common` and the cut) whatever their number; on bench50's 414-face body one `common` takes about 55 ms. A through-all hole is max(F, h) + 1 mm long, with F the farthest corner distance and h the head depth, so a head deeper than the body still leaves a bore below it.
- Dress-up (features/fillet.md, chamfer.md, shell.md): `fillet` (`Fillet`), `chamfer` (`Chamfer`, with `ChamferDistance` tagged `equal` or `two_distances`) and `shell` (`Shell`). They share `dressup.rs`: `select_edges` resolves `edges` and skips smooth edges with an `Ignored` warning (fewer than two faces in the kernel topology, as at a seam, or two faces whose outward normals at the edge's middle from kernel `Shape::edge_normals` differ by at most 1e-6 rad, on every surface type; a knife edge, with opposite normals, and an edge the query rejects as invalid input, where a face has no defined normal, have a corner), `run_or_search` calls the kernel and runs the "too large" search on any failure except invalid input, and `add_origins` turns kernel history into the face origins that `name_blend` and the shell's naming map to names (naming.md sections 3.6.5 to 3.6.7). A chamfer passes its edges to the kernel sorted by element name in byte order, so the order of `edges` never matters (the kernel takes the side of a tangent chain from its first edge), and a two-distance chamfer measures `expr` on the face of each edge whose name sorts first (`flip` swaps the distances). Shell hollows each solid of the body with its own removed faces (a solid without any becomes a closed hollow) and combines several results with the kernel's `compound`, mapping each solid's history through `Shape::locate`.
- Body features (features/boolean.md, mirror.md, linear_pattern.md, circular_pattern.md, move_body.md, split_body.md, import.md): `boolean` (`Boolean`, with `BooleanOp`), `mirror` (`Mirror`), `linear_pattern` (`LinearPattern`, with `LinearPatternDirection`), `circular_pattern` (`CircularPattern`), `move_body` (`MoveBody`, with `MoveBodyRotation`), `split_body` (`SplitBody`) and `import` (`Import`). `boolean` checks the target and every tool body for a solid, then calls `apply_op` with one `Tool` per tool body (its shape and a copy of its naming map), which makes one kernel `fuse`, `cut` or `common` call; consumed tools get `Clear` updates even when the operation had no effect. The copy features share `copy.rs`: `validate_target` and `add_source`/`add_target` for `op` and `target`, `check_instance_limit` (at most 10000 instances, the original included; patterns read their counts with `eval_count(..., 1)`), `check_canceled` between copies, and `Source` (`new` checks the source holds a solid), whose `copy` transforms the source and names it with `NamingMap::with_instance` and whose `place` combines every copy with one `apply_op` (join into the source, new into the target). With op new a target that holds a solid is `BodyNotEmpty` at any count, with or without copies; without copies (count 1) the source keeps an unchanged `Join` update, or the still empty target gets none, with a `NoEffect` warning. `move_body` carries the input naming map over unchanged and reports `NoEffect` with an unchanged `Modify` update when nothing moves. `split_body` needs a solid above `VOLUME_TOLERANCE` of the body's volume on each side, names the whole kernel split once (section faces by side, other faces by history) and gives each body the projection of that map onto its solids through `Shape::locate`. `import` names every face `<id>/face` (numbered `#n` in geometric order) and has no dedicated Python form. Nested param structs use `deny_unknown_fields` so an unknown key inside them is reported instead of dropped.

## Commands

```sh
cargo test -p partsmith-features
cargo clippy -p partsmith-features --all-targets -- -D warnings
cargo fmt -p partsmith-features
# performance budgets (features.md section 5), release builds only
cargo test -p partsmith-features --release --test budgets
```

The kernel facade needs an OCCT install: `export OCCT_ROOT=/opt/occt/7.9.3/native`.

## Rules

- Built-in features use only the public API, like a plugin would (features.md section 2.11): `?` on kernel calls (`From<KernelError>`), `FeatureError::internal`, `point`, `vector`, `BuildContext::face_placement` and `VOLUME_TOLERANCE` are public for that, and items of private modules are imported from the crate root (`crate::name_shape`, `crate::PrimitivePlacement`). `builtin/common.rs` holds what the built-ins share and uses only public items, including `out_of_range` (an `OutOfRange` whose message bound differs from the rule's) and `naming_failed` (a `NamingError` as `Internal`). Only the dress-up files `dressup.rs` and `shell.rs` still map kernel errors with the crate-private `naming::kernel`, which goes once they use `?`.
- Every registered feature needs an example in `examples/`.
- `FeatureError` keeps the payload types the spec gives, so the crate expects `clippy::result_large_err` (see `lib.rs`).
