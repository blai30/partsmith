# partsmith-occt-sys

C++17 shim over OCCT 7.9.3 exposed with `cxx`, plus the safe Rust facade over it: plain values and immutable `Shape` handles in, new shapes with history and face roles out. The only crate with C++ and `unsafe`.

Spec: `docs/spec/kernel.md` (the definition of done). Acceptance tests in `tests/` come from its section 6; do not weaken them. Requires an OCCT install from `scripts/build-occt.sh`, found through `OCCT_ROOT_<TARGET>` (for example `OCCT_ROOT_WASM32_UNKNOWN_EMSCRIPTEN`) or `OCCT_ROOT`.

## Public interface (crate root)

- Constants: `OCCT_VERSION` (`"7.9.3"`, part of recompute cache keys), `LINEAR_TOLERANCE` (1e-6 mm).
- Values: `Point`, `Point2`, `Vector`, `Axis`, `Plane` (`XY`, `XZ`, `YZ`, `y_axis`, `to_world`), `Transform` (`IDENTITY`, `translation`, `rotation`, `mirror`, `scale`, `then`, `apply_point`, `apply_vector`), `Color` (sRGB components).
- `Shape` (cheap clone, `Send + Sync`): `empty`, `kind`, `count`, `is_empty`, `solids`, `locate`, `is_valid`, `volume`, `area`, `center_of_mass`, `bounding_box`, `element`, `elements`, `topology`, `edge_normals`, `tessellate` (into `partsmith_mesh::Mesh`), `to_brep`, `from_brep`. Sub-shapes are `SubShape { kind: SubShapeKind, index }` with 1-based `TopExp::MapShapes` indices; `ShapeKind` is the kind of a whole shape.
- History: `OpResult { shape, history }`, `History` (`modified_from`, `generated_from`), `InputHistory`, `ElementFate` (`is_deleted`), `Origin`.
- Primitives: `make_box`, `make_cylinder`, `make_sphere`, `make_cone`, `make_torus` return `Primitive { shape, faces: Vec<PrimitiveFace> }`.
- Profiles: `make_profile(plane, regions)` from `PlanarRegion`, `PlanarLoop`, `TaggedCurve` and `PlanarCurve` returns `PlanarProfile` with the tag of every edge.
- Sweeps: `extrude` and `revolve` return `SweepResult { shape, faces: Vec<SweepFace> }`.
- Operations on shapes, all returning `OpResult`: `fuse`, `cut`, `common` (history inputs `[target, tools...]`, coplanar faces unified), `fillet` (`EdgeRadius`), `chamfer` (`ChamferEdge`, `ChamferSize`), `shell`, `transform`, `compound`; `split` returns `SplitResult` (`PlaneSide`, `SectionFace`); `section` returns a compound of edges.
- Element queries: `ElementGeometry`, `GeometryKind`, `Topology` with `FaceTopology`, `EdgeTopology` and `VertexTopology`; `EdgeNormals { point, tangent, faces, continuity }` with one `FaceNormal { face, normal }` per face containing the edge, in ascending face order, and the `Continuity` (`C0` or `G1OrBetter`) recorded between the edge's two faces, or across a seam (spec section 3.6, item 5; fillet.md uses it for its smooth-edge rule).
- STEP: `write_step` and `read_step` with `StepBody` and `StepImport`.
- Errors: `KernelError { operation, kind, exception, message }` with `user_message()` (also its `Display`), `KernelErrorKind`, `Operation` (displayed in snake_case).

## Internals

- `src/ffi.rs` is the cxx bridge (shared structs and flat index arrays). Each `src/<area>.rs` checks its arguments in Rust first (spec sections 3.1 and 4.2), calls the shim through `error::call`, and converts the result; `error.rs` classifies the shim's `"<exception>: <message>"` text.
- `cpp/shim.h` declares the C++ `Shape` (the shape plus its four const index maps), the exception-translating `trycatch` and the `Partsmith_*` exceptions; `cpp/internal.h` holds helpers shared by the sources. Sources by area: `primitives`, `profiles`, `sweeps`, `booleans`, `blends` (fillet, chamfer, shell), `transforms` (transform, split, section, compound), `queries`, `mesh`, `exchange` (STEP, BRep, one-time initialization, the STEP mutex) and `history` (history normalization, copies, validity check and repair).
- Verified on the built library by tests (`tests/blends.rs`, `src/blends.rs`): fillet and chamfer faces are generated by their edges and corner faces by their vertices; shell rims are the removed faces' `modified` images, inner faces the kept faces' `generated` images, and arc joins are generated by the concave edge or vertex. OCCT's own history meets spec 3.4.9 without augmentation.
- Profiles and sweeps store the curves of edges on planar faces (`store_plane_pcurves`). OCCT keeps none for planes and projects them again on every use, which made validity checks, element queries and later operations on profile-based solids up to a quarter slower. Only shapes an operation built itself are touched, since storing writes to the edges.
- Sizes that must be positive (primitive dimensions, cone radius difference, fillet radii, chamfer distances, shell thickness) must be at least `LINEAR_TOLERANCE` (`values::is_positive_length`), and a revolve angle must exceed the angular tolerance: OCCT rejects smaller ones with generic exceptions or builds degenerate solids.
- Split: the splitter merges an input face lying on the plane with the tool, so tool images that are also an input face's image are not section faces.
- `from_brep` rejects bytes that do not start with the header `to_brep` writes before calling `BinTools::Read`, which otherwise prints to standard output past the messenger. `tests/exchange.rs` (`standard_streams`) reruns its test binary in a child process to check that the kernel writes nothing to either standard stream.
- Shell without removed faces: OCCT's `MakeThickSolid` returns only the inner offset solid when there are no closing faces, so the shim offsets with `BRepOffsetAPI_MakeOffsetShape` (same parameters) and builds the hollow solid from the input's shell and the reversed inner shell.
- Shell order (spec section 3.4.8, item 5): OCCT's offset assembles shells from maps keyed by shape addresses, so the face order of closed hollows and of shells with arc joins changed from run to run, with every index, the BRep bytes and the last bits of the volume. `checked_shell` rebuilds the returned solids and shells with faces ranked by the input elements they come from (`ordered_by_input`), keeping faces, edges and vertices so the history still applies, and stores the two surfaces of each edge's continuity record in result face order (`order_continuity_records`; the offset records them in map order too, which changed only the BRep bytes). Every other operation was repeatable in one process and across processes; tests 104 to 107 (`tests/determinism_and_concurrency.rs`) run each operation 4 times with other allocations in between and in two child processes.
- Validity (spec section 3.5, `ChangeCheck` in `cpp/history.cpp`): `ensure_valid` runs the checks of `BRepCheck_Analyzer` only on faces of the result that are not faces of the operation's inputs (by `IsSame`), with their wires, edges and vertices (edges and vertices also in the context of every face and edge holding them, including unchanged neighbors), and on shells and solids that are not an input's; with no input face in the result it runs the analyzer on the whole. Inputs are the boolean's target and tools, the copy for fillet, chamfer and shell, and split's input, whose pieces are checked before being copied apart (repair then runs on the copies, since `ShapeFix_Shape` merges solids sharing a face). Repair checks the whole repaired result. Faces kept unchanged are trusted, so an invalid solid that `read_step` kept can pass its invalid parts through (test 111). `tests/common` builds such an input by moving a vertex in BRep bytes (`box_with_displaced_corner`).
- Topology (`shape_topology`): one walk over the faces and one over the edges with `TopoDS_Iterator` (`TopExp_Explorer` allocates), the inverse relations by a stable counting sort, and `BRep_Tool::IsClosed` only for edges with a closed curve representation. Test 112 checks that every relation agrees with its inverse.
- Tessellation names `IMeshTools_MeshAlgoType_Delabella` (spec section 3.7, item 2): OCCT's default Watson mesher inserts each face's nodes one by one and took 11 to 12 s on a sphere of radius 250 at the engine's resin tolerance and on `PLATE` at 0.05 mm, where Delabella takes about 1 s; naming an algorithm also stops OCCT reading `CSF_MeshAlgo` from the environment (test 113). Changing the mesher changes meshes and the examples' expected print results (spec section 7, open issue 8).
- Shell attempts (spec section 3.4.8, `cpp/blends.cpp`): each attempt (closed hollow, thick solid, cavity cut) returns its shape and history, and `checked_shell` rejects it when it is invalid after repair, holds no solid, removes no material, or has an inner face that is not at the wall thickness from the kept face it was generated from (OCCT turns a convex face's offset inside out when the wall is thicker than its radius and returns a wrong solid). When the thick solid fails and a removed face meets a kept face at a concave edge (`BRepOffset_Analyse`, which only reads, run on the input so nothing is copied when the fallback does not apply), where OCCT's join offset cannot close the wall and returns the input unchanged, the shim retries on a fresh copy: the cavity is `BRepOffset_MakeOffset` with `GeomAbs_Intersection` and offset 0 on the removed faces, and the result is the solid minus the cavity (`run_boolean`, shared with `booleans.cpp`, without unification). The offset's history (cavity elements generated from input elements) merged with the cut's gives spec 3.4.9 without augmentation, including the wall bottom in the removed face's `generated` list. If the retry fails too, the first attempt's error is reported. A removed face meeting a concave fillet tangentially is not handled (spec open issue 7).
- Face area and centroid (`face_mass` in `cpp/queries.cpp`): planes bounded by lines and circular arcs in the parameter plane and cylinders bounded by lines are integrated exactly from their boundary (Green's theorem with one field per integral; an arc is its chord plus a circular segment); other faces use `BRepGProp::SurfaceProperties`. `BRepGProp` spends 18 x 18 integration points on every boundary edge: `elements` plus `topology` of `PLATE` (spec section 5) took 28.5 ms, of which 25.9 ms were faces, and now take 2.6 ms (faces 0.3 ms, `topology` 1.8 ms). The exact results match `BRepGProp` within 2e-14 relative on planes, cylinders, holes, arcs, fillets, mirrored and located shapes. `area()` uses the same function, so it equals the sum of the face measures.
- Edge normals take the surface parameters from the edge's curve on each face (projection only when there is none) and the normal from `BRepLProp_SLProps`, reversed for reversed faces; the faces are found by scanning the face map, so the order is ascending like `topology()`.
- Defensive branches no test reaches through the public API: in `normal_at_edge` (`cpp/queries.cpp`), the projection (valid shapes have a curve on every non-planar face for each of its edges, and `BRep_Tool::CurveOnSurface` computes one on planes) and `has no defined normal`; in `shape_edge_normals`, `has no direction at its middle` (profiles have only lines, arcs and circles, and the singular points of primitives, the cone apex and the sphere poles, are vertices, so no edge has its middle there); in `require_wall_thickness` (`cpp/blends.cpp`), a projection that finds no point (projection on an untrimmed analytic surface always finds one). Only an imported solid that stays invalid after repair, or imported B-spline geometry, could reach them.

## Commands

```sh
cargo test -p partsmith-occt-sys
cargo clippy -p partsmith-occt-sys --all-targets -- -D warnings
cargo fmt -p partsmith-occt-sys
# WebAssembly, run under Node (needs the activated Emscripten SDK and the wasm OCCT install)
source /opt/emsdk/emsdk_env.sh && cargo test -p partsmith-occt-sys --target wasm32-unknown-emscripten
cargo bench -p partsmith-occt-sys --bench budgets            # spec section 5 budgets; fails when one is over
cargo bench -p partsmith-occt-sys --bench budgets -- step    # only the operations whose names contain a word
```

The WebAssembly tests need OCCT built for wasm without `OCC_CONVERT_SIGNALS`. OCCT's CMake defines it on every non-MSVC build; with Emscripten 4.0.15 and `-fwasm-exceptions`, the `setjmp` it places inside `try` blocks makes the compiler emit invalid code for `ShapeUpgrade_ShapeDivide.cxx` and `ShapeCustom_BSplineRestriction.cxx` (V8: `br_table: label arity inconsistent`), and every test binary fails to instantiate. Signals never reach wasm code and the shim never calls `OSD::SetSignal`, so the wasm build should pass `-UOCC_CONVERT_SIGNALS` in its C and C++ flags.

## Rules

- Every `unsafe` block or impl has a `// SAFETY:` comment; the only `unsafe` code is the bridge's `unsafe extern "C++"` block and the `Send` and `Sync` impls of `Shape`.
- Every bridge function that can fail returns `Result`; nothing throws across the boundary. No C++ type appears in the public API.
- No facade function modifies an input shape: algorithms that may write to their inputs run on copies, booleans run non-destructively.
- The shim never prints, never installs signal handlers, never reads environment variables and never writes files.
