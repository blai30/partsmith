# partsmith-occt-sys

C++17 shim over OCCT 7.9.3 exposed with `cxx`, plus the safe Rust facade over it: plain values and immutable `Shape` handles in, new shapes with history and face roles out. The only crate with C++ and `unsafe`.

Spec: `docs/spec/kernel.md` (the definition of done). Acceptance tests in `tests/` come from its section 6; do not weaken them. Requires an OCCT install from `scripts/build-occt.sh`, found through `OCCT_ROOT_<TARGET>` (for example `OCCT_ROOT_WASM32_UNKNOWN_EMSCRIPTEN`) or `OCCT_ROOT`.

## Public interface (crate root)

- Constants: `OCCT_VERSION` (`"7.9.3"`, part of recompute cache keys), `LINEAR_TOLERANCE` (1e-6 mm).
- Values: `Point`, `Point2`, `Vector`, `Axis`, `Plane` (`XY`, `XZ`, `YZ`, `y_axis`, `to_world`), `Transform` (`IDENTITY`, `translation`, `rotation`, `mirror`, `scale`, `then`, `apply_point`, `apply_vector`), `Color` (sRGB components).
- `Shape` (cheap clone, `Send + Sync`): `empty`, `kind`, `count`, `is_empty`, `solids`, `locate`, `is_valid`, `volume`, `area`, `center_of_mass`, `bounding_box`, `element`, `elements`, `topology`, `edge_normals`, `tessellate` (into `partsmith_mesh::Mesh`), `to_brep`, `from_brep`. Sub-shapes are `SubShape { kind: SubShapeKind, index }` with 1-based `TopExp::MapShapes` indices; `ShapeKind` is the kind of a whole shape.
- History: `OpResult { shape, history }`, `History` (`modified_from`, `generated_from`), `InputHistory`, `ElementFate` (`is_deleted`), `Origin`.
- Primitives: `make_box`, `make_cylinder`, `make_sphere`, `make_cone`, `make_torus` return `Primitive { shape, faces: Vec<PrimitiveFace> }`.
- Profiles: `make_profile(plane, regions)` from `PlanarRegion`, `PlanarLoop`, `TaggedCurve` and `PlanarCurve` returns `PlanarProfile` with the tag of every edge.
- Sweeps: `extrude` and `revolve` return `SweepResult { shape, faces: Vec<SweepFace> }`.
- Operations on shapes, all returning `OpResult`: `fuse`, `cut`, `common` (history inputs `[target, tools...]`, coplanar faces unified), `fillet` (`EdgeRadius`), `chamfer` (`ChamferEdge`, `ChamferSize`), `shell`, `transform`, `compound`; `split` returns `SplitResult` (`PlaneSide`, `SectionFace`); `section` returns a compound of edges.
- Element queries: `ElementGeometry`, `GeometryKind`, `Topology` with `FaceTopology`, `EdgeTopology` and `VertexTopology`; `EdgeNormals { point, tangent, faces, continuity }` with one `FaceNormal { face, normal }` per face containing the edge, in ascending face order, and the `Continuity` (`C0` or `G1OrBetter`) recorded between the edge's two faces, or across a seam (spec section 3.6, item 5; fillet.md uses it for its smooth-edge rule).
- STEP: `write_step` and `read_step` with `StepBody` and `StepImport`.
- Errors: `KernelError { operation, kind, exception, message }` with `user_message()` (also its `Display`), `KernelErrorKind`, `Operation` (displayed in snake_case).

## Internals

- `src/ffi.rs` is the cxx bridge (shared structs and flat index arrays) with the decoders of its flat lists (`triples`, `split_at_offsets`). Each `src/<area>.rs` checks its arguments in Rust first (spec sections 3.1 and 4.2), calls the shim through `error::call`, and converts the result; `error.rs` classifies the shim's `"<exception>: <message>"` text.
- `cpp/shim.h` declares the C++ `Shape` (the shape plus its four const index maps), the exception-translating `trycatch` and the `Partsmith_*` exceptions; `cpp/internal.h` declares the helpers shared by the sources, grouped by the source that defines them, and the header-only ones for OCCT algorithms (`require_no_errors`, `set_boolean_options`, `history_of`). Sources by area: `shape` (the `Shape` constructor and maps, conversions, exceptions, compounds and copies), `primitives`, `profiles`, `sweeps`, `booleans`, `blends` (fillet, chamfer, shell), `transforms` (transform, split, section, compound), `queries` (indexing, validity, bounds, element geometry, topology, edge normals), `measure` (volume, area, center of mass, face area and centroid), `mesh`, `exchange` (STEP, BRep, one-time initialization, the STEP mutex), `validity` (input state, validity check and repair) and `history` (history normalization).
- Verified on the built library by tests (`tests/blends.rs`, `src/blends.rs`): fillet and chamfer faces are generated by their edges and corner faces by their vertices; shell rims are the removed faces' `modified` images, inner faces the kept faces' `generated` images, and arc joins are generated by the concave edge or vertex. OCCT's own history meets spec 3.4.9 without augmentation, except for the wall ends of tangent openings, which the shim records (below).
- Profiles and sweeps store the curves of edges on planar faces (`store_plane_pcurves`). OCCT keeps none for planes and projects them again on every use, which made validity checks, element queries and later operations on profile-based solids up to a quarter slower. Only shapes an operation built itself are touched, since storing writes to the edges: booleans, fillet, chamfer and shell store them on their results too (spec section 3.5 item 5), whose edges belong to the copies they ran on or are new, after `CheckInputs::settle` has fixed which input faces the operation changed (`store_result_pcurves`); split, whose pieces share the input's edges, does not.
- Sizes that must be positive (primitive dimensions, cone radius difference, fillet radii, chamfer distances, shell thickness) must be at least `LINEAR_TOLERANCE` (`values::is_positive_length`), and a revolve angle must exceed the angular tolerance: OCCT rejects smaller ones with generic exceptions or builds degenerate solids.
- Split: the splitter merges an input face lying on the plane with the tool, so tool images that are also an input face's image are not section faces.
- `from_brep` rejects bytes that do not start with the header `to_brep` writes before calling `BinTools::Read`, which otherwise prints to standard output past the messenger. `tests/exchange.rs` (`standard_streams`) reruns its test binary in a child process to check that the kernel writes nothing to either standard stream.
- Shell without removed faces: OCCT's `MakeThickSolid` returns only the inner offset solid when there are no closing faces, so the shim offsets with `BRepOffsetAPI_MakeOffsetShape` (same parameters) and builds the hollow solid from the input's shell and the reversed inner shell.
- Shell order (spec section 3.4.8, item 5): OCCT's offset assembles shells from maps keyed by shape addresses, so the face order of closed hollows and of shells with arc joins changed from run to run, with every index, the BRep bytes and the last bits of the volume. `checked_shell` rebuilds the returned solids and shells with faces ranked by the input elements they come from (`ordered_by_input`), keeping faces, edges and vertices so the history still applies, and stores each edge's curve representations in result face order after removing those on surfaces of no result face (`order_curve_representations`: curves on faces and continuity records, keyed by the stored surface handle and the location relative to the edge, as `BRep_Tool::CurveOnSurface` matches them; the offset adds them in map order too, which changed only the BRep bytes, of open shells of filleted bodies among others). Every other operation was repeatable in one process and across processes; tests 104 to 107 (`tests/determinism_and_concurrency.rs`) run each operation 4 times with other allocations in between and in two child processes.
- Validity (spec section 3.5, `ChangeCheck` in `cpp/validity.cpp`): `CheckInputs` records the state of every face of the operation's inputs before it runs, with its edges as the face sees them (surface, tolerances, flags, the 3D curve and the curves on that face with their ranges, vertex points and point representations), and `ensure_valid` runs the checks of `BRepCheck_Analyzer` only on faces of the result that are not faces of the inputs (by `IsSame`) or whose state changed in place, with their wires, edges and vertices (edges and vertices also in the context of every face and edge holding them, including unchanged neighbors), and on shells and solids that are not an input's; with no input face in the result it runs the analyzer on the whole. Inputs are the copies of the boolean's target and tools, the copy for fillet, chamfer and shell, and split's input, whose pieces are checked before being copied apart (repair then runs on the copies, since `ShapeFix_Shape` merges solids sharing a face). Repair checks the whole repaired result. Faces kept unchanged are trusted, so an invalid solid that `read_step` kept can pass its invalid parts through (test 111, spec open issue 9, which waits for review). `tests/common` builds such an input by moving a vertex in BRep bytes (`box_with_displaced_corner`).
- Topology (`shape_topology`): one walk over the faces and one over the edges with `TopoDS_Iterator` (`TopExp_Explorer` allocates), the inverse relations by a stable counting sort, and `BRep_Tool::IsClosed` only for edges with a closed curve representation. Test 112 checks that every relation agrees with its inverse.
- Tessellation names `IMeshTools_MeshAlgoType_Delabella` (spec section 3.7, item 2): OCCT's default Watson mesher inserts each face's nodes one by one and took 11 to 12 s on a sphere of radius 250 at the engine's resin tolerance and on `PLATE` at 0.05 mm, where Delabella takes about 1 s; naming an algorithm also stops OCCT reading `CSF_MeshAlgo` from the environment (test 113). Changing the mesher changes meshes and the examples' expected print results (spec section 7, open issue 8).
- Shell attempts (spec section 3.4.8, `cpp/blends.cpp`): the copy a shell works on has every location applied to its geometry (`copy_unlocated`, `ShapeUpgrade_RemoveLocations` when anything in the copy is located), since the offset fails with `BRepOffset_BadNormalsOnGeometry` on located blend surfaces (test 115). Each attempt (closed hollow, thick solid, cavity cut, tangent opening) returns its shape and history, and `checked_shell` rejects it when it is invalid after repair, holds no solid, removes no material, leaves a removed face unopened (`require_openings`: the face, or an image of it, as large as it), or has an inner face that is not at the wall thickness from the kept face it was generated from (OCCT turns a convex face's offset inside out when the wall is thicker than its radius and returns a wrong solid). When the thick solid fails and a removed face meets a kept face at a concave edge (`BRepOffset_Analyse`, which only reads, run on the input so nothing is copied when the fallback does not apply), where OCCT's join offset cannot close the wall and returns the input unchanged, the shim retries on a fresh copy: the cavity is `BRepOffset_MakeOffset` with `GeomAbs_Intersection` and offset 0 on the removed faces, and the result is the solid minus the cavity (`run_boolean`, shared with `booleans.cpp`, without unification). The offset's history (cavity elements generated from input elements) merged with the cut's gives spec 3.4.9 without augmentation, including the wall bottom in the removed face's `generated` list. If the retry fails too, the first attempt's error is reported (`checked_with_fallback`, shared with the attempts below). A removed face meeting kept faces tangentially along some edges only is not handled (spec open issue 7).
- Walls past convex rounds (spec section 3.4.8, item 6): `vanishing_flags` marks the kept faces whose inner offset vanishes (`convex_radius`: a cylinder, a sphere, or a torus across its tube, curving away from the material at the middle of its parameter bounds, with a radius below the wall plus `kVanishingMargin`, 0.01 mm, since OCCT's offset also fails on a round it would leave thinner than that). With any, `vanishing_path` picks the path before any attempt, from their radii and `EdgeConcavity` (`BRepOffset_Analyse` of the input, which also answers the concave-edge question of item 3). `CompleteIntersection` takes a cavity out of the solid (`cavity_shell` with `FaceIntersection::Complete`: `offset_cavity`, whose complete intersection drops the vanishing faces, extends their neighbors and returns a closed shell that becomes the cavity solid) and has no retry, so each attempt of a failing "too large" search costs one offset and one cut. `WithoutThem` (a wall within `kVanishingMargin` of one of their radii, a vanishing sphere, or a removed face tangent to a kept face, where the complete intersection fails) runs the attempts of items 1 to 3 on the solid without those faces (`without_faces`, `BRepAlgoAPI_Defeaturing`, whose history is merged first): `join_offset_shell` makes the closed hollow from that solid's offset, or cuts that solid's thick solid from it and the resulting cavity from the copy, so concave edges keep their arc joins. `ArcJoins` (a concave edge between kept faces, whose arc join the complete intersection would make sharp) does the same first and the complete intersection only when that fails. Defeaturing rebuilds the solid once per separate group of faces (about 27 ms each for the rounds of test 131's cube, against about 20 ms for its whole complete-intersection shell), which is why the complete intersection runs wherever it works. OCCT's complete intersection with arc joins (`MakeThickSolidByJoin` or `PerformByJoin` with intersection on) would keep arc joins without defeaturing and handles spheres, but the edges it builds change direction and order from run to run (closed hollows of test 131's cube, and `L` with a round), so its results are not repeatable (spec section 3.11).
- Tangent openings (spec section 3.4.8, item 7): where every edge between the removed faces and the kept faces of the solid the attempts run on is tangent (`opens_tangentially`, `EdgeConcavity::only_between` on that solid), OCCT's thick solid kept each removed face and a reversed copy of it, a closed hollow that passed every other check, so `join_offset_shell` runs `tangent_opening_shell` instead: the closed hollow (`inner_offset`, shared with `closed_hollow`) minus, for each face a removed face generated in the inner offset, the prism sweeping it back to the removed face along its normal (`planar_normal`; a curved removed face fails). Cutting the prisms from the closed hollow takes about 28 ms on test 45's body; cutting the inner offset solid and the prisms from the solid took 100 ms. Each prism side ends the wall along one edge of the inner face and is recorded as `generated` by the input edge between the removed face and the kept face whose inner face borders that edge (`WallEndOrigins`), so every wall end has its own rank in `ordered_by_input` and its own name; recorded as the removed face's `modified` images, the four wall ends of test 45's body changed order from run to run, since `BRepTools_History::Merge` collects images in a map keyed by addresses. `vanishing_path` sends a removed face tangent to any kept face to `WithoutThem`, since the complete intersection cannot open it either.
- Face area and centroid (`face_mass` in `cpp/measure.cpp`): planes bounded by lines and circular arcs in the parameter plane and cylinders bounded by lines are integrated exactly from their boundary (Green's theorem with one field per integral; an arc is its chord plus a circular segment); other faces use `BRepGProp::SurfaceProperties`. `BRepGProp` spends 18 x 18 integration points on every boundary edge: `elements` plus `topology` of `PLATE` (spec section 5) took 28.5 ms, of which 25.9 ms were faces, and now take 2.6 ms (faces 0.3 ms, `topology` 1.8 ms). The exact results match `BRepGProp` within 2e-14 relative on planes, cylinders, holes, arcs, fillets, mirrored and located shapes. `area()` uses the same function, so it equals the sum of the face measures. `volume()` (and the shell's material check, `solids_volume`) sums the divergence theorem term of every face of each solid relative to the mean of its vertices: exact from the same integrals for those faces (`analytic_volume_term`), `BRepGProp_Vinert` for the others (spec section 3.6 item 1, test 116); `center_of_mass` still uses `BRepGProp::VolumeProperties`.
- Edge normals take the surface parameters from the edge's curve on each face (projection only when there is none) and the normal from `BRepLProp_SLProps`, reversed for reversed faces; the faces are found by scanning the face map, so the order is ascending like `topology()`.
- Defensive branches no test reaches through the public API: in `normal_at_edge` (`cpp/queries.cpp`), the projection (valid shapes have a curve on every non-planar face for each of its edges, and `BRep_Tool::CurveOnSurface` computes one on planes) and `has no defined normal`; in `shape_edge_normals`, `has no direction at its middle` (profiles have only lines, arcs and circles, and the singular points of primitives, the cone apex and the sphere poles, are vertices, so no edge has its middle there); in `require_wall_thickness` (`cpp/blends.cpp`), a projection that finds no point (projection on an untrimmed analytic surface always finds one); `require_openings` failing (the only removed faces OCCT's thick solid kept are those `tangent_opening_shell` now opens). Only an imported solid that stays invalid after repair, or imported B-spline geometry, could reach them.

## Commands

```sh
cargo test -p partsmith-occt-sys
cargo clippy -p partsmith-occt-sys --all-targets -- -D warnings
cargo fmt -p partsmith-occt-sys
# WebAssembly, run under Node (needs the activated Emscripten SDK and the wasm OCCT install)
source /opt/emsdk/emsdk_env.sh && cargo test -p partsmith-occt-sys --target wasm32-unknown-emscripten
cargo bench -p partsmith-occt-sys --bench budgets            # spec section 5 budgets; fails when one is over
cargo bench -p partsmith-occt-sys --bench budgets -- step    # only the operations whose names contain a word
```

The WebAssembly tests need OCCT built for wasm without `OCC_CONVERT_SIGNALS`. OCCT's CMake defines it on every non-MSVC build; with Emscripten 4.0.15 and `-fwasm-exceptions`, the `setjmp` it places inside `try` blocks makes the compiler emit invalid code for `ShapeUpgrade_ShapeDivide.cxx` and `ShapeCustom_BSplineRestriction.cxx` (V8: `br_table: label arity inconsistent`), and every test binary fails to instantiate. Signals never reach wasm code and the shim never calls `OSD::SetSignal`, so the wasm build should pass `-UOCC_CONVERT_SIGNALS` in its C and C++ flags.

## Rules

- Every `unsafe` block or impl has a `// SAFETY:` comment; the only `unsafe` code is the bridge's `unsafe extern "C++"` block and the `Send` and `Sync` impls of `Shape`.
- Every bridge function that can fail returns `Result`; nothing throws across the boundary. No C++ type appears in the public API.
- No facade function modifies an input shape: algorithms that may write to their inputs run on copies. Booleans run non-destructively and on copies that share the inputs' geometry (`copy_elements`), since unification writes curves on faces to the edges the result shares with its arguments, even when the boolean then fails (test 114).
- The shim never prints, never installs signal handlers, never reads environment variables and never writes files.
