# partsmith-recompute

Runs a document's timeline: validation, dependency graph, parameter and expression evaluation, content-hash cache keys, the shared result cache with LRU eviction, rollback and stop points, failure, panic and cancellation isolation, and per-feature reports.

Spec (the definition of done): `docs/spec/recompute.md`. Acceptance tests in `tests/` come from recompute.md section 6, features.md section 6.4 (`tests/body_semantics.rs`) and naming.md tests 81 to 90 (`tests/naming_conformance.rs`); test 37 (the section 5 budgets) is the benchmark `benches/budgets.rs`; tests 41 to 68 and 71 to 73 (the statuses and the loss diagnosis) are `tests/diagnosis.rs`, as far as phase 1 of the reference stability plan builds them (its module documentation lists the tests and parts later phases add), test 69 is the corpus (`tests/reference_stability_{1,2,3}.rs`, below), test 70 the newcomer error corpus (`tests/newcomer_errors.rs`, phase 3), and the writer chain tests of section 3.5 are in `tests/timeline.rs`. The per-feature document tests `tests/feature_<type>.rs` and their helpers `tests/feature_support/mod.rs` belong to the built-in feature pipelines (features.md section 6.1). Do not weaken them.

## Public interface (crate root)

- `Recompute` (`new`, `with_cache_limit`, `registry`, `graph`, `plan`, `run`, `cache_len`, `clear_cache`), `DEFAULT_CACHE_ENTRIES`, and `Input { document, context, stop_at, assets }`. `Recompute` is `Send + Sync`; `graph` and `plan` take `&self` and never change the result cache.
- Graph: `Graph` (`nodes`, `node`, `dependents`, `affected_by`, `independent`), `Node`, `NodeState`, `Edge`, `EdgeKind`, `Change`.
- Plan: `Plan`, `PlanStep`, `Action`.
- Keys: `CacheKey` (32 bytes, `Display` is 64 lowercase hex characters).
- Report: `Report`, `FeatureReport`, `Status`, `Timing`, `BodyReport`, `ParameterReport`, `Message` (`severity`, `code`, `pointer`, `text`, `suggestion`, `repairs`, `fixes`, `detail`, `root`, `reason`). A feature whose only messages are info notices has status `Ok`.
- Loss diagnosis: `LossReason` (`Unknown`, `NotInDocument`, `Suppressed`, `ComesLater`, `RolledBack`, `UpstreamFailed`, `OtherBody`, `Removed`, `EntityDeleted`, `PointGone`, `CopyGone`, `NotInFile`, `Followed`) and `Removal` (`CutAway`, `Covered`, `Rounded`, `Beveled`, `Hollowed`, `PieceGone`, `NoLongerMade`, `NoLongerMeet`).
- Re-exported from `partsmith-features`: `CancelToken`, `FeatureOutput`, `BodyState`, `FeatureError`, `FeatureWarning`, `Repair`, `Fix`, `Severity` (`Info`, `Warning`, `Error`).

## Internals

- `validation.rs`: `Validations` memoizes `validate_and_canonicalize` plus `dependencies`, the compact key params and the names expressions use, per record content (the BLAKE3 hash of id, type and params in stored order), so documents that share ids (`SequentialIds`) keep their own outcomes. Each `graph`, `plan` or `run` is one pass; after it the memo is pruned to the cache limit by last use, never dropping what the pass used.
- `timeline.rs`: `Timeline::prepare` gives every record its state (stop point, then rollback, then suppression, then validity), computes providers, edges, parameters and context names, and builds the `Graph`. Each step's `StepKind` holds its validation (`Valid`) once: an active step always, a suppressed or rolled-back one when it validates, so `Step::valid` gives the loss diagnosis what every record writes. `check_links` holds the pre-build checks. A stop point that names no record falls back to the rollback marker (section 3.1 step 3); its `unknown_stop` text then says the run stopped at the marker, because section 4's text ("the whole timeline was rebuilt") would be false.
- `graph.rs`: inactive nodes provide no bodies, so `affected_by` of a feature change is queried on the graph in which that feature is active (after unsuppressing or adding it, before suppressing or removing it).
- `evaluate.rs`: values and the key of one active step, from the keys of earlier steps. `key.rs`: the key preimage (`KeyInput`) and the compact canonical params text.
- `plan.rs` and `run.rs` walk the steps in order with the same key computation and checks; `cache.rs` holds outcomes (`Built` output with its body states, made with `BodyState::from_update` so they keep the topology and volume the feature measured, or the error), each with the loss findings memoized for it (`diagnosis::Findings`, evicted with it), and evicts by last-use run, then key. `run.rs` leaves messages empty; `Recompute::run` renders them after the loop.
- `chains.rs`: `Bodies`, every body's current state, provider and writer chain (section 3.5). A build gets its declared bodies' chains as `BuildInputs::history` (taken out and put back, so nothing is copied; a body its dependencies name twice is taken once and a record joins a chain once, so a plugin's duplicate links cannot misalign a chain); `state_before` gives any body's state just before any record, with its provider.
- `diagnosis/` (section 3.10): `mod.rs` holds `LossReason`, `Removal` and `render_messages`, which explains each error, warning and notice with an `Explainer` per feature (roots of `upstream_failed` chains, `because` of empty bodies, `lost_face`, the reasons and `after` of losses, those a `plane_fallback` carries included, `by` of follows) and renders it with the run's outputs as `DocumentNames`. `view.rs` is the finished run as the diagnosis reads it (`RunView`, `RecordFact`); `memo.rs` the memoized `Findings` with the `Observations` they hold under and the `Probe` that records them (record facts, which say whether a record is at or after the rollback marker, the rollback marker, provider keys of undeclared bodies, rule 3's lookups of `by` and the order of the document's bodies; the states of the bodies the feature declares are read unobserved, through `declared_state_before`, since its key covers them); `reason.rs` rules 1 to 9, ambiguous `after` and follows, reading names only (naming maps and `BodyState::name_set`), so no element infos are computed; `explain.rs` the `Explainer` and the reason clauses and fixes it renders at report time; `face_name.rs` face names as the diagnosis reads them (`maker_of` and copy groups), on partsmith-naming's `ElementName::face_name` view.
- `pass_lru.rs`: `PassLru`, the map behind the cache and the validation memo. It records the pass (run, plan or graph) that last used each entry and, beyond a limit, evicts the entries used longest ago, the smaller key first on ties, never one the current pass used.
- `test_support.rs` (tests only): small test features (`test_datum`, `test_writer`, `test_reader`, `test_asset`, `test_panic`) and their `registry`, their records (`datum`, `datum_on`, `writer`, and `record` from any JSON), document helpers (`document`, `document_with`, `input`, `prepared`, `prepared_until`), the ids, names and notices tests write (`id`, `name`, `region_split`) and `with_view`, the diagnosis's view of a run of three datums; timelines are prepared over one shared registry.
- `tests/common` holds the `Harness`, the spec's test features (with `test_history`, which checks the writer chain `BuildContext::body_history` gives it and places its datum at the sum of the body's volumes before each writer) and the plan and graph readers, and re-exports the tolerances, measurement helpers and report readers of `tests/feature_support` (`feature_report`, `body_report`, `final_state`, `state_before`; `Run` methods use the same readers), so every test measures and reads reports the same way. `benches/budgets.rs` includes it with `#[path]`.
- `tests/diagnosis.rs` runs corpus scenarios through `tests/stability_common` (the record builders and shared setups of `records.rs`, documents, runs and edits, fixes, the STEP plates of the import scenarios, and the picks below), which it includes with `#[path]`; that module is shared with the corpus and is not behind `stability-study`. Picks follow the corpus's "Picked references" rule: `run_picked` runs a setup, re-picks every reference (`Reference::from_element`), region (`Region::reference()`), face sketch plane (`fallback_frame: body`) and edge or face axis (`direction`) in the state the setup builds, and runs the picked document; `with_picks` carries those picks into an edited document wherever the edit kept the stored query or region key; `stored` reads the pick a record stores for a query.
- Feature `stability-study`: the reference stability corpus (docs/design/reference-stability-corpus.md, R01 to R66) as `tests/reference_stability_{1,2,3}.rs`, with their helpers in `tests/stability_support_{1,2,3}/mod.rs` (directories, so Cargo builds no test target of their own); the record builders and shared setups (`tests/stability_common/records.rs`), documents, runs, edits, fixes, picks, readers, resolver diagnostics (`diagnose`) and checks they share live once in `tests/stability_common`, which all three and `tests/diagnosis.rs` include with `#[path]` (the thirds re-export it; the first third keeps its own `Expectations` and `EXACT_POSITION_TOLERANCE`, the corpus's 1e-6 mm). Every setup runs picked (`run_picked`, through `run` or the first third's `setup`), every edit keeps the picks (`with_picks`, through `edit`, `edit_document` or `run_edited`), and checks that resolve a reference resolve its stored pick. Message checks compare the structural message the specs render (recompute.md test 69); cause lines ("deleted", the changed setting) are the engine twins'. `Cargo.toml` gives the three tests `required-features`, so default runs build none of them; they record the study's expectations and fail until its plan is implemented, so CI only compiles and lints them.

## Commands

```sh
export OCCT_ROOT=/opt/occt/7.9.3/native
cargo test -p partsmith-recompute
cargo clippy -p partsmith-recompute --all-targets -- -D warnings
cargo fmt -p partsmith-recompute
# timing budgets (recompute.md section 5, test 37), all or by words of their names
cargo bench -p partsmith-recompute --bench budgets
cargo bench -p partsmith-recompute --bench budgets -- plan cancel
# the reference stability corpus (fails by design until the study's plan is implemented)
cargo clippy -p partsmith-recompute --features stability-study --all-targets -- -D warnings
cargo test -p partsmith-recompute --features stability-study --test reference_stability_1
```

Every test runs by default against `Registry::with_builtins()` (all 20 types are registered). The only ignored tests are the release-only feature budgets in `tests/feature_<type>.rs`.
